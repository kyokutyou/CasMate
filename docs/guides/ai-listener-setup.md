# AIリスナー初回設定手順（自分用）

本書はv0.5.0のAIリスナーを自分の配信で使い始める手順である。自動テストでは外部接続を模擬しており、実アカウントの登録・認証・投稿は本手順で確認する。機能の挙動は [AIリスナー仕様](../features/ai-listener.md) を参照する。

## ソースから起動する

依存関係が用意された作業フォルダーで `pnpm build` を実行後、`pnpm start` で起動する。管理画面のOBS操作の下に「AIリスナー」がある。既存の配布版EXEはコード変更では更新されないため、この段階ではビルドした作業フォルダーから起動する。

pnpmが実行前の依存関係再確認で停止する既存作業環境では、依存関係がインストール済みであることを確認し、起動を `pnpm --config.verify-deps-before-run=false start` として行える。これはその1回の実行だけに適用し、プロジェクト設定は変更しない。

## OBS連携の準備

手動・OBS連動とも、管理画面のOBS連携を設定して実際に配信中にする必要がある。手動方式はAIをオンにして配信開始を待てるが、配信終了後は次回改めてオンにする。接続不能・配信先への再接続中は投稿を休止する。配信テストは自分が管理する投稿先で行う。

投稿頻度には変更できない上限がある。件数・解除予定時刻はAIの発言の調整で確認でき、解除時刻は投稿の予約ではない。停止・再起動や記憶削除で上限はリセットされない。正式な条件は [強制投稿上限](../features/ai-listener.md#強制投稿上限) を参照する。

## Geminiの準備

1. [Google AI Studio](https://aistudio.google.com/) で自分のプロジェクトとAPIキーを用意する。
2. プロジェクトのプランがFree Tierであることを確認する。有料プランへの切替・請求の有効化はこの手順で行わない。使用予定モデルの無料枠を [料金表](https://ai.google.dev/gemini-api/docs/pricing) で確認する。
3. 管理画面のAI設定へキーを保存し、既定の `gemini-3.1-flash-lite` が選ばれていることを確認する。APIキーをチャット、ソースコード、ログへ貼り付けない。
4. 生成が制限された場合はAI Studioの利用状況・制限を確認する。きゃすメイトの表示からキーの課金状態や残り枠を保証できるとは解釈しない。[請求の公式説明](https://ai.google.dev/gemini-api/docs/billing)

AIへ渡す本文には会話内容が含まれる。名前・URLを本文から自動削除する機能はない。無料枠では入力・出力がGoogleの製品改善に利用される場合があるため、利用するプロジェクトと地域に適用される [Gemini利用条件](https://ai.google.dev/gemini-api/terms) を確認する。モデル・キーを変更する場合も無料枠を確認する。

## YouTube投稿アカウントの連携

1. [Google Cloud Console](https://console.cloud.google.com/) で自分用のプロジェクトを用意し、YouTube Data API v3を有効にする。
2. OAuth同意画面を構成する。テスト運用の場合は投稿用Googleアカウントをテストユーザーに追加する。
3. OAuthクライアントをDesktop appとして作成し、クライアントJSONを取得する。Webアプリ用やモバイル用のクライアントを代用しない。
4. AIリスナーの詳細にある「YouTube DesktopクライアントJSON」へJSONの内容を入力して保存し、「YouTube Liveと連携・再認証」から公式ブラウザ画面へ進む。
5. 投稿に使用するGoogleアカウント・YouTubeチャンネルを選んで許可し、アプリへ戻って表示された連携先を確認する。
6. 期限切れ・失効時は再認証する。解除する場合はアプリの連携解除を使い、外部解除に失敗した場合はGoogleアカウントの接続済みアプリ設定でも解除する。

テスト運用では認証が継続できる期間などにサービス側の制約がある。公開配布向けの審査・共通登録はこの手順の対象ではない。[公式Desktop OAuth手順](https://developers.google.com/youtube/v3/guides/auth/installed-apps)

## Twitch投稿アカウントの連携

1. [Twitch開発者コンソール](https://dev.twitch.tv/console) で自分用のアプリを登録する。アカウントの二要素認証等、登録時に求められる条件を満たす。
2. クライアント種別はPublicとし、Client IDを控える。登録画面でRedirect URIの入力が必須の場合はlocalhostの開発用URIを登録する。本機能の認証はDevice Code方式であり、そのURIを受信口として使用しない。
3. きゃすメイトへClient IDを設定して保存し、「Twitchと連携・再認証」を押す。
4. 開いた公式画面で投稿用アカウントを選び、表示されたコードが必要な場合は入力して許可する。
5. アプリへ戻り、連携アカウントを確認する。期限切れ・取消の場合は連携操作をやり直す。

Client Secretを発行・配布してログインの代用にしない。[アプリ登録](https://dev.twitch.tv/docs/authentication/register-app/)、[Device Code認証](https://dev.twitch.tv/docs/authentication/getting-tokens-oauth/)

## したらば・人格・運用準備

1. コメント取得画面で使用する配信・チャンネル・スレッドを設定する。
2. したらばへ参加させる場合は、AI設定の名前・E-mailを入力する。次スレッド作成の名前・E-mailとは別の設定である。
3. 人格を登録して各サービスへ割り当て、参加するサービスと開始方式を選ぶ。
4. 音声認識のモデルとマイクを準備する。OBS連動を使う場合は既存のOBS連携を設定する。
5. 設定値と投稿先を確認してからAIを開始する。投稿先がコメントを許可していない場合は、制限を回避せず該当サービスの状態を確認する。

## 実装後の確認

### 映像入力の追加後の確認手順

2026-09-18採用の映像入力・画像送信デバッグを実装した。OBS・Geminiを用いた実機の受入確認は以下の手順で行う。通常動作は [映像入力](../features/ai-listener.md#映像入力)、開発中だけの機能は [画像送信デバッグ](../features/ai-listener.md#撤去可能な画像送信デバッグ)、有効化と無効化は [デバッグ利用・撤去手順](./ai-visual-debug-removal.md) を参照する。

1. OBSの接続を準備し、「映像」タブでAIへ見せるソースを選ぶ。ゲーム映像だけを見せたい場合は、そのゲームの映像ソースを選択する。
2. 配信側シーンで対象を表示し、「撮影して確認」で範囲を確認する。別ソースのキャラクターが入らないこと、指定ソース自体に含まれる表示は撮影されることを確かめる。この操作はGeminiへ送信しない。
3. 画像にもGeminiのデータ取り扱いが適用されることを確認して、画像添付をオンにする。会話本文の文字数設定は画像の利用量を制限しない。
4. 開発中のテストは、AIを停止し処理完了を待ち、デバッグ欄で人格を選んで「テスト生成」を実行する。Geminiへの送信は発生するがサービスへの投稿は行わない。送信画像と返答、取得失敗時の理由を確認する。
5. 確認後は開発用フラグを無効化して起動し直す。完全撤去は [専用ファイル・登録箇所の一覧](./ai-visual-debug-removal.md#完全撤去する箇所) に従い、通常の画像添付と撮影確認が残ることを確認する。

画像入力追加後のプロンプトログでは画像本体を除外するため、`request` だけでは画像付き要求全体を再現できない。画像の添付有無・寸法等は別の記録情報で確認する。テスト生成はこの保存ログへ記録しない。

### 会話・投稿の確認

「送信する会話本文の上限」は保存する記憶の上限と別に調整できる。抽出・配分・日時の扱いは [送信する会話の選別](../features/ai-listener.md#送信する会話の選別) を参照する。デバッグログの `selection` で選別前後の本文文字数・件数を比較できる。`request` 内の「関連する過去の会話」「最近の会話」は空なら省略される。各グループの `date` と `utcOffset` が日付と共通オフセット、`entries` の各行が時刻・役割・サービス・本文である。以前のログではオフセットが各行の時刻に付いている。本文の削減量はトークン削減率とは異なるため、実際の使用量とコメントの自然さも確認する。

短さや文体の確認では、`systemInstruction` にある「今回は…文字」と成功投稿を比較する。[短文と話し方の生成指示](../features/ai-listener.md#短文と話し方の生成指示) を適用し、短い反応が混ざるか、語尾・励まし・引用の反復が減るかを複数回の投稿で確認する。保存済み人格の「草・ｗを使う」など競合する記述は見直すと意図を伝えやすい。新しい基本文体は過去の発言を見本にしないよう指示するため、記憶の削除は必須ではない。

送信内容を調べる場合はAIリスナーの詳細で「送信プロンプトをデバッグログに保存」をオンにし、生成後に「保存フォルダーを開く」から `prompts-YYYY-MM-DD.jsonl` を開く。`kind: "prompt"` 行の `request` が送信リクエスト本文で、`systemInstruction` が基本指示・人格、`contents` が会話、`generationConfig` が生成設定に対応する。文章検査で見送った場合は、同じ `id` の `kind: "outcome"` 行に `result: "skipped"` と理由コード（`empty`／`length`／`ng`／`duplicate`）が記録される。`length` は目標文字数の超過ではなく、絶対上限または投稿先上限の超過を示す。理由行には生成本文を含めないため、画面に「生成文を見送りました（空文・文字数・NG・同文）」と出たときの内訳を確認できる。確認後は設定をオフにする。会話本文が残るため、共有記憶削除後も残るログの取り扱いに注意する。記録・保持の正式仕様は [AIリスナー仕様](../features/ai-listener.md#デバッグ用プロンプトログ) を参照する。

「したらば：投稿可能」でも全体が「Gemini（HTTP …）：確認待ち」の場合は、文章生成が止まっていて、したらばへの送信には進んでいない。429はAI Studioの利用上限・使用量、401／403はキー・権限・利用条件、404はモデル名・提供状況を確認する。400はキーが無効と明示される場合と生成リクエストの問題を区別する。原因を解消後に「復旧後に再開」を押す。キーの保存だけでは確認待ちは解除しない。[Gemini公式トラブルシューティング](https://ai.google.dev/gemini-api/docs/troubleshooting)

配信者自身が使用・管理できる接続先で、サービスを1つずつ有効にして認証、取得、生成、実投稿、最新結果、ログを確認する。その後、複数サービス、停止・再開、OBS連動、したらば次スレッド追従を確認する。自動テストによる確認と実サービスでの投稿確認を区別する。

記憶・ログの保存フォルダーと機能の詳細は正式仕様を参照する。秘密情報を添えずに状態・エラー種別で問題を確認し、制限や結果不明時は同じ投稿を安易に再送しない。
