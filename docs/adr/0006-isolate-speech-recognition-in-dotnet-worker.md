# 配信者音声認識を独立した.NETワーカーへ分離する

配信者音声認識は、sherpa-onnx C# APIとNAudioを使用するWindows x64向け.NET 10ワーカープロセスへ分離し、TypeScriptのローカルバックエンドとは標準入力・標準出力上のバージョン付きJSON Linesで連携する。ElectronへネイティブNodeアドオンを直接組み込む方式よりプロセス間契約と配布物は増えるが、実機で確認済みのC#音声処理を再利用でき、マイク、ONNX Runtime、sherpa-onnxネイティブライブラリの障害をコメント取得、表示、読み上げ、ローカルバックエンドから隔離できるためである。

## Considered Options

- sherpa-onnxのNode.jsバインディングをElectronまたはNode.jsローカルバックエンドへ直接組み込む方式
- .NET音声認識コードを同一プロセスのネイティブアドオンとして呼び出す方式
- .NET 10ワーカーを子プロセスとして起動し、JSON Linesで連携する方式

## Consequences

- Electronメインプロセスはワーカーの起動、監視、終了を所有し、ローカルバックエンドのAppStateはワーカーから受けた状態と認識結果だけを公開する。
- 標準出力はJSON Linesプロトコル専用とし、人間向け診断は標準エラーへ分離する。標準エラーへ音声データ、認識文字列、マイク識別子の完全値、ローカルファイルの完全パスを出力しない。
- プロトコルのバージョン不一致、壊れたJSON、ワーカーの予期しない終了は配信者音声認識だけを利用不可にし、アプリ全体を終了しない。
- アプリ終了時は終了要求を送信し、応答しない所有ワーカーだけを強制終了して孤児プロセスを残さない。
- .NETランタイム、sherpa-onnx、ONNX Runtime、NAudioと依存DLLをWindows配布物へ含め、各バージョン、ライセンス、ソース入手方法を第三者ライセンス表示へ記録する。

詳細な利用者向け挙動とJSON Lines契約は [配信者音声認識仕様](../features/streamer-speech-recognition.md) を参照する。
