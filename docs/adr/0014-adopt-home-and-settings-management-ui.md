# 管理画面をホームと設定に分離する

## Context

機能追加により、配信中に操作する項目と事前の設定が同じ画面に並び、必要な設定を探しにくくなった。カードを個別に開閉する構成から、実際に操作できる比較用画面で構成を見直した。

## Decision

2026-09-15の比較で選ばれたA5を基に、日常操作をホームへ、機能設定を分類一覧と共通の編集先へ分離する。画面の採用内容と受け入れ条件は [管理画面仕様](../features/management-screen.md)、PC状態の取得・提供とウィンドウ寸法は [ローカルアプリケーション仕様](../features/local-application.md) がそれぞれ所有する。

同日の仕様確定で、PC計測は既存.NET基盤を使った独立プロセスへ分離し、Windows標準の計測情報を管理専用経路で提供する方式を採用した。音声認識の有効状態に依存せず計測でき、計測障害を配信支援から隔離できるためである。GPUとアプリ負荷の範囲、更新・鮮度・色の条件、最小ウィンドウの保留は解消した。具体的な値と契約は上記の所有文書だけに定義する。

2026-10-11、機能が増えた段階で利用者が8案から選んだ「スタジオボード」と、用途別の4画面へ構成を更新する。設定は4案から選んだカテゴリカードを採用する。事前に確認する場所とコメントを見ながら操作する場所を分け、共通の編集先へ戻れる構成にするためである。二画面に限定する先行判断はこの追加判断で置き換える。画面の移動を配信開始へ連動させず、個別操作・保存・計測の契約を維持する。詳細は管理画面仕様が所有する。

同日、管理画面の配色を独立した「アプリ設定」で選ぶ方式を採用する。OBSの表示設定とPCアプリ全体の外観は利用目的が異なり、URLの折りたたみ内では見つけにくいため、ポート・更新情報と共に分類一覧へ入口を設ける。選択肢・既定値・適用範囲は管理画面仕様、保存・互換性はローカルアプリケーション仕様が所有する。

2026-10-25、初回設定の導入後にホーム・設定との重複を見直し、利用者の明示承認により独立した配信準備画面を廃止する。用途別4画面の先行判断を、ホーム・配信中・設定の3ページへ更新する。確認手順を他画面へ移植せず、日常の状態確認と各機能への既存の入口を利用することで、画面の選択を簡潔にする。機能自体、設定保存、計測、移動と処理の分離は維持する。具体的な廃止範囲と初回設定の案内は[管理画面仕様](../features/management-screen.md#配信準備画面の廃止)が所有する。

## Considered Options

- 既存の機能カードを一画面に並べ、詳細を個別に開閉する。
- ホームと設定を分ける（A系統）。
- 左メニューで機能を選ぶ（B）。
- 配信準備・配信中・外配信の用途から選ぶ（C系統）。

配信者は複数の見本を比較し、A5の構成を選んだ。日常の開始・停止と設定への入口を分け、設定の編集先は共通にすることで、小さい画面でも機能を探せる構成とする。採用判断は利用者による見本の評価であり、定量的な優位性を実証したという意味ではない。

## Consequences

- 従来のカード開閉記憶を画面全体の基本モデルにしない。機能設定の保存・適用方式は変更しない。
- 画面移動で未適用値や実行中の処理を失わない状態管理と検証が必要になる。
- PC状態は独立した計測プロセスの同梱・監視と管理専用APIの検証が必要になる。仕様の確定と実機計測・負荷検証の完了は区別する。
- 試作は視覚的な参考資料として保持し、架空データや比較機能を本体に持ち込まない。
- 本決定は改修方針の採用であり、本体への反映・配布の完了を示さない。
