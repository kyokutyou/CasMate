# VOICEVOXとローカル音声変換を採用する

v0.2.0では、コメント読み上げに別途インストールされたVOICEVOX Engineを使用する。VOICEVOXが生成するWAVをPCで再生し、同じWAVを同梱するバージョン固定のLGPL構成FFmpegでAAC-LC・M4A・モノラルへ変換してスマホへ送る。

## Considered Options

- 各ブラウザのWeb Speech APIで端末ごとに読み上げる方式
- クラウド音声合成サービスで音声を生成する方式
- VOICEVOXのWAVをそのままスマホへ送る方式
- VOICEVOXのWAVをローカルで圧縮してスマホへ送る方式

Web Speech APIは導入が容易で通信量も少ない一方、利用できる声がOSとブラウザに依存し、PCとスマホで同じ声を維持できない。また、合成結果の音声バイナリをきゃすメイトが取得できないため、同じ音声をPC、スマホ、口パクへ利用できない。

クラウド音声合成は追加のアカウント、資格情報、利用料金、コメント本文の外部送信が必要となるため採用しない。WAVの直接配信は実装が単純だが、外配信での通信量が大きくなるため採用しない。

FFmpegは標準のネイティブAACエンコーダーを含むLGPL構成を使用し、GPL、nonfree、`libfdk_aac` を含む構成は使用しない。採用するビルドのバージョン、配布元、ライセンス文、ソース入手方法を配布物の第三者ライセンス表示へ固定して記録する。

## Consequences

- 配信者はVOICEVOXを別途インストールする必要があるが、FFmpegを別途インストールする必要はない。
- PCとスマホは同じVOICEVOX合成結果を元にするため、声、話速、音高、抑揚を一致させられる。
- VOICEVOX Engineの起動検出、自動起動、所有プロセスだけを停止するプロセス管理が必要となる。
- VOICEVOXと各音声ライブラリの利用条件、話者ごとの利用規約、必要なクレジットを配信者が確認できる導線が必要となる。
- FFmpegのバージョンとLGPL適合性を更新時に再確認し、配布物へ必要な告知と入手手段を含める必要がある。
- WAV、M4A、コメント本文は処理中のメモリだけで扱い、音声ファイルまたはテレメトリーとして残さない。
- VOICEVOXまたはFFmpegの障害をそれぞれのアダプター内へ分離し、コメント取得や他の表示機能を停止させない。

詳細な利用者向け挙動は [コメント読み上げ仕様](../features/comment-speech.md) と [スマホ音声再生仕様](../features/mobile-speech.md) を参照する。
