# PC管理画面からきゃすメイト用OBSソースを登録する

- 状態: 採用（2026-10-05）。実装と実機検証の完了は別に判定する。
- 正式仕様: [OBSソース登録](../features/obs-source-registration.md)。

2026-10-08追記: スマホの登録対象を端末共通入力にする判断は[ADR 0026](./0026-device-shared-obs-input.md)で更新する。

2026-10-05追記: 同仕様の明示操作による約5秒の表示テストを、4つのブラウザ表示に採用する。通常状態・履歴へ架空内容を投入せず、実表示成功は配信者がOBSで確認する。AI画像にテスト表示が含まれることは配信者の許容に従う。

同日の見直しで、利用者はスマホ映像テストの除外を選択した。合成映像の確認効果はPC→OBSに限られ、実スマホのカメラ・マイク・回線は確認できない一方、実映像との排他・復帰とOBS再読込に専用処理を必要とするためである。ボタンだけでなく映像生成・ワーカー制御・転送保留・OBS再読込／再開の専用処理を撤去し、スマホは通常送信で確認する。OBSへの登録と設定読戻し確認は採用を維持する。

URLコピー後にOBSでブラウザ・メディアソースを作る手間を減らす。既存の認証付きループバック接続をPC管理画面から共用し、対象表示を選ぶ明示操作を採用する。追加先はOBSで編集中の既存シーン（通常時は現在、スタジオモードではプレビュー）を操作時に取得し、コレクション表示とシーン選択欄を省く。未完了処理は元のシーンに固定して誤った配置修復を防ぐ。音声・Androidの配信操作権限は拡張しない。

同日の画面簡略化では、ソース欄を「使用するOBSソース」、表示テストの説明を「5秒のテスト表示を送ります。」へ変更する。正常終了の定型文・終了トースト・常設補足文を省き、処理中・不可理由・エラー・要確認を維持する。

続く4案の比較から利用者は1案「最短で追加」を採用した。候補なし・一意な候補では選択操作を省き、複数候補と選び直しが必要な場合だけ選択欄を示す。追加と表示テストを主操作として並べ、テスト終了は同じボタンで行う。復旧・不適合理由・手動手順は開いて確認できる詳細へ整理し、取得や通知で操作位置を変えない。画面構成の採用であり、登録確認・再試行の所有判定・共通占有・公開境界を変更しない。

既存ソースは名前で所有判定せず、実効設定とUUIDで適合を確認して共有する。共有設定と既存の配置を保持し、今回追加する項目だけを初期配置する。送信後の切断・配置失敗は段階別に確認し、確認できない変更を再送・削除しない。操作状態は管理専用のメモリに保持し、保存契約を増やさない。

ADR 0012のPC集約・認証・配信操作の確認を維持し、ソース作成の対象外判断を本機能の明示登録と設定読戻し確認に限って更新する。映像表示成功の判定、シーン切替、任意URL、一般的なOBS管理は採用しない。
