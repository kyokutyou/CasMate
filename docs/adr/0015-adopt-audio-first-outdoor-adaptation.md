# 外配信で音声優先の現在画像静止と送信品質拡張を採用する

> 2026-09-30追記: 自動制御の優先順位・名称・復帰判断・完了条件は[ADR 0016](./0016-redesign-outdoor-adaptation.md)で置き換えた。以下は採用当時の判断記録であり、旧条件を現行仕様として適用しない。H.265、同一SRT、手動操作優先、映像故障の分離は継承する。現在の挙動は[外配信仕様](../features/outdoor-streaming.md)を参照する。

## Context

屋外の帯域変動で映像と音声が途切れる場合にも、配信者は音声をできるだけ最後まで届けたい。2026-09-22、利用者が[実現性調査](../research/outdoor-audio-first-emergency-design-2026-09-20.md)を踏まえた推奨案を採用した。今回の依頼は正式仕様の更新であり、実装・性能検証は含まない。

## Decision

[ADR 0011](./0011-use-srt-direct-to-obs.md)のOBS直接受信を維持し、同一SRT接続で映像と音声を送る。固定／自動の映像ビットレートとH.265の選択肢を追加し、自動モードには独立した音声優先の許可を設ける。

通常の映像量低下でも厳しい場合、現在のカメラ画像を保持して再エンコードし、低負荷の動画で慎重に復帰を試す。別の待機画像への変更による大きな画面差分を避けることを狙う。ただし瞬間量低減を保証する判断ではなく、ビットレート制御と実測を必要とする。

最初の採用では固定モードへの緊急介入を含めず、緊急静止中もカメラを継続する。手動非表示と明示停止を自動処理より優先する。映像だけの故障を正常な音声経路へ波及させない設計も採用する。

挙動・保存・例外・実測待ち項目・受け入れ条件は[外配信仕様](../features/outdoor-streaming.md)、画面配置は[Android画面](../features/android-mobile-client.md#android画面)が所有する。本記録で詳細を重複定義しない。

## Considered Options

- 動画のビットレート低下だけで継続する。
- 回線悪化時に別の待機画像へ切り替える。
- 現在のカメラ画像を保持して再エンコードする（採用）。
- 音声と映像を別SRT接続・別回線へ分ける（今回は採用しない）。

## Consequences

- 同一SRT接続・共有送信キューの制約があり、音声の独立帯域や完全断中の継続は保証できない。OBS受信側の音声欠落・遅延を第一の評価軸にする。
- 既存の再接続時キャッシュ破棄・キーフレーム要求を新機能として重複実装しない。混雑対策に音声も含む全キャッシュ消去を流用しない。
- 保存設定と実行値、手動非表示と緊急静止、通信障害と映像故障を分離する必要がある。
- 初期の静止方式はカメラ取得を継続するため、省電力・発熱低減は保証しない。
- H.265・動的変更・映像だけの再準備にライブラリ上の経路があっても、端末・OBSでの継続性は別途検証する。
- 採用は実装完了を意味しない。制御値と故障時の限界は所有仕様の確定項目を実測で解消してから本実装を完了する。
