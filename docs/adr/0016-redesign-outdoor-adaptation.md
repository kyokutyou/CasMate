# 外配信の自動制御を動画継続・早期復帰優先で再設計する

## Context

旧試験実装への閾値追加では、静止からの復帰、回線観測の意味、エンコーダー変更の実効性、検証の負担を整理しきれなかった。2026-09-30、利用者は自動制御全体を一から仕様・実装し直し、低画質でも動く映像と早い復帰を優先する方針を採用した。OBSとスマホの録画を撮って比較する作業は求めず、普段使う端末での短い確認を残す。

この判断は[ADR 0015](./0015-adopt-audio-first-outdoor-adaptation.md)の自動制御の優先順位・名称・復帰判断・完了条件を置き換える。SRT直接送信、H.265選択、現在画像保持の方式、手動非表示と停止の優先、映像故障の分離は継承する。

## Decision

- 自動制御を観測・判断・適用へ分けて作り直し、「弱回線対策」を動画低下・必要時の静止・早い動画試行の許可とする。基本のSRT輸送と登録・音声経路は維持する。
- 静止で滞留が消えたことを動画帯域の回復とみなさず、新しい動画の生成・送出・ACKによって試行を評価する。試行には期限と有限の再試行待ちを設け、静止自体が生んだ改善で待ちをリセットしない。
- 主キューだけに依存せず、未ACK・ACK進行・音声待ち・期限切れを追加観測する。固定版RootEncoderの必要モジュールをローカルソースで管理し、動的目標変更の未稼働・受付・失敗を呼出側へ返す。対応範囲の宣言、API受付、実映像量を区別する。
- 短い端末内の数値履歴と利用者の明示操作によるJSON保存を設ける。映像・音声、コメント、接続先、秘密情報は収集せず、自動送信しない。
- 自動テストを中心に、回線と独立したエンコーダーの遅延・無反応・ピークを含む閉ループ検証を行う。普段の1台・1構成で実エンコーダー・GL・SRT・OBSの短い確認を行い、録画や精密測定・複数機種の長時間試験を必須にしない。試験入力の成功と実回線性能の確認は区別する。

具体的な状態・初期値・例外・保存・診断・受け入れ条件は[外配信仕様](../features/outdoor-streaming.md#弱回線対策と自動制御)だけが所有する。配置は[Android画面](../features/android-mobile-client.md#android画面)、用語は[CONTEXT.md](../../CONTEXT.md#外配信)を参照する。

## Considered Options

- 旧試験実装の閾値を追加調整する: 観測不足や受付と実効性の混同を残すため採用しない。
- 自動制御全体を再設計し、既存の輸送・登録・音声基盤を使う: 採用する。
- SRT輸送も独自に作り直す、またはPC中継・受信側からの制御を追加する: 今回の目的に不要な範囲拡大となるため採用しない。
- 録画比較や多端末・長時間試験を完成の必須条件にする: 利用者の作業負担を避ける方針に合わず採用しない。任意の追加性能検証としては妨げない。

## Consequences

- 設計初期値で実装を進められるが、実回線で測定済みの推奨値や、OBSで一定秒数以内に復帰する保証にはしない。
- ライブラリの変更範囲・固定元・ライセンス・互換APIを管理し、重複依存と観測処理による送信への影響を検証する必要がある。
- 送信側だけで受信映像・音声の完全性は分からない。短い実機確認を通した構成と未確認構成を分け、追加測定を未実施ならそう記録する。
- 旧表示名の保存互換と、手動非表示・ミュート・明示停止の優先を維持する。今回の文書更新は実装完了や実機受け入れ完了を意味しない。
