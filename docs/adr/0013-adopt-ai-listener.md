# AIリスナーの投稿と共有記憶を採用する

## Context

既存仕様ではAI会話を将来候補とし、コメント取得をログイン不要に、したらばへの書き込みを次スレッド作成と案内に限定していた。視聴者コメントが少ない配信で話題を提供するため、配信者は会話による要件確認でAIリスナー機能を採用した。

## Decision

AIリスナーを独立した主要機能として正式仕様へ追加する。採用した利用者向け挙動の唯一の所有文書は [AIリスナー仕様](../features/ai-listener.md) とする。採用理由は、静かなときの発言機会を作り、人格を替えても配信内容を共有し、前回の配信に続く会話を可能にするためである。

v0.5.0の正式仕様として、利用者の選択と、残りの判断の委任後に承認された仕様完成計画を採用する。[決定記録](../planning/ai-listener-open-decisions.md) で出所を区別する。当初は文書更新までを承認し、仕様完成後の利用者の実装指示によりコード実装へ進んだ。

## Consequences

### 2026-09-19の悪用抑止

配信者以外が他人のコメント欄へAIを参加させる悪用のハードルを上げるため、手動方式も含むOBS配信中の必須確認と、再起動でも維持する投稿上限を採用する。投稿先の所有・許可確認や改造版への完全防御は今回採用しない。具体的な数値、状態遷移、保存と失敗時の扱いは [AIリスナー仕様](../features/ai-listener.md#強制投稿上限) が所有する。

### 認証・保存・重複防止の理由

- ブラウザを使う公式認証を採用する。パスワードをアプリへ入力させず、Desktop/Publicクライアントの方式によって配布可能なWindowsアプリ内に共通の秘密を埋め込む設計を避ける。方式と権限は機能仕様が所有する。
- 資格情報は既存の暗号化保存基盤を使い、暗号化失敗を平文保存で回避しない。通常設定と公開用状態に秘密を混在させないためである。
- 共有記憶と発言ログを分離する。記憶を忘れる操作と投稿の確認を独立させ、ログから削除済み会話が復活することを防ぐ。
- 記憶は順序付きのファイル置換、ログは投稿前後を関連付ける追記記録とする。それぞれの更新・復旧目的が異なるため、同じ保存物へ統合しない。
- 外部投稿の結果不明を成功や未送信と断定せず、自動再送しない。読み取り側の自己投稿照合も曖昧なら該当AIを休止し、既存サービスの表示を壊さず二重投稿を抑える。
- ローカル保存の失敗では投稿を休止する。一方、期限を過ぎたログの削除失敗は警告・再試行とし、書込失敗と区別する。

- [ADR 0001](./0001-login-free-comment-acquisition.md) のログイン不要のコメント取得は維持する。投稿用のアカウント連携を取得全体の必須条件へ広げない。
- [ADR 0004](./0004-limit-shitaraba-write-to-next-thread.md) の書き込み範囲限定は、AIリスナー仕様で採用した投稿に限って拡張する。次スレッド作成・案内の既存判断や規制回避禁止は維持する。
- 既存の一時コメント履歴・音声認識プレビュー履歴と、本機能の記憶・発言ログの所有範囲を分ける。一般的な履歴保存の解禁とは扱わない。
- 認識自体はローカルに維持し、本機能による認識結果の利用を明記する。Geminiへの文章送信と投稿は機能上必要な通信であり、不要なテレメトリー等への送信禁止を解除しない。
- 詳細仕様は分割仕様方式に従い、本ADRや全体仕様へ重複記載しない。

### 2026-09-18の映像入力追加

配信者の採用表明により、指定OBSソースを参照する映像入力を追加する。配信側シーン全体では別ソースのキャラクター等へ反応し得るため、見せるソースを選択する方式を採用した。日常的な撮影対象の確認は接続認証から分けて「映像」タブへ置く。検証用の送信観測・テスト生成は撤去可能に分離し、確認後に通常機能へ影響させず取り除けるようにする。挙動は [映像入力](../features/ai-listener.md#映像入力) と [画像送信デバッグ](../features/ai-listener.md#撤去可能な画像送信デバッグ) が所有する。これは追加仕様の採用であり、実装完了の記録ではない。
