# ADR 0020: PC・スマホ直接接続を採用する

- 状態: 採用（2026-10-04）、v0.5.0。実装済み・実機検証未完了。
- 正式な機能契約: [PC・スマホ直接接続仕様](../features/smartphone-direct-connection.md)。設定・登録は[スマホ連携仕様](../features/smartphone-integration.md)が所有する。

同日追加の[ADR 0021](./0021-unify-smartphone-connection-preparation.md)で接続準備の一本化と登録情報の更新を採用した。独立した映像利用設定、全機能準備を登録成功の条件にする判断、再登録の扱いは同ADRが参照する所有仕様で更新する。以下は直接接続の初版で採用した判断を記録する。

## 背景

利用者は外配信の新経路としてPCとAndroidの直接接続を選び、映像・配信マイク、コメント・読み上げ、OBS操作のすべて、IPv4／IPv6、自動開放と手動設定を求めた。映像利用ONの間の待受維持と、PC再起動時の自動再準備も採用した。SRTだけではコメント・制御を運べず、既存LAN／Tailscaleの平文・無認証読取をそのままインターネットへ公開できない。

独立した仕様・ネットワーク観点のレビューから、WebView資産までのPC確認、Android共通QRへの範囲限定、既存登録版の互換、ON機能の登録準備失敗、全候補喪失時の外出中復旧、開放と実到達の区別を明確にした。

## 決定

- LAN／Tailscaleに排他的な直接接続を追加し、初期OFFとする。既存経路の招待版6・応答版8と保存済み登録、通常ブラウザ・コメントURL入力を維持する。
- 直接接続はAndroid共通QR専用とし、SRT caller→端末別PC listener、PC鍵確認と用途別認証を伴う専用HTTPS／WSSを使う。管理面・OBS入力はループバックのままにする。
- コメントの既存Web UIを表示用に再利用するが、HTMLと全関連資産も共通ネイティブ通信で検証して供給し、WebViewへ秘密を渡さない。SSLエラーの続行や未検証取得への戻りを採用しない。
- 公開IPv6を優先しIPv4を代替候補にする。UPnP IGDを優先、PCPを次候補として有限期限を更新する。手動設定、Windowsの権限要求と所有規則の管理を扱い、失敗・残存・到達未確認を成功へまとめない。
- 実装調査で、IGD IPv6の標準UniqueIDではアプリ所有を再確認できず、Addによる延長も他アプリの同一対象を取り込むことが判明した。初版のIPv6自動開放はPCPとし、標準IGD IPv6の作成・更新・削除を行わない。所有が不明な設定を操作するための例外を追加せず、手動設定を案内する。詳細と出典は直接接続仕様が所有する。
- 登録準備の失敗ではON機能を黙って省略せず、同じ端末・内部ポートへ再試行を対応付ける。既存の健全な通信と他端末を維持する。
- 保存済み候補が残る限り再接続する。すべて失われた場合はQR再登録が必要で、QRを得られない外出中の復旧を保証しない。初版でDDNS運用・独自の接続先配布や中継サービスを追加しない。

## 既存ADRとの境界

| 既存判断 | 維持・更新する範囲 |
| --- | --- |
| [ADR 0003](./0003-unauthenticated-read-only-lan.md) | LANのIPv4・無認証読取、管理非公開は維持する。直接接続の所有開放・Windows規則は新経路だけの例外 |
| [ADR 0009](./0009-use-tailscale-private-network-for-mobile-speech.md) | 利用者管理のTailscaleと開発者が共用中継を運営しない判断は維持。外部接続の選択肢へ直接接続を追加 |
| [ADR 0010](./0010-adopt-native-android-client.md) | WebView表示とネイティブ音声の分離を維持。直接接続の表示資産取得もネイティブが所有 |
| [ADR 0012](./0012-adopt-authenticated-obs-control.md) | PC経由の用途別OBS認証・確認・失効・故障分離を維持。直接接続WSSだけ外部入口を追加 |
| [ADR 0017](./0017-network-based-multi-device-smartphone-integration.md) | 排他的選択と複数端末を維持し、2経路から3経路へ拡張 |
| [ADR 0018](./0018-native-srt-and-local-receiver.md) | PC受信・OBSローカル転送、OFFで受信停止、端末別隔離を維持。直接接続の公開IPv4／IPv6を追加 |
| [ADR 0019](./0019-consolidate-smartphone-transports.md) | 2本のネイティブ接続、購読・世代・機能分離を維持。既存経路の通信版と登録形式は変更しない |

## 結果と不採用案

開発者運営のクラウド・帯域費用を追加せず、VPNなしの選択肢を提供する。一方でPC側の受信許可・ルーター機能・上流回線・アドレス安定性に依存し、全回線での成立と外出中の全候補喪失からの復旧は保証しない。通常ブラウザでの直接接続、SRT rendezvous・独自UDPホールパンチ、管理面やOBS本体の公開は採用しない。

仕様作成後の利用者の実装依頼により、PC・Androidの製品コードと自動検証を追加した。[直接接続の検証記録](../validation/smartphone-direct-connection-2026-10-04.md)で実装と実機確認を区別する。実ルーター・Windows規則の変更を検証のために実行しておらず、配布物生成は含めない。
