# ADR 0028: Androidで手書きを送信映像へ合成する

- 状態: 採用（2026-10-13）

## 背景

利用者は、送信中の大きなプレビューへ手書きし、通常は途中の線も配信へ載せたい。モード終了後も線を残し、送信停止で破棄する。弱回線対策の静止中には手元で編集を続け、動画復帰成功まで公開を待つことを選択した。

## 判断

Androidの既存GL経路で透明な手書きを合成し、既存形式でエンコード・SRT送信する。描画文書は送信セッションが所有する。カメラ背景の保持と手書きの固定リビジョンを分離し、静止中の専用プレビューにだけ最新編集版を載せる。復帰成功の内部通知で送信用の固定を解除し、一時的な動画状態や画面操作を公開確定に使わない。

同日、縦持ちで横長の送信枠を編集する際の小ささに対し、手書き画面だけの拡大・移動を採用した。送信側の合成座標は維持し、表示変換をタッチ座標へ逆適用する。移動は明示的な操作モードに分け、一本指の線を画面移動と取り違えない。

2026-10-14、スマホで操作見本を確認した利用者が再設計を採用した。描画面の広さと操作の少なさを優先し、タイトル帯と明示的な描く／移動の切り替えを、映像上の固定アイコンと2本指の表示操作へ置き換える。指の開始待ちと全指解除までの描画禁止で誤描画を防ぐ。既存GLの逆変換・送信セッション・公開リビジョンは維持し、画面設計だけでカメラ表示面や送信経路を再生成しない。

## 結果

PC・OBS・通信登録は変更不要になる。クリーンな保持背景によって静止中にも古い線を消せる。一方、出力と編集のリビジョン管理、診断時刻の従来の保持動作、GL再準備・非同期世代の検証が必要になる。具体的契約は[Android手書き映像合成仕様](../features/android-handwriting-overlay.md)が所有する。
