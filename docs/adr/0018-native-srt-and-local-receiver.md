# 0018: libsrt送信と端末別PC受信を採用する

- 状態: 採用（2026-10-03）。実装・実測の完了とは区別する。
- 更新する判断: ADR 0011のOBS直接受信、ADR 0016の通信エンジン維持、ADR 0017の映像OFFの意味。

2026-10-08追記: 固定OBS入力の単位とワーカー間の引継ぎは[ADR 0026](./0026-device-shared-obs-input.md)で更新する。

2026-10-04追記: [ADR 0020](./0020-adopt-smartphone-direct-connection.md)で公開IPv4／IPv6の直接接続を追加する。PCの端末別受信とOBSループバック転送、OFFで受信停止は維持する。この追加だけでは既存のポート・OBS入力を再移行せず、過去の送受信検証を直接接続の完了とみなさない。

## 背景

外配信はWebRTCではなく、Android内のSRT実装からOBSへ直接送信していた。通信の再送・生存監視・送信待ちと適応制御が結び付いており、PCは実受信を観測できなかった。利用者は送受信双方の刷新、途切れにくさと回復、良好な回線で撮影からOBS表示まで1秒未満を優先した。品質の詳細設定は維持し、有料の中継サービスは追加しない。

## 決定

Androidの撮影・ハードウェアエンコード・MPEG-TS多重化を再利用し、SRT通信をlibsrt 1.5.7へ移す。暗号化はMbed TLS 3.6 LTSを静的リンクし、公式ソースの版とSHA-256を固定する。LAN/TailscaleでPCの端末別ネイティブワーカーへ送り、復号後のMPEG-TSを再エンコードせず127.0.0.1のUDPへ転送する。OBSは固定のローカルメディアソースで受信する。

PCアプリの起動を必要条件とし、映像OFF・登録削除・経路切替・終了は該当受信を閉じる。Androidの撮影停止とOBS配信停止は別操作のままにする。端末別プロセス、資格情報、固定ポートで故障を分離する。

libsrtは再送・暗号化・ペーシング・接続監視を所有する。アプリは有界な送信待ち、接続世代・取消・再試行、キャプチャ維持と適応制御を所有する。PCの受信フィードバックは復帰判定の根拠とするが、OBSの表示成功とは扱わない。欠測や古い世代は回復の根拠にしない。

## 移行と影響

PCとAndroidを更新し共通QRを読み直し、OBS入力を一度変更する。旧ポートは予約と移行前バックアップを保持し、旧OBSソースと競合しない新規ポートを割り当てる。旧通信エンジンの並行運用はしない。端末識別、名前、品質、音量、コメント・OBS操作登録を保つ。新規遅延は400msとし保存済み値は変更しない。

Tailscaleの経路は利用者のネットワーク条件による。無料利用可能な既存接続を使い、新たなクラウド契約や独自の有料リレーは要求しない。1秒未満・復旧5秒以内は測定条件付きの目標であり、未測定やリレー経路で保証しない。

正式な挙動・通信契約・検証条件は[外配信仕様](../features/outdoor-streaming.md)、登録と移行は[スマホ連携仕様](../features/smartphone-integration.md)が所有する。
