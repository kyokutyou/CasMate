# 0025: 受信したスマホ音声の認識と認証付き入力操作を採用する

- 状態: 採用（2026-10-08）。実装・実機検証の完了とは区別する。
- 更新する判断: ADR 0006のマイク取得、ADR 0018のPC受信転送、ADR 0022の今回の保存移行。

外配信では声がPCマイクではなくOBSのメディアソースへ届くため、端末別SRT受信のMPEG-TSをOBSと別のループバックUDPへ分岐し、同梱FFmpegで音声だけを16kHzモノラルPCMへ復号する。既存.NETワーカー、VAD、モデルとセッション共有を維持する。入力はPCマイクまたは登録スマホの1つだけとし、OBSの加工・ミュートとは独立する。

受信転送は認識の待ち・故障で停止しない。接続境界でnative自身が認識分岐を解除し、新世代の準備後だけ再開する。通常停止のflushと入力切替・通信断の破棄を区別する。PCM待ちは最大5秒とし超過時は旧待ち・VAD・結果を失効して現在音声へ戻る。FFmpegはWindows Job Objectの親終了連動で所有する。

共通QR登録済み端末へ音声認識操作専用資格を発行し、既存制御接続を共用する。スマホ操作は保存済み本番ON/OFF、単一入力、再試行だけ。一般管理APIや本文・履歴・WAV操作は公開しない。

今回の現行設定13、PC台帳4、Android保存5は原本を保全して新版へ明示移行し、値・登録・ポート・用途資格を引き継ぐ。制御2と登録12/14の既存用途を限定併存させ、制御3と登録15/16で認識資格を追加する。更新順序に依存せず既存更新資格から取得し、QR再登録を要求しない。未知・破損・それ以前の終了形式は既存の保全契約に従う。

正式な動作は[配信者音声認識](../features/streamer-speech-recognition.md)、媒体は[外配信](../features/outdoor-streaming.md)、認証・版選択は[通信](../features/smartphone-transport.md)、登録は[スマホ連携](../features/smartphone-integration.md)が所有する。
