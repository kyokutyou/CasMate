# 認証なしの読取専用LAN公開を限定採用する

v0.2.0では、外配信中の配信者が同一ネットワーク内のスマホからコメントと読み上げ音声を受け取れることを優先し、スマホ向け画面へ認証を設けない。その代わり、既存の管理面とは別の読取専用公開面を、検出したプライベートIPv4アドレスごとに限定して提供する。

本ADRはv0.3.0以降もLAN公開の判断だけを所有する。Tailscale公開の判断は [ADR 0009](./0009-use-tailscale-private-network-for-mobile-speech.md) を参照する。

2026-10-04追記: [ADR 0020](./0020-adopt-smartphone-direct-connection.md)の直接接続は公開IPv4／IPv6・認証付きTLS・所有する開放／Windows受信規則を扱う別経路である。本ADRのLAN公開制限と管理面非公開は維持し、無認証LANの条件を直接接続へ流用しない。

## Considered Options

- ループバック接続だけを維持し、スマホ対応を行わない方式
- URLトークン、PIN、ペアリングなどの認証を必須にする方式
- 管理画面を含む既存ローカルバックエンド全体をLANへ公開する方式
- 認証なしでスマホに必要な読取専用面だけをLANへ公開する方式

認証は同一ネットワーク内の他者による閲覧を防ぎやすい一方、外配信ごとの入力や再接続手順が増える。v0.2.0では配信者の選択により認証なしを採用する。ただし、既存バックエンド全体の公開は、設定変更、操作トークン、接続先、ローカル情報が露出する危険が大きいため採用しない。

`0.0.0.0` へのワイルドカードバインドは、意図しないインターフェースへ公開範囲を広げるため採用しない。RFC 1918のプライベートIPv4を持つインターフェースごとに待ち受け、IPv6、ループバック、リンクローカル、パブリックIPv4を除外する。

## Consequences

- 同じネットワークへ参加できる端末は、認証なしで配信セッション中のコメントとスマホ用音声を閲覧できる。
- LAN公開の既定はオフとする。
- LAN公開面はスマホコメント画面、最小状態、専用WebSocket、期限付きM4A取得だけを提供する。
- 管理REST、操作トークン、設定、接続先、OBS状態、ウィンドウ状態、ファイルパス、診断情報はLAN公開面へ含めない。
- LAN公開面から設定変更、コメントソース操作、ウィンドウ操作、キャラクター素材操作を行えない。
- TLSを提供しないため、信頼できないWi-FiではLAN公開をオンにしない旨を案内する。
- VPNアダプターもプライベートIPv4であれば公開対象となり得るため、管理画面に実際の公開URLを全て表示する。
- ルーターのポート転送、ネットワーク分離、Windowsファイアウォール規則をきゃすメイトが回避または自動変更しない。

詳細な公開契約とエラー処理は [スマホ音声再生仕様](../features/mobile-speech.md) を参照する。
