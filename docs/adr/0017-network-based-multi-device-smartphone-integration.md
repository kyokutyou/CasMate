# ネットワーク別のスマホ連携と複数端末を採用する

2026-10-08追記: OBS入力の割当単位と経路間の受信引継ぎは[ADR 0026](./0026-device-shared-obs-input.md)で更新する。経路ごとの登録資格と排他的なネットワーク選択は維持する。

2026-10-04追記: [ADR 0020](./0020-adopt-smartphone-direct-connection.md)で直接接続を第3経路に追加する。排他的選択・複数端末・端末ごとの固定OBS入力は維持し、既存LAN／Tailscaleの招待版6・応答版8を変更しない。

同日追記: 独立した映像利用設定と登録後の更新方針は[ADR 0021](./0021-unify-smartphone-connection-preparation.md)で更新する。現行契約は同ADRが参照する所有仕様に従い、以下は当初の判断を記録する。

## 判断

2026-10-03、利用者は用途別の入口をLAN／Tailscale別へ変更し、両方OFFを許す排他的な公開選択、コメント・音声提供の常時有効化、経路別の映像利用設定、複数スマホの音声・映像・OBS操作を採用した。

映像は端末・ネットワーク別のOBSメディアソースへ直接SRT送信する。PCアプリを中継にしない。OFFは準備設定だけを変更し、保存済みAndroidからOBSへの送信を停止・禁止しない。Androidは同じPCのLAN・Tailscale登録を保持し、利用者が接続先を選ぶ。

ADR 0009の両経路同時公開は排他的選択へ、ADR 0011のTailscale・1台前提はLANと複数端末へ更新する。ADR 0003の読取専用公開とADR 0012の認証付き確認操作・故障分離は維持する。OBS全体の確認・実行は同時1件を維持する。

旧登録との対応、登録の原子的保存、端末別の認証・音声キュー、削除後も残るOBS入力とのポート競合を正式仕様で扱う。詳細の所有者は[スマホ連携仕様](../features/smartphone-integration.md)とそこから参照する各機能仕様とする。

同日、ネットワークごとに共通QRを1つとし、読取端末を自動登録する方式を追加採用した。認証付きの登録待受を映像状態用ポートへ追加し、コメント公開面の読取専用契約を維持する。インストールごとの認証と原子的な端末割当で、再試行の重複登録を防ぐ。失効・移行・QR版6の詳細はスマホ連携仕様が所有する。
