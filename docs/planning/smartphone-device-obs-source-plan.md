# スマホのOBSソースを端末単位に統一する実装計画

2026-10-08、利用者が採用。サブエージェント3名のレビューを反映した計画。正式な製品契約はスマホ連携・OBSソース登録・外配信の所有仕様に記載する。

実装と3観点の独立レビューを完了し、指摘は解消済み。Windowsのlint・型チェック・全体1,128テスト・build、Androidの単体テスト・lint・デバッグビルドが成功した。Electronで狭い画面・状態更新・通知とフォーカスを確認した。USB端末と起動中のOBSを確認できず、実端末の映像・音声、実回線での切替とOBSの配置・音量保持は未確認。Windows buildではNuGetの脆弱性情報取得に警告が残る。配布用インストーラーは生成していない。

## 採用する動作

- 同じ登録端末のLAN・Tailscale・直接接続は1つの固定OBS入力を使う。端末IDで識別し、機種名で複数端末を統合しない。
- 既存利用者は新しい端末共通ソースを一度追加する。旧ソースは利用者が整理し、旧転送ポートの予約は保持する。
- 共通入力の保存後はOFF・表示経路の未登録でも入力コピーとOBS登録を利用できる。入力未割当、保存・入力エラー、OBS接続・占有の禁止条件は維持する。
- 経路選択・撮影開始は既存の手動操作を維持し、経路切替は再接続を伴う。

## 保存と移行

- PC台帳の現行を版6、対応を4・5・6とする。版4からの認識資格追加も維持し、版5の用途資格・投影ハッシュ・版数を保全する。Android保存・招待・登録応答・通信版は変更しない。
- 旧形状を検証して暗号化原本を退避し、原子的置換・再読込確認後に利用する。失敗時は原本を保持し、共通保存契約に従って編集停止と手動復旧を案内する。
- 移行時にはOBSポートを割り当てない。端末の任意の`obsLocalPort`は初回の映像準備時に未予約番号から割り当て、端末ごとに保存まで原子的に確定する。未割当とポート不足で台帳全体を利用不能にしない。
- 経路別のOBS転送ポートを廃止し、SRT受信・公開ポート、PC鍵・所有開放、全予約を保持する。削除済みと旧OBSポートを自動再利用しない。

## 受信切替

- LAN/Tailscale用と直接接続用の受信管理器は維持し、端末IDごとの独立した調停を共用する。周期refresh、設定変更、再試行、停止を含む全ワーカー操作を通す。
- 保存成功後に経路世代を失効し、旧ワーカーの実終了後だけ新しいワーカーを開始する。受付・await後・開始直前に最新経路と対象設定を照合する。保存キューからDirectRuntime全体のrefresh/stop完了を待たない。
- 停止は通常終了1.5秒、その後の所有プロセス強制終了と終了確認1.5秒を上限とする。実終了未確認では停止不明の所有記録を保持し、同じOBS入力への新受信を止める。遅い実終了後は現在世代だけ再試行する。他端末とコメント公開は独立して継続する。
- 経路切替・OFF・停止不明では認識分岐と旧認識世代を失効する。新受信の確認後だけ認識を再開し、認識障害でOBS転送を止めない。

## OBS登録と画面

- 登録対象を`{kind:'smartphone',deviceId}`、identityを端末IDと保存済み共通入力に統一する。経路・profile版数・受信準備状態を登録の可否やidentityから分離する。
- 入力取得は既存POSTの本文を`{}`にし、旧network付き要求は拒否する。管理端末情報に`obsLocalPort`を置き、経路profileからOBS用localPortを除く。
- ソース名は「きゃすメイト 端末名」。新規配置、再利用、別シーン共有、復旧・結果確認は既存OBS登録の契約を維持する。経路切替だけで登録を中断しない。
- 既存の共通通知と状態欄を使い、処理や結果で操作位置・フォーカスを動かさない。

## 検証

- 4→6・5→6、未準備端末、全予約保全、用途資格保全、ポート不足、退避・置換失敗と中断復旧。
- 全経路のURL同一性、別端末分離、OFF登録・コピー、再起動、秘密再発行、別シーン共有、登録中の経路切替、削除と旧API要求拒否。
- 連続切替、遅い準備・停止、終了失敗・停止不明・遅い実終了、旧世代拒否、端末間の非待機、認識分岐の失効と復帰。
- Windowsのlint・型チェック・全体テスト・build、生成定義に伴うAndroidの単体テスト・lint・デバッグビルド。全体テストとbuildは同時実行しない。
- Electron・通常ブラウザの対象幅と通知・フォーカス、可能な実端末とOBSで映像・音声・配置と音量の保持を確認する。未確認条件を報告する。仕様一致／故障影響の独立レビューで重大指摘を解消する。
- 既存の未コミット変更を保持し、配布物は明示依頼がある場合だけ生成する。
