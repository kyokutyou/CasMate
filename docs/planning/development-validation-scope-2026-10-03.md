# 開発時の検証範囲を整理する実施計画

2026-10-03。配信者が採用した5点の改善を、正式文書と検証設定へ反映するための計画。古い比較見本の継続検査と同じ画面確認の繰り返しを減らし、製品の回帰検証を維持する。配信者の実行指示により5点と下記の追加承認を反映済み。通常ブラウザは操作接続が利用できず未確認で、Electronの描画とCodex内ブラウザの代表操作を確認した。検証の成否・制約は完了報告へ記載する。

正式な開発手順は [AGENTS.md](../../AGENTS.md) と [開発の運用手順](../development-workflow.md)、通知・画面の挙動は [管理画面仕様](../features/management-screen.md)、配布検証は [ローカルアプリケーション仕様](../features/local-application.md) が所有する。反映後も本計画を日常の必読文書に追加しない。

## 変更する5点

| 対象 | 反映する内容 | 完了条件 |
| --- | --- | --- |
| 運用改善の効果評価 | 「導入後3件程度」の試行を終了し、日常の記録指示から外す | 読み取り範囲・再実行理由等の評価用集計を毎回求める指示がなく、トークン削減効果は未実証と区別される |
| 過去の比較見本 | 製品のlint・全体テストから見本専用の検査を分離する | 製品の検査対象が維持され、見本は専用コマンドで検査できる |
| 通知の画面確認 | 共通通知の座標・高さ・スクロール・フォーカスを実際の描画エンジンで自動検証する | 通知の各状態・長文・連続操作・狭幅の回帰を検出でき、通常の文言変更で同じ計測を繰り返さない |
| 管理画面の確認範囲 | 共通変更と個別画面変更の確認範囲を分ける | 変更内容から対象画面・幅・実行環境が決まり、影響不明では範囲を広げる |
| インストーラーの試験 | 配布物生成の明示依頼がある場合の検証へ分ける | 通常の完了検証はビルドまでで、インストーラー生成・試験を暗黙に要求しない |

## 実施順序

### 1 運用文書と正式仕様を先に更新する

主な対象は [開発の運用手順](../development-workflow.md)、[管理画面仕様](../features/management-screen.md)、[ローカルアプリケーション仕様](../features/local-application.md)。AGENTS.mdは参照先・適用条件の整合に必要な箇所だけ更新する。

- 「導入後3件程度」の試行を終了する。評価が不十分だった事実は [過去の反映記録](../validation/development-workflow-2026-09-17.md) と区別し、効果が実証済みになったとは扱わない。今後の効果評価は、再評価を依頼されたときに目的と期間を定めて行う。
- 製品と比較見本の検査範囲、通知の自動検証、後述する画面確認の判断表を所有文書へ反映する。通知の実状態更新・描画・非交差の自動検証が成立するまでは、従来のブラウザー計測を免除しない条件も、この工程で所有文書へ明記する。
- インストーラー試験を、明示依頼によりインストーラーを生成した場合の検証へ限定する。展開版EXEを依頼された場合はその起動を確認し、インストーラーを追加生成しない。
- lint・型チェック・製品の全体テスト・ビルド、検証後の追加変更に対する再実行条件、保存・認証・公開・外部投稿等のレビュー条件を維持する。
- 通常の検証結果は、対象・コマンド・成否・未確認点を完了報告へ短く記載する。毎回詳しい検証記録ファイルを作る運用は終了する。
- 実機の測定値や複雑な再現条件など、保存して後から参照する必要がある場合だけ、別ファイルに記録する。機能仕様が求める実機構成・測定値の記録条件と、過去の検証記録は保持する。

関連する条件と例外を読み、既存の未コミット変更を取り込んだ現在の文書へ差分を適用する。所有範囲・参照リンク・AGENTS.mdとの整合を確認できたら、検証設定の変更へ進む。

### 2 比較見本の検査を分離する

対象は [package.json](../../package.json)、[ViteとVitestの設定](../../vite.config.mts)、[lint実行スクリプト](../../tools/lint.mjs)、[lint回帰テスト](../../tests/lint-runner.test.ts)、[README](../../README.md) と見本専用のテスト設定。

現時点で見本を直接参照するテストは次の7ファイル。実施時に参照元を再確認し、製品挙動の唯一の検証が含まれていれば、必要な確認だけを製品側の回帰テストへ移してから分離する。

- [管理画面の見本](../../tests/management-ui-prototype.test.tsx)
- [コメントフィルターの見本](../../tests/comment-filter-ui-prototype.test.tsx)
- [OBSコメント表示の見本](../../tests/comment-overlay-ui-prototype.test.tsx)
- [スマホ音声の見本](../../tests/mobile-speech-ui-prototype.test.tsx)
- [次スレッド作成の見本](../../tests/next-thread-ui-prototype.test.tsx)
- [OBS操作の見本](../../tests/obs-control-ui-prototype.test.tsx)
- [文字演出の見本](../../tests/text-effects-ui-prototype.test.tsx)

反映後のコマンドを次のように分ける。

| コマンド | 検査する対象 | 実行条件 |
| --- | --- | --- |
| `pnpm lint` | 製品ソース・製品テスト・ルート設定・開発ツール・除外対象外の新規ソース | 通常の完了検証 |
| `pnpm test` | 製品の全体テスト。上記の見本専用テストを分離 | 通常の完了検証 |
| `pnpm lint:prototypes` | 比較見本のソースと見本専用テスト | 見本の変更・再利用時、および今回の分離確認 |
| `pnpm test:prototypes` | 見本専用テスト | 見本の変更・再利用時、および今回の分離確認 |

lintはGitによる列挙を維持し、明示的な製品／見本の実行範囲を追加する。製品側から分離するのは比較見本のディレクトリと見本専用テストだけとし、製品ソース・開発ツール・その他の新規ディレクトリを一括除外しない。無効な指定、列挙失敗、検査対象ゼロ、違反検出は失敗として返す。

Vitestは見本専用設定を追加し、製品側と見本側の収集対象が意図した集合になることを確認する。単にテストを削除したり、失敗を通すために時間上限やアサーションを緩めたりしない。比較資料は [ADR 0014](../adr/0014-adopt-home-and-settings-management-ui.md) に従って保持し、再検討を依頼された場合に参照できるようにする。

完了時は、分離前後の製品テスト・見本テスト・lint対象の差分を確認する。製品の新規ソースの検査、見本専用実行での違反検出、無効な実行範囲・余分な引数・Git列挙失敗・範囲選択後のゼロ件・ESLint除外後のゼロ件の失敗を回帰テストで検証し、意図した見本以外に検査対象の欠落がないことを確認する。

### 3 共通通知の描画テストを整備する

既存の [通知テスト](../../tests/management-warnings.test.tsx)、[画面操作テスト](../../tests/dashboard-source-start.test.tsx)、[共通見出しテスト](../../tests/management-editor-heading.test.tsx) を利用する。実際の描画は [AI画面のレイアウトテスト](../../tests/ai-listener-layout.test.tsx) と [読み上げ画面のスクロールテスト](../../tests/comment-speech-scroll.test.tsx) の非表示Electron方式を参考にする。

- 本番のManagementShellとCSSを使う共通通知の描画テストを追加する。既存のElectron依存を使い、検証用プロファイルと模擬APIで利用者の設定や外部接続を変更しない。
- 実際のReactの状態更新で、表示前・処理中・成功／失敗・更新・消去を再現する。対象の座標・外形、本文高、スクロール、フォーカス、横はみ出しを比較する。
- ホーム／設定、接続済み／再接続中、取得済みのPC状態と桁の増加を含む表示を使う。仕様の通知検証幅で、表示中のブランド・PC状態・接続状態・ヘッダーの操作要素・本文の操作領域と通知の矩形が交差しないことも確認する。本文が移動しなくても、通知が他の表示や操作を覆う場合は失敗にする。
- 長文、連続操作、狭い画面を含める。通知先・置換・寿命・警告の保持は既存の操作テストを活用し、同じ確認を増やさない。
- 共通通知の描画と各機能から共通通知への接続を分けて検証する。ボタン文言、状態欄、個別CSSを変更した場合は、変更した画面の描画確認も対象とする。
- jsdomの模擬寸法による成功を、実際の描画確認の代わりにしない。Electron起動失敗や未実施は成功扱いにせず、利用できる環境で再確認する。

自動テストが上記の実状態更新・描画・非交差を確認できることを完了条件とする。その確認前に、既存のブラウザー計測の必須条件を免除しない。文字の読みやすさ・重なり等の目視確認は、変更した配置や部品を中心に残す。

実行中の描画テストで、320px幅のホームの共通通知がブランド・取得済みPC数値を覆う既存不具合を確認した。2026-10-03に配信者が、既存仕様の「覆わない」へ合わせる最小限のCSS修正を今回の対象へ追加承認した。ヘッダー高・本文位置・通知寿命・操作は維持し、通知の有無で配置を切り替えない。これ以外の製品表示の変更は対象外のままとする。

### 4 画面確認の対象を変更内容から決める

管理画面仕様の受け入れ条件は製品が満たす条件として維持し、毎回実行する範囲を次の判断表で定める。複数の行に該当する変更は範囲を組み合わせる。

| 変更内容 | 必要な確認 |
| --- | --- |
| 共通通知への文言追加・変更だけ | 共通通知の自動テストと変更機能の通知先・内容・寿命。個別の座標測定は追加しない |
| 個別画面の配置・ボタン文言・状態欄・CSS | 変更画面と、そのCSSが影響する画面をElectronで描画確認する。最狭幅と通常幅を含め、変更した折り返し条件・縦横・長文・処理中の状態を確認。通常ブラウザでも変更画面の代表操作を確認 |
| 共通見出し・通知・ナビゲーション・共通CSS | 実際に利用する全編集先を対象に、仕様の画面幅・状態保持・キーボード操作を確認。Electronで描画を確認し、通常ブラウザでは入口・往復・通知等の代表操作を確認 |
| Electron固有の最小寸法・表示倍率・窓操作 | Electron実機で枠を除いた表示領域、最小寸法、倍率、復元・フォーカスを確認 |
| 影響範囲を特定できない変更 | 利用側を調査し、特定できるまで共通変更として確認範囲を広げる |

全編集先の一覧は実施時の本体から確認し、過去の「13画面」へ固定しない。画面名・入口・所有仕様が現在の一覧と対応することを確認する。共有部品の変更を個別画面の変更として扱わない。

通常ブラウザの代表操作は、変更画面への入口、変更した入力・操作と通知、戻る操作と状態・フォーカス保持を対象とする。省略できるのは、共通通知の文言だけの変更で上記の自動検証が成立している場合、またはElectron固有の変更で通常ブラウザへ渡るDOM・CSS・共通コードが不変と確認できる場合に限る。環境固有の機能は、その機能仕様が求める実行環境で確認する。

窓操作・保存寸法・表示倍率を変更した場合に加え、ヘッダー・最狭幅の部品・文字サイズの変更で最小外寸や倍率変更時の表示へ影響する場合は、Electron実機で枠を除いた表示領域も確認する。影響が不明な場合はこの確認を省略しない。実行した環境と省略・未確認の制約は、完了報告に短く記載する。

受け入れ条件に並ぶ760×560、560×760、480px前後、420px前後、320px、Electron最小外寸の意味を保存する。共通変更での確認と個別変更での確認を区別し、同じ測定をElectronと通常ブラウザの全組み合わせで重複させない。

通知の文言変更、個別CSS、共通CSS、窓の寸法、文書のみの変更の5例で、読み取り・自動検証・画面確認の対象が判断できたら完了とする。

### 5 最終レビューと検証を行う

編集終了後に「採用した5点と正式仕様の一致」と「検査対象の欠落・故障時・影響範囲」の2観点でレビューする。自己レビューか独立レビューかを明示し、今回の計画を理由に新しい常設のレビュー工程を増やさない。

検証設定・テストを変更するため、実装完了時は `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build` を実行する。負荷の高い全体テストとビルドは順番に実行する。見本専用コマンドも分離確認として一度実行し、製品の検証結果と分けて扱う。

文書リンクとアンカー、`git diff --check`、分離前後の検査対象、共通通知の描画結果、画面確認の判断例を確認する。成功後に追加変更があれば、正式な再実行条件に従う。既存の別作業による失敗と今回の変更による失敗を区別し、未解決・未実施を成功扱いにしない。

完了報告には変更点・検証成否・制約を短く記載し、別ファイルへの記録は第1工程の保存条件を満たす場合だけ行う。この整理のための継続的な計測、毎回の詳細な検証・レビュー記録、定例評価を新設しない。

## 今回の対象外

製品の表示・操作・保存・公開範囲の変更、AndroidやOBSの実機確認条件の一括削減、PC計測の負荷確認の削除、比較資料や過去の記録の削除、新しいテスト基盤や依存の導入、トークン使用量の計測基盤、配布物生成は含めない。実施時の既存の別作業の変更を戻したり、計画だけの作成を全体テスト・ビルドの成功として報告したりしない。
