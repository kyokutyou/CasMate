## 実カメラ・SRT・OBS

実機のカメラと内蔵マイクを、同じLANの検証専用PC受信環境へ送信した。受信には製品のネイティブワーカーを使用し、専用のポータブルOBSでループバックUDP映像をデコードした。利用者のPC登録・接続設定と既存OBSには変更を加えていない。OBSの配信・録画は開始していない。

`OutdoorDrawingLiveDeviceTest` 1件が最終版で成功（94.578秒）。送信中の編集操作をテストから入力し、赤い線、全消去、取り消しをOBSの復号済み画素で確認した。960×540画像の中央検証領域に含まれる赤画素数は以下の通り。

| 操作段階 | 赤画素数 |
| --- | ---: |
| 描画前 | 0 |
| 描画後 | 5,631 |
| 全消去後 | 0 |
| 取り消し後 | 5,658 |

モード開閉とコメント・カメラのタブ往復で接続世代を維持し、映像・マイクの送信フレーム数が増え続け、入力故障がないことを確認した。読み上げサービスも停止しなかった。終了後は送信・読み上げを停止し、元の登録JSONと品質設定の一致、音声の再開希望解除を確認した。検証用PC・OBS・受信ワーカーを終了し、一時招待と制御用資格情報を削除した。

初回の実送信試験では、利用者のPC接続がOFFのため送信前提が成立せず、一時環境へ切り替えた。次の試験は段階開始の1秒後にOBS画像を撮影したため、前段階の映像を判定して失敗した。OBS設定を変更せず、各段階を維持して期待する復号画素の到着を待つ方式へ修正して成功した。停止後の音声設定保存にも非同期の完了待ちを追加した。これらの失敗を合成成功として扱っていない。

ログと一時検証スクリプトは `tmp/android-handwriting/`。登録値や実カメラの画像を正式文書へ添付しない。
