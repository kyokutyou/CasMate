# OBS着せ替えツールの検証（2026-10-08）

対象は[OBS着せ替えツール仕様](../features/obs-style-editor.md)の初版。正式な挙動は同仕様が所有する。

| 環境 | 確認方法・結果 |
| --- | --- |
| Windows Chrome 154.0.8037.98 | 通常の利用者設定と分離した一時プロファイル・headless実エンジン。生成HTMLを `file://` で開き、編集・プリセット・タブ保持・取り消し／やり直し・コピー成功・CSSとJSONの実ダウンロード・JSON読み込みを確認 |
| Windows Edge 154.0.4258.62 | 同条件・同検証。320px幅の横方向の溢れなし、空欄・範囲外・不正JSON・危険なフォント名／見本文を確認 |
| Electron 43 | 生成HTMLのiframeと実アプリの表示ページを同じ見本・寸法・生成CSSで比較。積み上げ・1件・見出し非表示・標準字幕・位置と最大幅・危険入力・影の7例で、位置／寸法／文字／色／余白／折り返しの計算結果が一致 |
| 実OBS Studio 32.2.2 | インストール済みOBSを一時的にコピーしたポータブル環境。音声入力なしの専用シーンに、共有表示部品から書き出したローカル見本と生成CSSを別々にブラウザソースへ設定。1件コメント・積み上げ長文／改行・サービス／投稿者の非表示・透明背景・標準字幕の左下配置・中央上の縁取り字幕をソースのPNG取得と目視で確認 |

Chrome／Edgeの検証はElectronとは独立して行った。両ブラウザでページのHTTP(S)要求・実行時例外は0。フォントと文章の引用符・改行・HTML終了タグは実行されず、外部画像を取得しなかった。通常のブラウザ設定・OBS設定・シーンを変更していない。

OBSの取得PNGはRGBAで、全5例の左上画素は完全透明だった。標準字幕1600×300の可視範囲は `(12,142)–(579,288)`、1件コメント600×800は `(12,12)–(588,175)`。長文が見本寸法を超えるケースはソース端で切れ、ツールは文字を縮めず警告する。

## 自動検証とレビュー

- `pnpm lint`、`pnpm typecheck`、`pnpm test --maxWorkers=4`：成功。全体は130ファイル・1202件。
- `pnpm build`：成功。単独HTMLを通常ビルドへ連携し、`dist-tools/obs-style-editor.html` だけを生成。インストーラーは生成していない。
- 仕様との一致／故障時・影響範囲を実装担当と別の2名が独立レビュー。影だけが切れる場合の警告不足1件を修正し、実描画回帰テストと両レビューの再確認を完了。
- 変更前の全体テストで既存画面2件が5秒制限に達した。個別実行73件は成功し、同時実行数4の変更前全体1131件と変更後全体1202件が成功した。タイムアウトした実行は成功扱いしていない。

実エンジン検証は[検証fixture](../../tests/fixtures/obs-style-editor-native-browser.mjs)、描画比較は[統合テスト](../../tests/obs-style-editor-rendering.test.tsx)で再実行できる。通常ビルドでは既存の大きなアプリchunk、CMakeの非推奨設定、NuGetの脆弱性情報取得失敗（NU1900）について警告が出た。NuGetのオンライン監査は完了扱いにしないが、コンパイル・ビルドは成功している。

## 確認の限界

ブラウザはheadless自動操作であり、利用者の通常ウィンドウでの手操作とは区別する。実OBSは架空の静止内容を使ったCSS描画確認で、実サービスの受信、音声認識、配信・録画や表示期限の実運用確認へは広げない。これらの既存契約は変更していない。
