# OBS映像確認の実装・検証（2026-10-14）

正式な動作は[OBS映像確認仕様](../features/obs-program-preview.md)が所有する。本記録は今回確認した差分・条件と未確認範囲を示す。

## 実装した範囲

- PCの認証付きOBS接続から本番シーン全体を撮影する処理と、既存の制御版3による対応機能通知・撮影・取消・受信確認付き画像転送を追加した。登録資格・保存・プロトコル版は変更していない。
- Androidの「送信・配信」に確認画面を追加した。明示的な開く操作による1枚取得、手動更新、旧画像の破棄、背景・接続・許可変更時の取消を実装した。
- 同じ作業ツリーでは手書きUI等の別変更も進行していた。これらを戻したり、本機能の実装として扱ったりしていない。

## PC検証

- 変更前の全体テストは146ファイル・1578件成功した。サンドボックス内のpnpm実行はrealpathのEPERMで失敗し、通常権限で実行した。
- 追加した撮影・OBS操作許可・認証・分割転送・世代・取消・同時要求の関連テストは成功した。OBS無応答の5秒期限も確認した。
- 実TCPの中継で下りを64バイト／16ms（約4KiB/秒）に制限し、16,000バイトの合成データが受信され、転送中に2回以上のpingへ応答し、制御接続が維持されることを確認した。実OBS画像や実外部回線の測定ではない。
- 最終の`pnpm lint`・`pnpm typecheck`は成功した。通常4並列の全体テストでは既存の着せ替えUI・通知描画テストにタイムアウトが出た。重いAndroid検証の終了後、`pnpm exec vitest run --maxWorkers=2 --testTimeout=15000`で147ファイル・1598件すべて成功した。条件変更後の成功だけで失敗原因は確定していない。
- `pnpm build`は成功した。

## Android検証

- 画像メタデータ・JPEG寸法・断片・旧世代・過大入力、受信予算の分離、取得・更新・取消・画面入口の関連単体テストは成功した。ライト／ダーク、320dp、文字2倍で処理中・成功・長いエラー間の画像領域と操作位置保持を自動描画で確認した。
- Android lint、アプリのデバッグ用Kotlinコンパイル、実機テストのKotlinコンパイルは成功した。
- 並行Gradle実行ではJARの使用中エラーが発生した。その後の関連テスト実行は成功した。初回の全体単体テストは351件中、別変更範囲の手書き入力・画面に14件の失敗が出た。PCビルド終了後の最終再実行は352件中344件成功、`OutdoorDrawingUiTest`の8件が失敗した。本機能のテストは成功したが、Android全体成功とは扱わない。最終実行は`--continue`でlintとアプリ／実機テストのコンパイルの成功を個別に確認した。
- Gradleの`connectedDebugAndroidTest`はUTP補助依存の取得に失敗した。コンパイル済みデバッグ／テストAPKをADBで登録を保持して更新し、同じ実機テストをADBから実行した。
- 実機では`ObsProgramPreviewDeviceTest`と`ObsProgramPreviewEntryDeviceTest`の2テストが成功した。640×360の合成JPEGの受信・描画、両配色と文字2倍での操作位置、実アプリの「送信・配信」から確認画面の開閉と、停止中の映像送信・読み上げが開閉で開始されないことを確認した。合成画像の画面も目視した。登録の変更・配信開始は行っていない。

## 独立レビュー

- 仕様との一致：取消後にも実行中のOBS要求が撮影枠を保持すること、画像転送による受信キュー・ハートビートへの影響を指摘・修正した。修正後の再レビューに未解決の具体的指摘はなかった。
- 故障時・影響範囲：撮影枠の早期解放と共有受信キューの超過を修正した。さらに大量の過大画像断片も画像だけの失敗へ分離し、129断片をメイン処理待ちにした回帰テストを追加した。修正後の再レビューに未解決の具体的指摘はなかった。
- レビュー担当はコード・仕様・テストの読取を行い、テスト実行や実機確認を代行していない。
