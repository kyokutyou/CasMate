# OBS映像確認の実OBS・Android検証（2026-10-14）

正式な動作は[OBS映像確認仕様](../features/obs-program-preview.md)が所有する。本記録は[実装・自動検証記録](obs-program-preview-2026-10-14.md)に続く実機確認であり、未実施の条件を確認済みとは扱わない。

## 確認条件

- Windows上のビルド済みきゃすメイト、OBS Studio 32.2.2、Android 12の実機を使用した。既存のLAN登録と認証付きOBS接続を使用し、登録資格・接続設定を変更していない。
- OBSのキャンバスは1920×1080、本番シーンは「テストB」。OBS配信は停止状態で確認した。配信・録画は開始していない。
- スタジオモードでは編集中プレビューを「テストA」、本番を「テストB」にした。本番にだけ識別用の一時テキストソースを追加し、画像の違いを目視した。
- 確認は実アプリの「送信・配信」→「OBS映像を確認」から行った。製品コードの変更は行っていない。

## 結果

| 条件・操作 | 実機で確認した結果 |
| --- | --- |
| スマホ送信停止中・OBS配信開始前に開く | 本番シーンの画像、シーン名、PC側の取得時刻が表示された |
| 本番のテキストをCHECK 1からCHECK 2へ変更し、更新せず待つ | 画像と取得時刻は変わらず、自動再取得しなかった |
| 「更新」を押す | CHECK 2を含む画像へ変わり、取得時刻も更新された |
| スタジオモードでプレビューA・本番Bに分けて更新 | テキストを含む本番Bが表示された。OBS側のプレビューAにはテキストがなく、実画像で区別できた |
| ホーム画面へ移動してからアプリへ戻る | 前の画像と取得時刻が破棄され、自動再取得しなかった。手動更新で再表示できた |
| 確認画面を閉じて開き直す | カメラ画面へ戻り、再度開く操作で取得できた |
| スマホの映像・マイクをSRT送信しながら取得 | 画像取得に成功し、送信サービス・マイク入力・送信ビットレートの表示が継続した |
| SRT送信中にOBSを終了 | 旧画像が破棄され、接続・許可の確認案内が表示された。スマホ送信サービスは継続した |
| OBSを再起動 | 自動再取得せず、手動更新で本番Bを再表示できた。スマホの映像・マイク送信も継続していた |

取得時刻の例は、テキスト変更前12:12:22、手動更新後12:13:17、プレビューと本番を分けた取得12:13:52、SRT送信中12:16:53、OBS再起動後12:19:51（PC表示・日本時間）。本番シーン全体に一時テキストが合成されることを確認したが、コメント・手書き・非表示映像の組合せを代替する検証ではない。

背景移行はホーム画面への移動を確認し、別操作を挟んでから復帰した結果で判定した。ホーム移動直後に同じコマンド内で即復帰した試行は、背景ライフサイクルの確認として数えていない。

## 後片付け

- 自分で追加した一時テキストソースを識別子で確認して削除した。本番B・スタジオモード無効へ戻し、OBS配信停止を確認した。
- スマホの映像・マイク送信を確認ダイアログから停止し、送信サービス終了と停止表示を確認した。
- その後、OBSは12:24に正常終了していた。今回の新しいクラッシュ記録はなく、最終状態を「OBS起動中」とは扱わない。
- 確認画像を製品の保存・履歴・ログやAIサービスへ追加していない。検証用の灰色背景と識別テキストの画面資料のみ一時作業領域に保持した。スマホのカメラ映像は記録資料として保存していない。配布物は生成していない。

## 未検証

- Tailscale：スマホの経路選択が無効で、今回の接続には利用できなかった。
- 直接接続：スマホに登録済みの選択肢はあるが、PCの接続経路変更や実外部回線での確認は行っていない。
- コメント・手書き・非表示映像を組み合わせた本番シーン、実際に読み上げが稼働している状態との同時利用。
- 実弱回線・縦長キャンバス。期限・連打・権限失効・不正断片・旧PC等の故障条件は既存の自動検証結果を参照し、今回の実機確認済みとは扱わない。
