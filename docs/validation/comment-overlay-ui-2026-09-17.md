# OBSコメント表示 A案の実装検証

## 対象と順序

利用者が3案の比較からA「一覧で調整」を採用し、「1件ずつ」を左・先頭・既定にするよう指定。`docs/features/comment-overlay.md`、`management-screen.md`、`local-application.md`の所有範囲を更新してから製品コードを変更した。共通編集見出し・通知・状態保持・設定保存・ループバック管理面の契約を確認した。

基準コミットは `29761d1c156643b4b5a22ace3ea35c27c8cc9de1`。比較見本は以前の状態の設計資料として残し、READMEに採用結果を記載。製品画面は独立した `CommentOverlayPanel` として実装し、共通自動保存を利用する。

新規設定はsingle。保存済みstack/singleは現在形式と旧形式の読み込みで維持する。Windowsフォント一覧は管理認証付きのローカルAPIだけに追加し、OBS用公開データとモバイルLAN面には含めない。

## 実画面

製品のViteビルドとLocalServer/AppStateをlocalhost:5399で起動。設定はメモリのみで、利用者の設定ファイル・接続先を変更せず、コメント取得・読み上げを開始していない。

- 1280pxで共通の戻る矢印、画面名、緑の説明枠、Aの領域順、左の「1件ずつ」が選択済みであることを確認。
- 幅760px、560px、320pxで確認。横方向のページはみ出しなし。320pxでは1件ずつ→積み上げの順で縦に並び、プレビューも画面内に収まる。
- 実Windowsのフォント一覧を取得（システムUI選択を含め323項目）。メイリオを選ぶと保存済みプレビューのcomputed fontFamilyに反映。検証後はYu Gothic UIへ戻した。
- 積み上げの新着を上へ選ぶと架空コメント3件の順序が変わり、1件ずつに戻すと1件になる。Escで閉じて開くボタンへフォーカスが復帰する。
- 文字サイズ201を入力すると要確認1件。ホーム往復後も201・aria-invalid=trueを保持し、32へ修正すると要確認0件。
- 実URL `http://127.0.0.1:5399/overlay/comments` のコピーと共通成功トーストを確認。コピー前後のボタン矩形は同一（幅136px、高さ38px、同一位置）。ブラウザーコンソールの警告・エラーなし。

Electronネイティブウィンドウ、実OBSブラウザソース、実読み上げとの同期は今回の実機確認未実施。表示キュー・保存・認証境界は自動テストで確認した範囲と区別する。インストーラー・配布用EXEは生成していない。
