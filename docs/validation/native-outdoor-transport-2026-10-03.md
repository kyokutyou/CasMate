# ネイティブSRT送受信の検証

2026-10-03。[外配信仕様](../features/outdoor-streaming.md#ネイティブ送受信契約)と[ADR 0018](../adr/0018-native-srt-and-local-receiver.md)の実装を対象とする。基準コミットは `e56d8ba25fa788af5209c7eef722d21918c45372`。実装・自動検証と、総遅延などの実測目標の達成は区別する。

## 対象と環境

Androidの撮影・エンコーダー・MPEG-TS生成を維持し、送信をJNIのlibsrt Callerへ変更した。Windowsは端末別のlibsrt Listenerで受け、再エンコードせずループバックUDP経由でOBSへ渡す。PCの映像OFF・端末削除・経路変更・アプリ終了で対応する受信を停止する。PC受信確認は完全なPES・PTSの進行で判定し、OBSの復号・表示確認と分ける。

- Windows 11、Visual Studio C++ tools 18、CMake 4.3.1。固定したlibsrt 1.5.7、Mbed TLS 3.6.7の公式アーカイブをSHA-256で確認してビルド。
- AndroidはJDK 21、SDK 37、NDK 28.2.13676358、CMake 3.22.1、Gradle 9.5。Java/Kotlinの出力対象は17。
- 実機はPixel 10aのAndroid 17/API 37、家庭内LAN、OBS 32.2.2（obs-websocket 5.7.4）。実機の送信はH.264、SRT設定400ms。

合成メディアの検証は600kbpsの制限、400ms分のプロキシキュー上限、17個に1個の破棄、30msの遅延、切断を含む。実登録情報やカメラ・マイクを使用しない。復号フレーム数・損失件数・復帰時間はこの実行の観測値で、全構成での保証値ではない。複数受信は2個の独立ワーカーで検証した。

途中のPC全体テストで旧版判定の期待1件が失敗し、登録応答の現行契約に合わせて修正した。レビュー修正後に上表の全体検証を行った。Android lintはJDK 17でlint内部の `List.removeLast` が失敗したため、JDK 21へ変更して再実行した。最終Android lintはエラーなし・15警告。WindowsのPC状態ワーカービルドには、NuGetの脆弱性フィード取得に失敗する既存の `NU1900` 警告が残る。未解決の警告と検証成功を区別し、警告を隠す変更はしていない。

## 更新・LAN実機・OBS

- PCの実設定を旧保護形式から版2へ移行した。元設定の暗号化バックアップ、端末ID・名前・認証情報の保持、旧ポートの予約、新しい受信／ローカル転送ポートの割当てを確認した。新版の登録応答は版7、外配信設定は版3。
- Pixelへ検証用APKを更新し、共通登録情報から同じ端末IDで再登録した。再登録の冪等性とコメント接続のinstrumentationは2テスト成功。既存のOBSメディアソースを新しいループバックUDP入力へ変更した。
- 実カメラ・マイクで送信し、新しい接続世代のPC受信確認とAndroidでの明示停止を確認した。OBSの本番配信・録画は開始していない。
- PC受信を2秒OFFにし、ONに戻す実機試行を2回実施した。ONから現在世代の映像受信を確認するまで **1,281ms／1,608ms**。両試行で世代1から3へ更新され、SRTの設定値は400msだった。撮影を保った再接続を確認した値であり、カメラからOBS表示までの総遅延ではない。
- 2回目にOBSを同時観測した。8回ともメディア状態は再生中、復号画像のハッシュは5種類、音声メーターは504観測成分中480が非ゼロ。画像はメモリー内で比較し、保存していない。この観測は画像の更新と音声信号の存在を示すが、画質の目視評価・実際の聴取・音声同期の評価は代替しない。

instrumentationは終了時にAndroid送信を停止し、PCの映像設定はONに戻した。録画ファイルや配信用資格情報を本記録へ含めていない。

## 管理画面

Electronで本番部品とCSSを描画し、320・560・760px幅の横はみ出し、12パターンの通知前後の操作位置、PC受信状態の変化前後のボタン位置・スクロール・本文高を自動確認した。描画画像でも読みやすさを確認した。

Codex内ブラウザで実PCアプリを操作し、LAN／Tailscaleの表示切替、実際の公開選択を保持すること、PC受信状態、ループバックUDP入力のコピー通知、非選択経路での無効化、画面を戻ったときのフォーカス・表示選択を確認した。320×760pxと760×560pxでも端末の受信状態・OBS入力欄を目視した。Chrome／Edgeの通常ブラウザは利用可能な操作接続がなく、今回の個別確認は未実施。

## 独立レビュー

仕様との一致と、規約・故障時・影響範囲の2観点を別の担当でレビューした。過去の映像受信確認が音声だけの継続で残る問題、PC側の破棄数の未反映、古いフィードバックを有効扱いする問題、移行バックアップの途中書込み、NAK・送信バイトの単位を修正した。両端の破棄数は検出件数の合算であり同一DATAが重複し得ることも明記した。回帰テストを追加し、再レビューでは重大な未解決指摘なし。

- カメラからOBS表示まで1秒未満の総遅延、同じ環境での旧方式とのCPU・帯域・遅延比較は未測定。方式変更だけで効率改善や目標達成を保証しない。
- Tailscale経由の実機、2台以上の実Android同時送信、実機H.265、長時間送信、画面ロック・アプリ切替、実際の音声聴取と同期は今回未確認。合成テストや単体テストでこれらを確認済みにしない。
- Windowsインストーラー・配布用EXE・リリースAPKは生成していない。PCの通常ビルドとAndroidの検証用デバッグビルドまで。
