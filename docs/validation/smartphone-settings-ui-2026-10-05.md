# スマホ連携設定の再構築・描画検証（2026-10-05）

日常の接続と状態確認を優先する依頼に対して「接続ハブ」を本体へ実装した。正式な配置・表示契約は[スマホ連携仕様のPC管理画面](../features/smartphone-integration.md#pc管理画面)が所有する。本記録は今回の差分の確認結果であり、接続準備一本化・直接接続の実機受け入れを完了扱いにしない。

## 対象と確認結果

- ネットワーク表示とON／OFF、接続・共通QR、端末一覧・OBS入力コピーを主な操作として再配置した。コメント・音質、OBS手順、接続の詳細設定は明示展開にした。
- 準備によるポート割当だけの経路を登録済みと表示しないよう、PC保存済み資格に由来する管理表示用の登録有無を追加した。保存形式、Android応答、受信プロトコル、公開入口は変更していない。
- 回帰テストで初期表示、表示と公開の独立、未登録経路、部分的な映像準備失敗、空の端末一覧、保存失敗時の操作抑止、既存のQR寿命・自動保存・画面往復を確認した。
- PC登録の投影では、LAN登録成立、Tailscale準備済みだが未登録、登録保存の失敗／成功、OFF後の登録保持、管理スナップショットへの秘密情報の非混入を確認した。
- 比較見本は「接続ハブ」「ステップ案内」「端末ワークスペース」の3案。架空データを使い、実登録・接続準備・クリップボードへの書込みは行わない。

## コマンドと実行条件

Windowsのコマンドでは既存の `node_modules/.bin` をPATHの先頭へ追加した。全体テストとビルドは同時実行していない。

| 対象 | 結果 |
| --- | --- |
| `pnpm lint` | 成功。264ファイル |
| `pnpm typecheck` | 成功。main・renderer |
| 関連3ファイルのVitest | 成功。43件 |
| `pnpm test --maxWorkers=1` | 成功。99ファイル・823件、317.83秒 |
| `pnpm build` | 成功。Vite、TypeScript、Windows補助ワーカー、ネイティブSRTワーカー |
| `git diff --check` | 成功 |

初回の全体テストでは、開発サーバー動作中に11スイートのモジュール読込と別画面の1件が失敗した。開発サーバーを停止した関連12ファイルの確認は154件成功した。4ワーカーでの全体実行ではコメント取得画面の5秒タイムアウトが発生し、後続の仮タイマー操作も失敗した。検証対象・タイムアウトを変更せず1ワーカーで全体実行し成功した。並列数を下げた成功だけから原因は確定しない。

制限内のElectron起動はGPU／一時ファイル制約で失敗したため、描画を含む確認は制限外で実行した。初回lintのfinally内の例外処理と、型チェックの代替状態オブジェクトの不足は修正後に再確認した。

最初のビルドは起動中の本体が受信ワーカーEXEを保持し、最後のコピーが `EBUSY` で失敗した。生成済みEXEと既存EXEは同一ハッシュだった。利用者の終了・再起動許可を得て、本体とワーカーが終了済みと確認した後に同じビルドを再実行し成功した。再起動後は管理ウィンドウの存在・応答、ローカルHTTPの200と今回生成したJSアセットを確認した。

ビルドには既存のNuGet脆弱性データ取得失敗 `NU1900` と依存CMakeの非推奨警告が残る。オンライン脆弱性確認の成功とは扱わない。配布用インストーラー・APKは生成していない。

## 描画・操作の確認範囲

本体の `ManagementShell`・`SmartphonePanel`・CSSを実際に描画するReactフィクスチャをElectronで実行した。実バックエンド、登録資格、カメラ、OBS操作、ルーター開放は使わない。

- LAN／Tailscale／直接接続の全3画面で、表示領域320×760、420×760、480×760、560×760、760×560を確認した。
- 各幅で実入力からの保存待ち→成功→失敗、実際のprops更新による受信中→古い報告・受信エラー、長文通知・直接接続の長い資源一覧、通知消去の7段階を確認した。計105段階で操作対象の矩形、本文高さ、スクロール、フォーカスが更新だけで変わらず、横はみ出しがないことを検証した。
- 全3スイッチの可視性とネットワーク見出し・説明の文字コントラストを測定した。最初の目視でスイッチの親を隠すCSSを発見し、修正と可視性の回帰確認を追加した。
- 画面往復の詳細開閉・入力保持・起点へのフォーカス復元、QR内のTabとEscape、QR起点への復帰を確認した。
- Electronの最小外寸320×360とズーム1.0／1.25で、枠を除いた表示領域の横はみ出しを確認した。通常幅と320pxの生成画像で可読性・折り返しを目視確認した。
- アプリ内ブラウザで本体フィクスチャへの入口、QR表示とEscape、OBSコピーの共通トースト、不正ポートによる要確認・QR／OBS抑止、ホーム往復での入力・開閉・フォーカス保持を操作した。
- 比較見本も隔離したElectronで320px／1024pxの全3案を描画し、横はみ出しと入力・ボタンの欠けがないことを確認した。アプリ内ブラウザで案切替、経路表示とスイッチの独立、直接接続でのURL非提供を確認し、実行エラーはなかった。

通常Chrome／Edgeを操作できる接続はなかった。アプリ内ブラウザでの確認を通常ブラウザでの完了として扱わない。実Android・実OBS・実ルーター・外部回線による接続確認は今回未実施。

## OBS登録手順の案内帯の追加（2026-10-05）

利用者が配置見本の「独立した案内帯」を採用し、本体へ実装した。配置と操作の正式仕様は引き続き[PC管理画面](../features/smartphone-integration.md#pc管理画面)が所有する。本追記の結果を、実Androidや実OBSの接続確認として扱わない。

- 手順の常設入口、3経路の共通配置、未登録・全経路OFF・利用不可・保存失敗・処理中でも閲覧できること、状態更新時のフォーカス保持、閉じる／Escでの復帰、画面移動時の消去、遅いQR応答との重複防止を回帰テストで確認した。AndroidからのOBS操作の設定入口も保持した。
- `pnpm lint`（264ファイル）、`pnpm typecheck`、画面操作テスト（32件）、Electron描画テスト（3経路）、`pnpm test --maxWorkers=1`（99ファイル・832件、314.41秒）、`pnpm build`、対象差分の `git diff --check` は成功した。ビルドには従来のNuGet脆弱性データ取得失敗と依存CMakeの警告が残り、オンラインの脆弱性確認を成功扱いにしない。
- 本体のReact・CSSフィクスチャをElectronで描画した。従来の105状態更新で案内帯のボタン座標も測定し、通知・保存・受信状態による移動がないことを確認した。3経路それぞれで320・420・480・560・760pxと最小外寸／ズーム1.0・1.25の計21条件について、手順ダイアログの領域内配置、横はみ出し、閉じる操作の可視性、内部のTab・Shift+Tab、Escと本文スクロール・起点フォーカスの復帰を確認した。通常幅と320pxの手順表示は生成画像でも目視した。
- 初回の描画確認は検証用JavaScriptの実行エラーで失敗した。繰り返す確認の変数を関数内のスコープへ修正し、全3経路を再実行して成功した。
- 通常ブラウザの代表操作は未完了。WindowsのComputer Useが現在のブラウザURLを確実に判定できず操作を停止したため、以後のUI入力を行っていない。前回のアプリ内ブラウザでの確認を、今回の案内帯の通常ブラウザ確認として扱わない。
- 編集後、担当者が「仕様との一致」と「故障時・影響範囲」を分けて自己レビューした。常設と明示開閉、OBS表示とOBS操作の区別、既存コピーの通知先、QRの寿命と遅延取消、保存・受信・公開・秘密情報に新しい処理を加えていないこと、CSSの影響が本画面に限定されることを確認した。独立レビューではない。
