# 共有記憶の文字数計算の測定（2026-10-15）

同一PC・同一条件で、変更前後に各3回測定した。発言追加時に書記素数を一度数えて保持し、状態表示では合計値を参照する変更により、1,000入力の同期処理の中央値は5,986.89msから32.13msとなった（約99.46%減）。

| 試行 | 変更前（ms） | 変更後（ms） |
| --- | ---: | ---: |
| 1 | 6032.3907 | 33.3834 |
| 2 | 5986.8921 | 32.1285 |
| 3 | 5955.9070 | 32.0914 |
| 中央値 | 5986.8921 | 32.1285 |

## 条件と再実行

- Windows、Node.js v24.19.0。Vitestのワーカー数は1。各試行は別のVitestプロセスで実行した。
- 対象は `tests/ai-controller.test.ts` の「遅い保存中の1000入力を最新1件へ集約し、終了で最終保存とflushを待つ」。
- 初期状態は既定設定。最初のコメント1件の保存を保留し、続いて `コメント0`、`発話1`、…、`発話999` を交互に追加する1,000回のループのみを `node:perf_hooks` の `performance.now()` で計測した。文字数計算以外に、入力受付・状態通知等も含む。
- セットアップ、保存完了待ち、終了処理、API通信は計測区間に含まない。実ディスクの速度、配信中のCPU使用率、音声やAIの応答時間の測定ではない。OS負荷等で値は変動するため、回帰テストに時間の合否閾値は設けない。

PowerShellで次を各3回実行する。変更前の値は最適化前の実装で取得した。

```powershell
$env:CASMATE_AI_MEMORY_BENCH = '1'
pnpm exec vitest run tests/ai-controller.test.ts -t '1000入力' --maxWorkers=1 --reporter=verbose
Remove-Item Env:CASMATE_AI_MEMORY_BENCH
```

出力の `AI_MEMORY_INPUT_BENCHMARK` に実測値を記録する。通常のテスト実行では測定ログを出さない。

## 回帰確認

- 状態表示100回と設定上限の変更で既存本文を再分割せず、追加入力だけを一度数えることを呼出回数で検証する。
- 絵文字・結合文字、上限ちょうど・超過、古い発言単位の削除、単体超過発言の除外、上限縮小・拡大、保存待ちスナップショットの保持を検証する。
- 実ファイルへの保存・再読込、記憶削除後の空保存、削除後の入力と再読込で、本文と合計文字数が一致することを検証する。
- 発言別の文字数・合計はプロセス内の一時状態であり、保存形式と本文は変更しない。読込時は保存された本文から再計算する。
