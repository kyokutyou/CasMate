# 起動処理の最適化と検証（2026-10-07）

## 対象と変更

ホーム表示までの待ち時間と初回描画の負荷を調査した。正式な起動契約は[ローカルアプリケーション仕様](../features/local-application.md)、設定画面の生成・保持は[管理画面仕様](../features/management-screen.md)が所有する。

- ローカル設定の復元とループバックHTTP/WebSocketの開始後に管理画面を生成する。スマホ接続の準備と起動時の外部コメント接続はバックグラウンドで進める。
- 未訪問の設定画面本文は初めて開くときに生成する。訪問後は保持し、編集中の値・詳細展開・処理状態を失わない。ホームの警告とエラー表示は初回から利用できる。
- 待機中の停止・終了で接続やウィンドウが復活しないようにする。初期復元と設定変更を直列化し、初期化中のスマホ台帳を操作可能な状態として公開しない。古い接続からのコールバック・失敗も新しい接続へ反映しない。

着手時から存在したスマホ終了処理等の変更は保持した。配布物は生成していない。

## 起動計測

Windows上の実Electronとビルド済みアプリで、通常条件とスマホ準備に500msの遅延を注入する条件をそれぞれ変更前後3回ずつ測定した。開始点は製品のmainエントリーをimportする直前、終了点はホームのDOMが表示可能になる時点とした。

各回で一時的なappData/userData/sessionData/logsと絶対パスの一時作業ディレクトリを使用した。設定は初期値、外部コメント接続・音声・AI・スマホ公開は無効、ポートは動的割当。利用者の保存設定は変更していない。管理ウィンドウは非表示で計測したため、OSが画面へ提示するまでの時間やPC状態のポーリングを含まない。

比較元は着手時に存在したビルド、変更後は今回の最終 `pnpm build` によるビルドである。OSのキャッシュを消去したコールド起動ではなく、標本数も少ないため、通常条件の小さな差を普遍的な速度向上として扱わない。

| ホーム表示まで | 変更前の3回（ms） | 変更後の3回（ms） | 中央値の変化（ms） |
| --- | --- | --- | --- |
| 通常条件 | 744.4 / 713.8 / 929.4 | 816.5 / 702.5 / 648.9 | 744.4 → 702.5 |
| スマホ準備に500ms遅延 | 1457.9 / 1242.2 / 1665.4 | 659.8 / 639.8 / 662.7 | 1457.9 → 659.8 |

遅延条件では変更後の全3回で、スマホ準備が完了する前にホームが表示された。これは待ち合わせを起動経路から外した確認であり、実サービスの通信時間を測った結果ではない。

通常条件の初回DOMは1,657〜1,659要素から433〜435要素へ減った（約74%減）。JavaScript転送量は500,098から500,190 bytesで、コードの転送量削減は今回の改善に含まない。mainエントリーのimport時間中央値も365.1から392.9msで改善していない。

計測用スクリプトと生データはGit除外済みの `tmp/startup-profile/` に保存した。正式仕様としては扱わない。

## 挙動・描画の確認

非同期待機を制御した回帰テストで変更前の失敗を再現してから修正した。管理画面表示を妨げるスマホ準備、必須ローカル初期化の保持、各待機点での終了、手動停止と遅れた自動接続、重複接続、古いコールバック、スマホ台帳正規化中の編集拒否を確認した。

実Electronのビルド済みDashboardで、13編集先を320×760、420×760、480×560、560×760、760×560の5サイズ、計65組で確認した。初回本文生成、見出しへのフォーカス、戻る際のフォーカスとスクロール位置、非表示項目へのTab移動防止、編集途中の無効入力と詳細展開の保持を確認した。最小外寸320×360と倍率1・1.25も確認した。15枚の画像を目視し、画面名の一致・狭幅の横はみ出し・操作の重なりを確認した。

通常ブラウザでも隔離したローカルサーバーのビルド済み画面で、ホーム、設定一覧、コメントフィルターの初回表示、戻る際のフォーカス、入力・詳細展開の保持、操作結果の共通トーストを確認した。このブラウザ確認のネイティブウィンドウ操作はスタブであり、実際のウィンドウ操作はElectronの全体テストで確認した。

描画用の非表示ウィンドウでは、GPU有効時のキー入力未到達と最初のcaptureに過去フレームが残る現象を確認した。既存Electron描画fixtureに合わせたGPU無効・backgroundThrottling無効の検証ウィンドウと、描画更新後の2回目captureへ変更して再実行し、全65組と15枚の目視確認が成功した。起動計測条件と製品コードはこの検証調整で変更していない。

編集後の独立レビューを「仕様との一致」と「故障時・影響範囲」に分けて実施した。レビューで見つかった、AI終了待機中のコメント接続再開とスマホ台帳正規化中の操作競合は回帰テストを追加して修正し、修正後も独立確認した。未解決指摘はない。

初回lintは未追跡の計測スクリプトを検査して失敗した。計測専用ファイルを既存のGit除外対象 `tmp/` へ移して再実行した。製品・テストの検査対象は除外していない。

初回の既定並列数による全体テストでは、4つのElectron描画テストの一時フォルダー削除が `EBUSY` で失敗した。当該4ファイルは並列数1で再実行して成功し、その後の全体検証は並列数4で全件成功した。並列数を下げた結果だけで失敗原因を確定していない。途中の追加描画テスト実行にもタイムアウトがあり、成功として数えず、最終の全体成功と上記の実Electron描画確認で検証した。

ビルドにはViteの500KB超チャンク警告と、PCワーカーのNuGet脆弱性情報取得失敗（NU1900）が残る。ビルド自体は成功した。CMakeの既存警告もあったが屋外ワーカーのコンパイルは成功した。

利用者の実際の保存設定、外部サービスを有効にした実運用、OS起動直後のコールド起動、インストーラーは今回の計測対象に含めていない。
