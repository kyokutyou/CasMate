# コメント読み上げのホバー時スクロール修正

## 原因と変更

- 初回の話者未選択・エンジン未検出状態で読み上げをオンにし、下部の「エンジンの場所を指定」「話者一覧を更新」へマウスを移動すると、Electron 43.4.1で本文のスクロールが約306px上へ移動した。本文の高さとフォーカス先は変化しなかった。
- 共通の `button:hover` の `filter: brightness(1.08)` だけを除いた場合、およびスクロールアンカーを無効にした比較条件では移動が止まった。製品ではスクロール処理を変えず、読み上げ画面のsecondaryボタンだけを背景色によるホバー強調へ変更した。
- 設定保存・VOICEVOX接続・通知の処理に変更なし。作業開始時から存在したスマホ連携等の変更は維持した。

## 検証

- `tests/comment-speech-scroll.test.tsx` は製品の設定部品とCSSを使用し、実際のElectronウィンドウへマウス移動を送る。320×560、560×760、760×560の表示領域で、両ボタンのホバー前後のスクロール、座標、本文高さ、フォーカス、ホバー成立を確認する。修正前は760px幅のエンジン選択で約276pxの移動を検出し失敗、修正後は6条件成功。
- 別途、実際のManagementShellとReactの設定部品でオフ→オンの操作を行うローカル検証画面でも両ボタンの位置保持を確認。Windows表示倍率125%。テスト用プロフィール・設定を使用した。
- `pnpm lint`: 成功（232ファイル）。
- `pnpm typecheck`: 成功。
- `pnpm test`: 成功（80ファイル、702テスト）。
- `pnpm build`: 成功。NuGetの脆弱性情報取得でNU1900警告あり。インストーラー・配布EXEは生成していない。

## レビューと制約

- 自己レビューで、操作位置保持の仕様、CSS適用範囲、キーボードフォーカス表示、既存の操作テストとの整合を確認した。独立レビューは実施していない。
- Electronはサンドボックス内でGPUプロセスを起動できなかったため、承認された制限外実行で検証した。
- 通常ブラウザーでの追加確認は操作ツールのタイムアウトにより未完了。既存のインストール済みアプリと実VOICEVOXへの接続は今回の検証対象外。
- 読み取り判断表から管理画面の共通規則と読み上げ仕様へ絞って調査できた。ブラウザーエンジン固有の現象のため、DOM単体のテストではなくElectronの回帰テストを追加した。
