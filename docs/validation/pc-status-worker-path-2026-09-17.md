# 配布版のPC計測ワーカー起動パス修正

## 原因と変更

配布設定は `resources/pc-status-worker` を Electron の resources ディレクトリ以下に同梱するが、起動側は `pc-status-worker` 直下を探していた。配布版だけで1階層ずれ、計測全体が再試行待ちになる。userData はこのパス解決に関与しない。

パス解決を `worker-path.ts` に抽出し、配布先と一致させた。開発版のパスは維持。配布設定から期待パスを求める回帰テストで、修正前の失敗・修正後の成功を確認。

## 検証

- 関連テスト15件成功。lint（218ファイル）、型チェック、`pnpm build` 成功。
- 全体テストは73ファイル中70成功、662件中654成功・8失敗。失敗は `text-effects-panel` 5件、`settings` 2件、`dashboard-source-start` 1件。開始時から存在する文字演出の既定ルール追加と、従来の1ルール前提の期待値・単一ボタン検索が不一致。今回その変更には手を加えていない。
- このWindows PCで、既存の `release/win-unpacked` に同梱されたワーカーを、ビルド後の修正版パス解決と `PcStatusController` / `JsonLinesPcSampler` から起動。設定データを読み込まず、5秒後に `running`、AMD Radeon(TM) Graphics と NVIDIA GeForce RTX 2060 with Max-Q Design の使用率・専用メモリ、PC物理メモリが全て `valid` であることを確認。停止後に検証プロセスが正常終了。
- GPU使用率は初回に未取得、2回目に有効な値となることを実測。検証時の計測ワーカー単体の2回目はCPU約0.36%、専有物理メモリ約11.6 MiB。
- `pnpm` の実行時にローカルbinが見つからなかったため、検証コマンドのプロセス内PATHに `node_modules/.bin` を追加。ビルドでは既存の NuGet 脆弱性情報取得失敗 `NU1900` 警告あり。
- インストーラー・展開版EXEは新規生成していない。インストール済みアプリの更新、userDataの削除、修正済み配布版の画面操作は未実施。

## 自己レビュー

- 仕様との一致：独立ワーカーを同梱先から起動する既存仕様への修正。設定保存や取得周期、表示仕様は変わらない。
- 故障時・影響範囲：ElectronのPC状態起動箇所だけが新しい関数を利用する。既存のタイムアウト・再試行・停止処理を維持し、音声認識・FFmpegの起動には影響しない。開発版と配布版の両方をテスト。独立した別担当レビューは行っていない。
