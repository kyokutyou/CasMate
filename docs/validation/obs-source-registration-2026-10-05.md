# OBSソース登録の実機・画面検証

2026-10-05実施。[正式仕様](../features/obs-source-registration.md)の実装を対象とした記録。正式仕様の代わりにはしない。

## OBS実機

Windows上のOBS Studio 32.2.2、obs-websocket 5.7.4で確認した。インストール済みOBSを作業ディレクトリ内の一時ポータブル環境へコピーし、認証付きループバック接続・検証専用コレクションを使用した。利用者のOBS設定は変更せず、配信・録画は開始していない。検証用OBSは終了済み。

製品の登録コントローラーと共通OBS接続を使用し、次を確認した。

- コメント・音声認識・キャラクター・文字演出の4種類を作成し、設定・項目・保存された配置値の読み戻しが成功した。
- 未受信のUDPメディアを追加できた。映像寸法が0×0でも、配置の枠は1920×1080として保存され、成功を確認できた。
- 同じ対象の再追加は追加済みとして処理され、別シーンへは同じブラウザ入力を共有した。非表示の入れ子シーンにある共有入力も検出し、重複項目を作成しなかった。
- FFmpegから合成H.264/AACを固定ローカルUDP入力へ送信した。横320×180と縦180×320をOBSが受信し、中央内接の配置設定と1920×1080の枠を保持した。配置は保存値の読み戻し、映像はソース単体のPNGで確認した。
- OBS音量イベントの有限かつ0～1の受信値を219回確認した。最大値は0.13148801028728485だった。
- 合成コメントのブラウザソース画像を取得し、透明部分と表示部分があることを確認した。アルファ抽出値の最小値は0、最大値は255だった。

実OBSの`GetSceneItemList`では通常入力の`isGroup`が`null`になることを確認した。パーサーと回帰テストを実応答へ合わせ、上記確認を再実行した。

## 管理画面

製品コンポーネントを使う描画用fixtureで、Electronと通常ブラウザを確認した。描画用fixtureのAPIは模擬であり、実OBSとの通信確認とは分けている。

- Electron：320×760、560×760、760×560の30シナリオ。4つの入口、処理前後・通知前後のボタン位置とフォーカス、長い未完了一覧、要確認からの直接復旧、スマホ経路OFF時の手動手順、Tab・Escを確認した。
- 通常ブラウザ：同じ3サイズで横方向のはみ出しがなく、本文だけがスクロールし、閉じると操作フッターが見えることを確認した。
- 通常ブラウザ320×760：追加前と処理中で追加ボタンの位置・寸法が一致し、フォーカスとページスクロールを保持した。Shift+Tabによる循環と、Esc後の元の入口へのフォーカス復帰を確認した。

画面fixtureとPNGはGit除外の`tmp/obs-registration-layout/`、実OBSの測定結果とPNGは`tmp/obs-source-validation/`に保存した。恒久的な配布物ではない。

## 未確認の範囲

Android実端末からの送信、LAN／Tailscale／直接接続を通る送受信、物理カメラ・マイクでは確認していない。OBSのメディア受信は合成データによる確認であり、「スマホ送信後の映像・音声」の実端末確認済みとは扱わない。入力形式・端末・経路別の選択、Androidとの排他と公開境界は自動テストで検証する。

この記録に全体テスト・ビルドの成功は含めない。最終検証結果と独立レビューは作業の完了報告に記載する。
