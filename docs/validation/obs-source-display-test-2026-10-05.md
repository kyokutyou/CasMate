# OBS表示テストの検証記録

2026-10-05実施。[正式仕様](../features/obs-source-registration.md#obs表示テスト)の実装を対象とする。実表示を自動判定する製品機能は追加していない。

## スマホ合成映像テストの除外

同日、利用者の判断でスマホ映像テストを除外した。スマホ登録ダイアログのテスト操作・状態欄、PCの合成映像生成、テスト専用ワーカー制御・転送保留、OBS再読込・再開と固定フレーム読取を撤去した。スマホのOBS登録・設定確認と通常のSRT→UDP転送、4つのブラウザ表示テストは現行対象とする。以下のスマホ合成映像に関する実測・調査は撤去前の履歴であり、現行機能の確認項目ではない。

- LAN／Tailscale／直接接続の全経路で、スマホのテストボタン・状態欄が表示されず、登録と通常送信の手順が残ることを回帰確認した。
- 同3経路の旧テストAPI指定は管理認証後に400 `OBS_TEST_UNSUPPORTED_TARGET`となり、OBS要求と占有取得を行わないことを確認した。
- ブラウザの準備中停止・遅延応答・次のテストへの非干渉・対象変更の警告保持、通常受信の関連テストを確認した。
- 撤去後の`pnpm lint`（製品288ファイル）、`pnpm typecheck`、`pnpm build`、`pnpm test:native`は成功。buildの既存NU1900・依存CMake警告は下記と同じで、完了を確認した。
- `pnpm test:native-media`：通常受信でH.264/AAC119フレーム、H.265/AAC89フレームを実デコードした。損失／破棄338、復帰779msを観測し、他端末隔離と親終了時の停止を確認した。実カメラ・マイク・回線の性能測定ではない。
- `pnpm test --maxWorkers=1`：撤去後の最終コードで110ファイル・973件すべて成功（390.23秒）。削除したスマホテスト専用テストを、スマホ指定の拒否・ブラウザの取消・警告保持などの回帰へ置き換えた。
- 仕様一致／故障影響の2名による独立レビューを完了し、P1／P2の指摘なし。通常受信に関わる5ファイルがテスト機能導入直前のsnapshotと一致することも確認した。
- Electronの既存描画検証と、Codex内蔵ブラウザの560×760／320×760でスマホ登録画面にテスト操作がないこと、横はみ出しがないことを確認した。閉じる操作で入口へのフォーカス復帰も確認した。ブラウザ確認は模擬APIを使用し、実スマホや実OBSの通信確認とは区別する。[撤去後のスマホ登録画面](../research/assets/obs-source-display-test/smartphone-without-test.png)。独立したChrome／Edgeの追加確認は未実施。

## OBS実機で確認した範囲

Windows 11、OBS Studio 32.2.2、obs-websocket 5.7.4。同じPCのインストール済みOBSを一時ポータブル環境へコピーし、新規設定・認証付きループバック接続・検証専用コレクションを使用した。利用者の通常OBS設定は変更せず、配信・録画は開始していない。検証用OBSは終了済み。

製品の登録・表示テストコントローラー、ローカルサーバー、ネイティブ受信ワーカー、同梱FFmpegを使用した。

- コメント・音声認識・文字演出・キャラクターの4種類をOBSで描画した。開始・手動終了後にソース単体のPNGを取得した。
- テスト中に通常コメントを追加し、終了後にその最新コメントが表示されることをPNGで確認した。通常履歴・認識結果へ架空表示を投入しないことはAPIテストでも確認した。
- 未受信UDP入力へ640×360の無音H.264テストパターンを送った。OBSがデコードした寸法とPNGを確認し、終了前後の保存入力設定が同一であることを照合した。
- テスト終了後、同じネイティブSRT→UDP経路からH.264（320×180）とH.265（192×320）の合成映像・AACを送信し、OBSのデコード寸法・PNGと音量イベントを確認した。最終実行で有効な音量値221回、最大0.1314496397972107を観測した。音量イベントを実マイクの聴取確認とは扱わない。
- 未受信入力の空更新後、OBS内部で新デコーダーも終了する場合があった。固定SerialFrame読取・ENDED継続確認・再検証後の一度のRESTARTを専用窓口に追加し、初回未受信と連続テスト、両形式への復帰を再確認した。

PNG：[コメントのテスト](../research/assets/obs-source-display-test/comments-test.png)、[終了後の最新コメント](../research/assets/obs-source-display-test/comments-after.png)、[テスト映像](../research/assets/obs-source-display-test/media-test-libopenh264.png)、[終了後の縦向きH.265](../research/assets/obs-source-display-test/media-after-libkvazaar.png)。ソース単体の取得画像であり、シーンの重なりやOBSミキサー全体の確認とは区別する。

## ネイティブ実通信

- `pnpm test:native`：暗号化、実SRT接続、期限・世代・キャンセル、テストセッションの3秒準備・5秒送信・2秒転送保留上限を確認した。
- `pnpm test:native-obs-display`：受動capability、実FFmpeg TS送出、5秒のワーカー期限、遅延Begin／TSの拒否、合成統計非混入、実SRTの途中接続による失効・通常転送への復帰を確認した。
- 同テストで、実SRTクライアントを接続したままメディアを送らず、テスト予約が拒否されることを確認した。64KiBを超えるTSバーストでは合成セッションが失効し、ワーカーの通常sampleが継続した。親パイプが詰まっても停止・復帰制御へ有界な書込余裕が残ることは単体テストで確認した。
- `pnpm test:native-media`：H.264/AAC119フレーム、H.265/AAC89フレームを実デコードした。帯域制限・損失・ジッター・断復帰で損失／破棄346、復帰777msを観測し、他端末隔離と親終了時の停止を確認した。この値は合成条件の観測であり、実回線・カメラからOBSまでの性能保証ではない。

旧版ワーカーへ新規要求を出さないこと、古いACK、応答不明、遅延予約、対象変更、停止不明時の占有保持、OBS再読込不明時の警告保持は自動テストで確認した。

## OBSで削除した後の再表示

同日の不具合修正。登録したコメントを複数シーンで共有し、OBSで現在のシーンから項目を削除して「OBSに追加」を開き直した場合を対象とする。適合入力が別シーンに残るため候補のソース名は正しいが、過去の成功を新しく開いた画面でも「登録設定を確認済み」と表示していた。

- 共有入力が残る場合と入力候補がなくなる場合の再表示を自動再現し、修正前に2件が失敗することを確認した。確認済み表示を当該画面から送信した操作に結び付け、開き直し・選択変更・削除通知では過去の成功を今回の確認に流用しない。過去の結果・未完了復旧は保持する。
- 入力・項目・シーンの削除通知で一覧を更新する。共有入力UUIDが変わらない場合も表示テスト可否を更新するよう、独立したcontext revisionを明示的な再取得条件に加えた。以前の可否応答による巻戻りを回帰確認した。対象シーンに項目がない場合は、追加してからテストする具体的な理由を返し、確認だけで登録を再送しない。
- 2名の独立レビューで、削除通知より遅い成功応答が新しい世代の確認済み表示を復活させるP2を発見した。HTTP終端と管理イベント終端の両経路で修正前の失敗を確認し、送信時の世代を保持する修正後に成功した。全体テストは途中の版を中断して最終コードで再実行した。再レビューの仕様一致軸・故障影響軸とも残るP1／P2なし。
- 最終UI関連4ファイル・66件が成功。Electron描画の36ケースと倍率1.25／1.5の24ケースでは、削除通知前後の寸法・ボタン位置・スクロール・フォーカスが保持されることを確認した。[削除後の実装画面（検証データ）](../research/assets/obs-source-display-test/deleted-shared-dialog.png)は模擬APIによる描画fixtureの画像である。
