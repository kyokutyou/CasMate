# 掲示板次スレッド作成仕様

## 問題

掲示板で配信中のコメントを受け付けている配信者は、現行スレッドが書き込み上限へ近づくと、配信を続けながら次スレッドのタイトルと本文を用意し、新規作成と接続先の切替を行わなければならない。手作業では作成忘れ、タイトル番号の更新忘れ、接続先の切替忘れが起こりやすい。

## 利用者視点の解決策

配信者は、現行スレッドの何番のレスで次スレッドを作成し、何番で接続先を切り替えるか設定する。きゃすメイトは現行スレッドのタイトルと1レス目から作成内容を用意し、指定したレス番号へ到達すると次スレッドを一度だけ作成する。作成後は次スレッドURLを表示し、任意で現行スレッドへ案内を投稿し、切替レス番号へ到達した時点で次スレッドへ接続し直す。

掲示板への外部書き込みを本機能へ限定した当初の理由とリスクは [ADR 0004](../adr/0004-limit-shitaraba-write-to-next-thread.md)、AIリスナーの採用による範囲の拡張は [ADR 0013](../adr/0013-adopt-ai-listener.md)、作成済み記録を永続化せず掲示板のタイトルを確認する判断は [ADR 0005](../adr/0005-use-board-title-check-for-shitaraba-next-thread.md) を参照する。AI投稿は [AIリスナー仕様](./ai-listener.md) が所有し、本機能の名前・E-mail等の設定や次スレッド処理は変更しない。スレッド切替中のAI投稿の扱いは同仕様に従う。

## ユーザーストーリー

1. 配信者として、現行スレッドの指定したレス番号で次スレッドを自動作成したい。配信中に作成時期を監視し続けずに済むからである。
2. 配信者として、次スレッドを作るレス番号と切り替えるレス番号を分けたい。現行スレッドを最後まで利用しながら次スレッドを先に用意できるからである。
3. 配信者として、起動時に作成開始レス番号をすでに超えていても次スレッドを用意したい。配信途中にアプリを起動しても作成忘れを防げるからである。
4. 配信者として、現行スレッドのタイトル番号を自動で一つ増やしたい。毎回同じ編集を行わずに済むからである。
5. 配信者として、タイトルを手動指定したい。数字を使わない題名や独自の命名規則にも対応できるからである。
6. 配信者として、現行スレッドの1レス目を次スレッドの本文へ再利用したい。案内文を作り直さずに済むからである。
7. 配信者として、本文を手動指定したい。次スレッドだけ案内内容を変えたい場合にも対応できるからである。
8. 配信者として、作成前にタイトルと本文を確認し、必要なら閾値より前でも作成したい。配信の進行に合わせて安全に準備できるからである。
9. 配信者として、作成済みの次スレッドURLをコピーまたはブラウザで開きたい。視聴者への案内と内容確認を行えるからである。
10. 配信者として、任意で現行スレッドへ次スレッドURLを案内したい。閲覧者が移動先を見失わずに済むからである。
11. 配信者として、次スレッドを作成できたことを音声で知りたい。管理画面を見続けなくても成功を把握できるからである。
12. 配信者として、次スレッドへ自動で接続先が切り替わったことを音声で知りたい。移動を見落とさず配信を継続できるからである。
13. 配信者として、再起動後も掲示板上の同名タイトルを確認してから次スレッドを作成してほしい。ローカル履歴の不整合と重複作成を避けられるからである。
14. 配信者として、作成できたか分からない場合に自動再試行してほしくない。重複スレッドを防げるからである。
15. 配信者として、作成に失敗してもコメント取得と他の配信支援機能を継続したい。一つの外部書き込み障害で配信全体を止めずに済むからである。
16. 配信者として、掲示板管理メニューで削除した次スレッドを過去の作成済みと表示してほしくない。現在の掲示板を正として再判定できるからである。
17. 配信者として、自動作成を使わず必要な時だけ「今すぐ作成」で次スレッドを用意したい。意図しない自動送信を避けながら作成支援を利用できるからである。

## 具体的な挙動

### 対象と有効化

- 本機能は、掲示板接続枠にしたらばまたはjpnknの有効な現行スレッドURLが設定されている場合だけ利用できる。
- 次スレッド自動作成の既定はオフとする。オンへ変更した時点から、初回履歴と新着の両方を用いて作成条件を評価する。
- 「今すぐ作成」は自動作成のオン・オフから独立し、有効な現行スレッドと作成予定内容がある場合に利用できる。作成開始レス番号へ到達する前でも実行できる。
- 自動作成のオン・オフ、レス番号、タイトル、本文、URL案内、投稿者欄の変更だけでは、掲示板のコメント取得を停止または再接続しない。
- 一つの現行スレッドに対して、作成済みの次スレッドは一つだけとする。
- 一つのコメントソースに対する接続可能数は [コメント取得仕様](./comment-acquisition.md) に従い、現行スレッドと次スレッドを同時にコメント取得しない。

### レス番号の監視

- 作成と切替の判定対象は、掲示板が投稿へ付与したレス番号だけとする。
- 初回履歴と新着の取得結果に含まれる有効なレス番号の最大値を、現行スレッドの最大レス番号として保持する。本文が空または共通コメントへ変換できない行でも、有効なレス番号は判定へ使用する。
- 最大レス番号が作成開始レス番号以上になり、現行スレッドの次スレッド一時状態で自動作成をまだ試行していなければ、自動作成を開始する。
- レス番号が作成開始レス番号と一致せず飛び越えた場合も、以上になった最初の評価で作成する。
- アプリ起動時、再接続時、本機能をオンへ変更した時、または作成開始レス番号を現在の最大レス番号以下へ変更した時も、同じ条件で直ちに評価する。
- 作成開始までの残りレス数は `max(0, 作成開始レス番号 - 最大レス番号)` とする。最大レス番号を取得できない場合は未確定と表示する。
- 自動作成の試行は、成功、失敗、結果不明のいずれでもその次スレッド一時状態に対して1回とし、設定変更だけで自動再試行しない。
- 「今すぐ作成」による明示的な手動試行は回数制限を設けないが、手動試行後に自動作成を開始しない。
- 現行スレッドURLを別のURLへ変更した場合は次スレッド一時状態を破棄する。後から元のURLへ戻した場合も新しい一時状態として掲示板を再確認する。同じURLの通信再接続では破棄しない。
- 切替後の初回取得で作成開始番号へ到達していても、旧スレッドのURL案内等の終了待ちで作成判定を失わない。旧処理との排他が解除された時点で新しい現行スレッドの条件を再評価し、同じ一時状態での自動再試行は行わない。

### 同名タイトルの確認

- 自動作成と「今すぐ作成」のどちらも、作成要求を送る直前に、同じ掲示板で現在公開中のスレッド一覧を取得する。
- 各タイトルを復号して前後の空白を除き、作成予定タイトルと大文字・小文字、全角・半角を区別して完全一致するスレッドを候補とする。現行スレッド自身は除外する。
- 候補が0件なら作成要求を送る。1件なら新規作成せずそのURLを次スレッドとして採用する。2件以上なら `uncertain` とし、配信者にURLの確認を求める。
- 一覧の取得、復号、または解析に失敗した場合は `failed` とし、作成要求を送らない。
- 作成要求の送信後に成功URLを確認できない場合は、同名タイトルを再確認する。1件なら成功、0件または2件以上なら `uncertain` とする。
- 掲示板管理メニューで行われた外部削除は定期監視しない。アプリ再起動、現行スレッドURLの変更、または「今すぐ作成」の実行時に再確認する。
- アプリ再起動または現行スレッドURL変更時の受動的な再確認で候補が1件なら `created` として採用するが、新しい作成操作ではないためURL案内と成功読み上げは再実行しない。

### 作成予定内容

- タイトルと本文は、それぞれ独立して `auto` または `manual` のモードを持つ。既定は両方とも `auto` とする。
- `manual` のタイトルと本文は設定へ永続化し、次スレッドへ切り替えた後も同じ値を再利用する。
- 現行スレッドURLの変更時と作成要求の直前に、現行スレッドのタイトルと1レス目を改めて取得し、自動モードの作成予定内容を更新する。
- タイトルまたは本文を生成できない場合は `inputRequired` とし、自動送信を行わない。
- 一度 `inputRequired` になった場合、設定修正だけでは作成を再開しない。配信者が作成予定内容を確認し、「今すぐ作成」を選んだ場合だけ送信する。
- 管理画面のプレビューへタイトルと本文を表示する。これらはループバック管理面だけに含め、スマホコメント画面へ公開しない。
- 作成要求を送信中または作成済みの間は、その作成試行のタイトル・本文を確認できる表示として保持する。その間に保存した手動値・モードは次回用の設定とし、現在の作成内容を上書きしない。結果不明から作成済みURLを登録した場合も、アプリ内で作成試行した内容を保持する。

### タイトルの自動生成

- 現行スレッドのタイトル内で最後に現れる連続した数字列を対象とし、十進数として1を加える。
- 半角数字だけの数字列は半角、全角数字だけの数字列は全角で出力する。元の桁数を最小幅として先頭ゼロを維持し、増分後に桁数が増える場合は必要な桁まで広げる。
- 例として、「配信2026 Part 009」は「配信2026 Part 010」、「配信０９」は「配信１０」、「配信99」は「配信100」とする。
- 半角数字と全角数字が同じ連続数字列に混在する場合、数字列がない場合、タイトルが空の場合、または生成結果が空の場合は自動生成できないものとする。
- `manual` では入力値をそのままタイトルへ使用する。空白だけの値は作成に使用しない。

### 本文の自動生成

- 自動本文は、共通コメントや初回履歴に残っている内容へ依存せず、現行スレッドの1レス目を明示的に取得して生成する。
- 掲示板の文字コードを復号し、HTML要素を実行または再送信可能な形で残さない。改行要素を改行へ変換し、文字参照を復元して、画面上で読めるプレーンテキストを使用する。
- 表示されているURL、レスアンカー、記号、内部改行を維持する。改行コードはLFへ統一し、先頭と末尾の空白行を取り除く。
- 非表示のリンク先、スクリプト、スタイル、埋め込み要素を本文へ追加しない。
- 1レス目を取得できない、復号できない、または変換後の本文が空の場合は自動生成できないものとする。
- `manual` では入力値をそのまま本文へ使用する。空白だけの値は作成に使用しない。

### 作成状態

次スレッド作成は次のいずれか一つの状態を持つ。

| 状態 | 意味 |
| --- | --- |
| `disabled` | 有効な現行スレッドがなく、自動・手動のどちらでも作成できない |
| `manualReady` | 自動作成はオフだが、「今すぐ作成」を利用できる |
| `monitoring` | レス番号を監視し、作成条件を待っている |
| `inputRequired` | 作成予定内容を生成できない、または配信者の確認が必要 |
| `creating` | 掲示板へ作成要求を送信して結果を確認している |
| `created` | 新規作成または同名タイトル確認で次スレッドを確定し、正規化したURLを保持している |
| `uncertain` | 要求送信後に、作成できたか確認できない |
| `browserRequired` | 掲示板から認証を要求され、ブラウザでの作成と作成済みURLの登録が必要 |
| `failed` | 送信前の準備または明確な外部エラーで作成できず、自動再試行を止めている |

- 状態には、状態名、最大レス番号、残りレス数、作成予定タイトル、作成予定本文、次スレッドURL、利用者向けメッセージ、最終更新時刻を含める。
- 自動作成と「今すぐ作成」は同じ状態遷移と外部送信処理を使用し、同時に二つの要求を開始しない。
- 自動作成をオフへ変更しても、すでに送信中の作成処理は `creating` のまま結果を待つ。オフ設定を手動作成可能の状態と混同せず、完了までは新しい作成操作を受け付けない。
- 設定保存中に自動作成が始まった場合も、設定反映のための遅い内容取得やその失敗で、作成試行の内容・結果・確定済みURLを上書きしない。
- 作成状態と次スレッドURLは次スレッド一時状態として配信セッション中だけ保持し、設定ファイルへ永続化しない。
- 送信前に失敗した場合、または掲示板が作成拒否を明確に返した場合は `failed` とし、自動再試行しない。設定または作成予定内容を確認後、「今すぐ作成」で再試行できる。
- 要求送信後のタイムアウト、接続断、解析不能な成功応答は `uncertain` とし、自動再試行しない。

### 結果不明の解決

- `uncertain` では、自動作成、「今すぐ作成」、接続先の自動切替を停止する。
- 配信者は、掲示板をブラウザで確認し、「作成済みURLを登録」または「未作成を確認」のいずれかを選ぶ。
- 作成済みURLは、現行スレッドと同じ掲示板に属し、異なるスレッドIDを持つ正規のHTTPSスレッドURLだけを受理する。受理後は通常の `created` と同じ扱いにする。
- 「未作成を確認」では `inputRequired` とし、配信者が「今すぐ作成」を選べるようにする。確認操作だけで自動送信を再開しない。

### 作成成功と一時状態

- 掲示板の応答または遷移先から、現行スレッドと同じ掲示板に属する新しいスレッドIDと正規のHTTPS URLを確認できた場合、または同名タイトル確認で候補を1件に確定できた場合だけ成功とする。
- 成功時は次スレッドURLを次スレッド一時状態へ保持して `created` を通知する。
- 作成成功後にURL案内、読み上げ、接続先切替が失敗しても、一時状態の作成成功と次スレッドURLを取り消さない。

### 接続先の自動切替

- 次スレッドが `created` で、現行スレッドの最大レス番号が切替レス番号以上になった場合、一時状態の次スレッドURLへ掲示板接続先を変更する。
- 作成済みの状態で切替レス番号を取得済み最大レス番号以下へ引き下げた場合も、新しいレスの到着を待たず切替条件を評価する。
- 次スレッド作成時点ですでに切替レス番号以上の場合は、成功確定後に直ちに切り替える。
- 前の切替処理中に、新しい現行スレッドの初回取得が切替番号へ到達した場合も、前の切替完了後に条件を再評価する。失敗した同じ接続先への切替を、完了だけを理由に自動再試行しない。
- 次スレッドを作成できていない場合は、切替レス番号へ到達しても現行スレッドの取得を継続し、切替不能の理由を管理画面へ表示する。
- 切替では、掲示板の取得だけを停止し、新しい接続先へ再接続する。YouTube Live、Twitch、画面、音声など他の機能を停止しない。
- 接続先の変更と再接続に成功した場合は、「次スレに移動しました」をシステム案内として読み上げる。切替に失敗した場合は読み上げない。
- 切替後のコメント識別と重複排除は [コメント取得仕様](./comment-acquisition.md) に従い、現行スレッドと次スレッドを区別する。
- 切替後の最初の取得結果は [コメント取得仕様](./comment-acquisition.md) に従う初回履歴として扱う。

### 現行スレッドへのURL案内

- 「現行スレッドにURLを投稿」がオンの場合、成功を確定してから、したらばでは5秒、jpnknでは30秒待ち、切替前の現行スレッドへ案内を1回送信する。既定はオフとする。jpnknの待機は作成直後の連投制限に余裕を持たせるためで、全板・送信元での受理を保証する秒数ではない。
- URL案内の待機中も、作成成功の読み上げと、切替レス番号へ到達済みの場合の接続先切替を待たせない。管理画面の案内説明は現行スレッドのサービスに対応する待機秒数を表示する。
- 案内文テンプレートは `{url}` をちょうど1回含める。既定値は次のとおりとする。

  ```text
  次スレッドはこちらです。
  {url}
  ```

- 送信時に `{url}` を正規化した次スレッドURLへ置き換え、その後に掲示板書き込み境界のURL変換を適用する。ほかのプレースホルダーは解釈しない。
- 投稿者名とE-mailは次スレッド作成と共通の任意設定を使用する。既定は両方とも空とする。
- アプリで作成を試行した場合、その試行に使った投稿者名・E-mailを対応するURL案内にも使う。送信中に設定を編集しても別の投稿者情報へ置き換えない。作成成功時に案内するかどうかの設定評価は維持する。
- トリップとして解釈される `#` を投稿者名へ含む値は保存しない。E-mailは `#` を含めることができ、メールアドレス形式に限定せず、掲示板で通常使われる値をプレーンテキストとして扱う。
- 案内投稿の明確な失敗または結果不明を管理画面へ表示するが、次スレッドの作成成功、成功読み上げ、接続先切替を取り消さない。
- 案内投稿も送信後の結果不明時に自動再試行しない。

### システム案内の読み上げ

- 次スレッド作成成功時にコメント読み上げがオンの場合、「新しいスレを用意しました」をシステム案内として通常の読み上げ待ち順序へ1回追加する。
- 接続先の自動切替成功時にコメント読み上げがオンの場合、「次スレに移動しました」を別のシステム案内として通常の読み上げ待ち順序へ1回追加する。
- システム案内は現在のVOICEVOX話者と音声設定を使用する。PC読み上げ、有効な「スマホでコメントを聞く」、PC音声に応じた口パクの対象とする。
- システム案内は共通コメントではなく、コメント一覧、OBSコメントビューへ追加しない。コメントソース名、投稿者名、本文文字数制限を適用しない。
- コメント読み上げがオフの場合は読み上げず、後からオンにしても遅れて追加しない。
- コメント読み上げと「スマホでコメントを聞く」の待ちキュー上限、破棄、再生順、障害復旧は各機能の既存仕様に従う。
- 音声合成、PC再生、スマホ変換、口パクの失敗で、次スレッド一時状態、URL案内、接続先切替を変更しない。

### 管理画面

2026-10-26、レス番号の条件は「作成開始の番号は、切替の番号以下にしてください」と案内する。作成内容・残り件数を取得できない場合は、現在のスレッド接続やタイトル・本文の確認へ案内する。

2026-10-20、配信者が比較見本「設定と確認を並べる」を採用した。同日の追加見直しで、状態欄は「2行にまとめる」を採用した。本節は編集画面の配置と操作導線を所有する。設定項目、作成・案内・切替・復旧の条件は本仕様の各節を維持する。

- 上部は[設定編集画面の共通レイアウト](./management-screen.md#設定編集画面の共通レイアウト)を使用し、説明枠は「次スレッドの作成と、接続先の切替を設定します。」の1文とする。
- 本文先頭に現行スレッドと稼働状態を全幅で置き、その下に「作成の設定」と「作成予定」を並べる。画面幅が900px以下の場合は、稼働状態、設定、作成予定の順に1列へ戻す。タブや手順ごとの分割は行わない。
- 左の「作成の設定」には、自動作成、レス番号、タイトル、本文、「投稿者名・E-mail」、「作成後の案内」を順に置く。右の「作成予定」には、予定タイトル・本文、今すぐ作成、状態説明、次スレッドURLと操作、復旧手順をまとめる。
- 自動作成は共通スリムスイッチのオン／オフで設定を示し、同じ意味の説明を繰り返さない。「作成するレス番号」「切り替えるレス番号」の入力と単位「番」を並べ、範囲と前後関係を近くに示す。番号入力は狭い画面では読み順を保って1列にする。自動作成の設定と実際の作成状態は区別し、「今すぐ作成」の近くに「自動作成がオフでも使えます。」と表示する。
- 稼働状態には保存済みの現行スレッドURL、最大レス番号、作成開始までの残りレス数、実際の作成状態を表示する。自動作成がオフの場合の残りレス数欄は「自動作成はオフ」とし、稼働中との誤認を避ける。未取得の値は未確定とし、見本の架空タイトルを表示しない。長いURL・状態名の更新で高さが変わらない領域を確保し、全文をスクロールで確認できるようにする。
- 状態欄は、十分な幅では上段に小さな状態表示、最大レス番号のラベルと値、作成開始までのラベルと値を左から横並びにし、下段に「現行スレッド」とURLを横並びにする。上下の余白は14px、段の間隔は10pxを基準とし、数値・状態・URLへ一律の複数行固定高を割り当てない。既知の状態名・未確定・数値・自動作成オフの切替で段数や下の設定位置が動かない幅を確保する。狭い幅では項目ごとに折り返し、480px以下では上段の項目を縦に並べ、URLもラベルの下に置く。URLは広い画面では1行、480px以下では2行分の高さとし、長い場合は枠内で折り返して縦スクロールで全文を確認できるようにする。横スクロールバーで文字の表示高を奪わない。
- タイトルと本文は独立した選択欄にし、自動の選択肢をそれぞれ「末尾の番号を +1」「1レス目を引き継ぐ」、手動を「手動で入力」とする。選択欄と同じ意味の説明は省く。手動選択時だけ対象の入力欄を表示し、空欄では作成できないことと次回も同じ値を使うことを短く示す。「投稿者名・E-mail」は任意・作成と案内に共通と分かる閉じた詳細に置き、既定名・sage・#の制約は対象欄の近くで確認できるようにする。
- 「作成後の案内」は初期表示で開いた詳細とし、利用者が開閉できる。「現行スレッドにURLを投稿」の共通スリムスイッチを置き、オンの場合だけ案内文と、現行サービスに対応する投稿待機秒数を表示する。保存方式・既定値・入力制約は既存自動保存を維持する。不正入力は編集画面内に保持し、有効な値だけを保存する。
- 作成予定タイトルと本文は実際の取得結果を常時表示する。この機能の送信内容確認として、一般の任意プレビューとは区別する。長い内容や内容の更新で操作位置が動かない寸法を確保し、内部スクロールで全文を読めるようにする。次スレッド設定や接続先の保存・反映待ちにはそれを伝え、古い作成予定で手動実行できないようにする。
- 作成予定の後に「今すぐ作成」、状態の説明、次スレッドURL、URLコピー・ブラウザ表示を置く。URLと操作の領域は作成前から確保し、利用できない操作は理由と無効状態を示す。操作中の二重要求を防ぎ、非同期処理中・完了でボタンの寸法やフォーカスを変えない。
- 「ブラウザで作成・結果を確認」を明示的に開くと作成済みURL入力、登録、未作成確認、現行掲示板を開く操作を利用できる。認証時・結果不明時の確認方法、認証後の登録では案内を省略すること、未作成確認だけでは再送しないことは詳細の中で短く伝える。状態更新で自動展開しない。結果不明・入力が必要・失敗・案内失敗の説明は要確認から編集先へ移動でき、結果不明・ブラウザ作成が必要な場合には復旧領域を開く方法を伝える。失敗時にも現行掲示板を開ける。
- 成功通知は[共通トースト](./management-screen.md#共通トースト)、保存失敗・操作失敗・入力不正・処理中表示は[通知で操作位置を動かさない共通ルール](./management-screen.md#通知で操作位置を動かさない共通ルール)に従う。画面を移動しても入力と開いている詳細を保持し、比較バー・架空状態切替・内部状態表示は本体へ含めない。
- 有効な入力が設定へ反映された後は、古い編集バッファを再利用しない。他の管理画面等から同じ設定を変更しても、過去の入力を復活させない。現行スレッドが変わった場合は旧スレッドの操作失敗を破棄し、旧URLへ戻った後に遅れて届く失敗も表示しない。
- 外部の設定変更でフォーカス中の手動タイトル・手動本文・案内文が非表示になった場合は、それぞれタイトル選択・本文選択・URL投稿スイッチへフォーカスを戻す。別の操作へ移動済みの場合は移動しない。

#### 操作条件

- 掲示板設定内に、次スレッド自動作成のオン・オフ、作成開始レス番号、切替レス番号、タイトルと本文の各モード、手動値、URL案内、案内テンプレート、投稿者名、E-mailを表示する。
- 状態領域に、現在の状態、最大レス番号、作成開始までの残りレス数、作成予定タイトル、作成予定本文、次スレッドURL、警告またはエラーを表示する。
- 次スレッドURLがある場合は「URLをコピー」と「ブラウザで開く」を提供する。ブラウザで開く対象は検証済みの `https://jbbs.shitaraba.net/` または `https://bbs.jpnkn.com/` の対象板・スレッドURLだけとする。
- 自動作成のオン・オフにかかわらず、有効な現行スレッドと作成予定内容がある場合は「今すぐ作成」を提供する。`creating` 中、`uncertain` 中、`browserRequired` 中、または同じ現行スレッドが作成済みの場合は無効にする。
- `uncertain` では、作成済みURL入力、「作成済みURLを登録」、「未作成を確認」、現行掲示板をブラウザで開く操作を提供する。
- `browserRequired` では、作成済みURL入力、「作成済みURLを登録」、現行掲示板をブラウザで開く操作を提供し、「未作成を確認」は提供しない。登録URLの条件と登録後の案内省略は[ブラウザ復旧](#jpnkn書き込みとブラウザ復旧)に従う。
- 管理画面の成功・失敗通知と自動保存は [ローカルアプリケーション仕様](./local-application.md) に従う。

### 掲示板書き込み境界

- 書き込み処理はコメント取得アダプターと分離した、交換可能な掲示板専用アダプターで行う。一方の障害を他方の状態として扱わない。
- 作成または案内の直前に掲示板の公開フォームを取得し、フォームが示す送信先、文字コード、必要な公開項目、時刻トークンを使用する。固定した非公開インターフェースや資格情報に依存しない。
- したらばの公開フォームへ送信する各テキスト項目に `http://` または `https://` で始まるURLが含まれる場合は、大文字・小文字を問わずスキーム先頭の `h` だけを除き、`ttp://` または `ttps://` として送信する。
- URL変換は外部送信の直前だけに行う。設定値、作成予定内容のプレビュー、作成済みの次スレッドURL、URLコピー、ブラウザ表示には変換を適用しない。
- 現行スレッドから得たカテゴリと掲示板ID、作成に必要なタイトル、本文、投稿者名、E-mail、および公開フォームが要求する最小項目だけを掲示板へ送信する。
- 投稿規制、NGワード、文字数、連続作成、外部投稿禁止、参照元、ホストなど掲示板固有の制限は掲示板の判定に従い、応答本文をそのまま表示せず安全な日本語エラーへ変換する。
- CAPTCHA、トリップ、ハンドルパスワード、掲示板管理者の資格情報を保存または自動処理しない。必要と判断した場合はアプリ内送信を止め、掲示板をブラウザで開く導線を表示する。
- 公開フォームは予告なく変わり得るため、解析不能を成功と推測しない。

## 設定

| 設定 | 範囲または候補 | 既定値 |
| --- | --- | --- |
| 次スレッド自動作成 | オン / オフ | オフ |
| 作成開始レス番号 | 1～10000の整数 | 980 |
| 切替レス番号 | 1～10000の整数 | 1000 |
| タイトルモード | `auto` / `manual` | `auto` |
| 手動タイトル | 文字列 | 空 |
| 本文モード | `auto` / `manual` | `auto` |
| 手動本文 | 文字列 | 空 |
| 現行スレッドにURLを投稿 | オン / オフ | オフ |
| 案内文テンプレート | `{url}` をちょうど1回含む文字列 | 「次スレッドはこちらです。\n{url}」 |
| 投稿者名 | `#` を含まない文字列 | 空 |
| E-mail | 文字列 | 空 |

- 編集可能な設定は現在の設定スキーマの `sources.shitaraba.nextThread` に保存する。
- 作成開始レス番号は切替レス番号以下とする。同じ値の場合は次スレッド作成を完了してから接続先を切り替える。
- 範囲外、整数でない値、作成開始レス番号が切替レス番号を超える組み合わせ、不正な案内文テンプレート、`#` を含む投稿者名は保存せず、直前の有効値を維持する。
- 手動タイトルと手動本文は空でも保存できるが、対応するモードが `manual` の間は作成できず `inputRequired` とする。
- 作成試行の有無、成功、失敗、結果不明、次スレッドURL、案内結果、最大レス番号、残りレス数、自動生成したタイトルと本文は永続化しない。
- 対応終了設定にあるinternal.shitarabaNextThreadRecordsは利用しない。原本の退避と初期化は[保存と対応版](./local-application.md#compatibility-baseline)に従い、一時的な作成記録を現行設定へ保存しない。
- 設定スキーマと移行方法は [ローカルアプリケーション仕様](./local-application.md) に従う。

## エラー処理

- 現行スレッドURLが不正または未設定の場合は `disabled` とし、外部通信を行わない。
- 自動タイトルまたは自動本文を生成できない場合は `inputRequired` とし、手動モードへの変更または再取得方法を日本語で案内する。
- フォーム取得または送信前検証に失敗した場合は `failed` とし、コメント取得を継続する。
- 掲示板が明確に拒否した場合は、原因を分類できる範囲で投稿規制、入力内容、外部投稿、連続作成などの確認方法を表示する。外部応答本文や内部例外を直接表示しない。
- 送信後のタイムアウト、接続断、成功URLを検証できない応答は同名タイトルを再確認し、一意に確定できなければ `uncertain` とする。
- 作成または案内失敗のエラーにタイトル、本文、投稿者名、E-mail、次スレッドURL、時刻トークン、外部応答本文を含めない。
- タイトル、本文、投稿者名、E-mail、次スレッドURL、外部応答本文をテレメトリー、分析、クラッシュレポート、診断ログへ記録しない。
- 一つの失敗でYouTube Live、Twitch、掲示板のコメント取得、コメント一覧、OBS表示、キャラクター表示、読み上げ、ローカルバックエンドを停止しない。

## テスト条件

テストは、偽の掲示板取得アダプターと書き込みアダプターをアプリケーション状態の入口へ接続し、設定移行、外部要求、同名タイトル候補、次スレッド一時状態、接続先、音声出力を観察する。実際の掲示板、画面内部構造、固定したフォームHTMLには依存しない。

1. 自動作成が既定オフで、オンへ変更するまではレス番号による作成要求を送らず、明示的な「今すぐ作成」だけを受け付ける。
2. 初回履歴と新着の最大レス番号が作成開始レス番号未満、同値、超過、飛び越しの場合に規則どおり一度だけ作成する。
3. 起動時、再接続時、機能をオンへ変更した時、作成開始レス番号を引き下げた時に到達済み条件を評価する。
4. コメントへ変換できない行の有効なレス番号も最大レス番号へ反映し、最大レス番号だけで作成条件を判定する。
5. 最後の数字列だけを増やし、複数数字、半角、全角、ゼロ埋め、桁増加を規則どおり処理する。
6. 数字なし、空タイトル、半角・全角混在数字列で `inputRequired` となり、自動送信しない。
7. 最新100レスに1レス目が含まれない場合も1レス目を別途取得し、HTML、文字参照、改行、表示URL、レスアンカーを規則どおりプレーンテキストへ変換する。
8. 1レス目を取得または変換できない場合は `inputRequired` となり、修正後も「今すぐ作成」まで送信しない。
9. 自動と手動の各モードを独立して選択でき、手動値を次スレッド切替後も再利用する。
10. 作成開始レス番号、切替レス番号、案内文テンプレート、投稿者名、E-mailの不正設定を拒否し、E-mailの `#` は有効な文字として保存できる。
11. 次スレッド設定だけを変更しても、掲示板のコメント取得を停止または再接続しない。
12. 自動作成と「今すぐ作成」が同じ要求を使用し、同時操作でも一つだけ送信する。
13. 自動作成が成功、失敗、結果不明のいずれでも1回で停止し、設定変更や同じURLの再接続で自動再試行しない。手動作成だけを再実行できる。
14. 作成前の同名タイトル確認で0件、1件、2件以上、取得失敗を規則どおり送信、既存URL採用、結果不明、失敗へ分類する。
15. 結果不明で同じ掲示板の別スレッドURLだけを登録でき、「未作成を確認」後も手動操作まで再送しない。
16. 次スレッド一時状態を永続化せず、アプリ再起動や別URLからの再訪時に掲示板の同名タイトルを再確認する。
17. 案内がオンの場合だけ、作成成功からしたらばでは5秒、jpnknでは30秒待って既定文または設定テンプレートを現行スレッドへ一度送り、失敗または結果不明でも作成成功と切替を維持する。待機中の読み上げと到達済みの切替は待たせず、案内失敗で自動再送しない。
18. 切替レス番号未満では現行スレッドを継続し、到達後は作成済み次スレッドへ掲示板だけを切り替える。
19. 作成時点で切替レス番号以上の場合は成功後に直ちに切り替え、未作成の場合は現行スレッドを継続する。
20. 切替後のコメント識別と初回履歴がコメント取得仕様の契約どおりに適用される。
21. コメント読み上げがオンの場合だけ作成成功文と自動切替成功文を通常の順序へそれぞれ1回追加し、PC、利用中のスマホ、口パクへ流す。オフの場合は後から読み直さず、切替失敗時は自動切替成功文を追加しない。
22. システム案内を共通コメント、コメント一覧、OBSコメントビューへ追加しない。
23. 作成、案内投稿、音声合成、PC再生、スマホ変換、口パクの各失敗を分離し、後続処理と他機能を継続する。
24. 手動作成と結果不明解決の操作がループバックOrigin、正しいHost、操作トークンを要求し、スマホ向け公開面から利用できない。
25. 状態、REST、WebSocket、LAN応答、診断ログへ、許可されていないタイトル、本文、投稿者名、E-mail、次スレッドURL、外部応答本文が漏れない。
26. 管理画面に残りレス数、プレビュー、今すぐ作成、URLコピー、ブラウザ表示、結果不明解決が状態に応じて表示される。
27. 実サービス確認は、配信者が明示的に許可した専用テスト掲示板だけで行い、一般掲示板へ試験投稿しない。
28. 新規設定では、設定表に定義したすべての既定値が適用される。
29. 有効な投稿者名とE-mailを設定した場合、次スレッド作成と有効なURL案内投稿の両方へ同じ値を渡す。
30. したらばの次スレッド作成とURL案内で外部送信する全テキスト項目の `http://` と `https://` を `ttp://` と `ttps://` へ変換し、設定、プレビュー、作成済みURLは正規のスキームのまま維持する。
31. 現行の編集可能な設定を保持し、旧保存の退避・初期化は[保存と対応版](./local-application.md#compatibility-baseline)に従う。対応終了したinternal.shitarabaNextThreadRecordsを利用・再保存しない。
32. アプリ再起動または現行スレッドURL変更時に同名タイトルを再確認し、既存URLを採用してもURL案内と成功読み上げを再実行しない。
33. 次スレッド自動作成がオフでも、有効な作成予定内容があれば「今すぐ作成」で同名タイトル確認と手動作成を実行できる。手動作成を試行した現行スレッドでは、成否にかかわらず、その後に自動作成を実行しない。

## 対象外事項

したらば・jpnkn以外での次スレッドまたは配信枠作成、本機能での既存スレッドへの一般コメント投稿、削除、モデレーション、複数の次スレッド作成、現行スレッドと次スレッドの同時取得、掲示板の最大レス数の自動検出、トリップ、ハンドルパスワード、CAPTCHA、掲示板管理者認証、投稿規制の回避、作成済みスレッドの自動削除は対象外である。別機能として採用した投稿は [AIリスナー仕様](./ai-listener.md)、全体の一覧は [OUT_OF_SCOPE.md](../../OUT_OF_SCOPE.md) を参照する。

## 外部サービスに関する前提

- したらばの公開掲示板はEUC-JPのフォームを使用し、タイトル、名前、E-mail、本文、公開された時刻トークンを送信する。実装可否の確認例は [公開フォーム例](https://jbbs.shitaraba.net/netgame/345/) を参照する。
- 掲示板固有の投稿制限と主なエラーは [したらば公式ヘルプ](https://rentalbbs.shitaraba.com/rule/help/) を参照する。
- 公開フォームの送信先、項目、文字コード、応答形式は外部仕様であり、利用者向けの固定契約とはしない。変更時は掲示板書き込みアダプターを更新し、本仕様の状態と安全性を維持する。

### jpnkn書き込みとブラウザ復旧

- 共通制御をjpnknにも適用し、板上限の自動検出/`!tmpl`専用モードは追加しない。間隔/閾値/タイトル/本文/投稿者設定を共用する。
- 作成・案内・AI投稿の送信直前に公開フォームを取得する。`bbs.jpnkn.com`の`/test/bbs.cgi`、対象`bbs`、返信時の`key`、必要公開項目とCP932を検証し、作成に`key`を混ぜない。フォーム不明・不正action・解析不能はPOSTしない。
- CP932生バイトでform-urlencoded化し、タイトル1～128/本文1～4096/名前・メール各128文字以下を送信前検証する。変換不能文字を黙って置換せず内容修正を案内する。jpnknにはURLの`h`除去を適用しない。
- POSTは同名確認後に1回。HTTP200や成功見出しだけで確定せず、検証済み同一板の別スレッドURLまたは一致タイトル1件で確定する。送信後の未知応答/タイムアウトは同名再確認し、一意に確定できなければ`uncertain`として自動再送しない。
- 明確な認証要求は`browserRequired`（ブラウザ作成が必要）とし、自動/今すぐ作成を停止する。設定変更・自動OFF・同URL再接続で解除しない。トークン保存/入力やCAPTCHA処理は追加せず、検証済み板URLをブラウザで開く導線と作成済みURL登録を提供する。
- 登録は同じ実サービス・同じ板・別スレッドの正規HTTPS URLだけ。`browserRequired`では登録だけを許可し、「未作成を確認」は`uncertain`限定。
- 認証状態からの登録では案内POSTを省略し、案内ONなら「認証要求のためアプリからの案内は省略しました。必要ならブラウザで案内してください」と表示する。案内成功とは扱わず共有設定を変更しない。成功通知/読み上げ/閾値切替は継承し、`uncertain`からの登録は従来の案内動作を維持する。
- 切替待機中の手動停止を後続再接続で打ち消さず、AI取得所有権の変更と切替を直列化する。旧接続の結果を新URLへ反映しない。
- 受け入れではフォーム異常/文字コード/同名0,1,複数/認証状態保持/登録URL検証/案内省略/成功通知/閾値切替/手動停止を検証する。実投稿は明示許可の対象・内容・件数に限る。
