# OBS操作仕様

[スマホからのOBS映像確認](./obs-program-preview.md)は本書のOBS接続・Android操作許可・資格を共用する。撮影は読取だけで、配信開始・終了や操作確認を要求しない。

[OBSソース登録・表示テスト](./obs-source-registration.md)は本書の接続をPC管理画面から共用し、配信確認・実行と共通の占有を使う。取得・解放でbusyとリビジョンを更新する。Androidへは既存のbusyのみを通知し、ソース登録・表示テストの結果・権限を追加しない。AIの読取専用窓口は維持する。

2026-10-04に[PC・スマホ直接接続](./smartphone-direct-connection.md)からのAndroid操作を追加採用した。追加は**実装済み・実機検証未完了**。PCからOBSへのループバック接続、操作許可・確認・失効・重複排除は維持する。

v0.5.0で追加するAIリスナーによるOBS配信状態の利用は [AIリスナー仕様](./ai-listener.md) が所有する。AIリスナーの開始・停止をOBS配信へ連動させる機能であり、本書のOBS配信開始・終了要求をAIに生成させる変更ではない。接続喪失・再接続等の連動条件は同仕様に従う。

指定OBSソースの画像取得と表示状態の参照は [AIリスナーの映像入力](./ai-listener.md#映像入力) が所有する。接続・認証は本書の基盤を共用し、AI側には読取専用の取得窓口を設ける。OBS操作の確認・認証や接続停止の扱いは変更しない。

## 問題と解決策

v0.4.0で、配信者音声認識とAndroidクライアントからOBS配信を開始・終了する。きゃすメイトと同じWindows 11 PCで動くOBS 1台を対象とし、PCがobs-websocket v5への接続と共通の操作処理を所有する。AndroidはPC経由で操作する。

本書はOBS接続、操作、確認、状態、認証、保存、通信契約を所有する。画面配置は [管理画面仕様](./management-screen.md) と [Androidクライアント仕様](./android-mobile-client.md)、登録QRの形式は [スマホ連携仕様](./smartphone-integration.md)、判断理由は [ADR 0012](../adr/0012-adopt-authenticated-obs-control.md) を参照する。

## ユーザーストーリー

1. 配信者として、AndroidでOBS配信を開始・終了したい。PCへ戻らず操作できるからである。
2. 配信者として、音声でも開始・終了を検証したい。音声認識から操作までの動作を確認できるからである。
3. 配信者として、検証後は音声操作だけを無効化したい。Android操作を残しながら発話による操作を防げるからである。
4. 配信者として、実行前に対象操作を確認したい。誤認識や誤タップによる操作を減らせるからである。
5. 配信者として、操作フレーズを変更したい。認識されやすい言い方で検証できるからである。
6. 配信者として、映像送信と同じQRで操作を登録したい。毎回認証情報を入力せずに済むからである。
7. 配信者として、映像送信なしでもLANから操作したい。屋内でもAndroidを操作端末にできるからである。
8. 配信者として、配信状態と操作結果不明を区別したい。通信の成功だけで配信できたと思い込まずに済むからである。
9. 配信者として、対象端末の登録を失効させたい。他端末やOBSへの直接映像送信を止めずに、PCの操作認証を取り消せるからである。
10. 配信者として、連打や通信断の後で操作が繰り返されないでほしい。意図しない配信の開始・終了を避けられるからである。
11. 配信者として、OBS操作が失敗しても他の機能を使いたい。コメント・読み上げ・映像送信を継続できるからである。

## 接続・設定・保存

- OBSの起動、配信先・配信キー設定、WebSocketサーバーと認証の有効化は配信者が事前に行う。きゃすメイトはOBSを起動・終了せず、配信設定を変更しない。
- 接続先は `ws://127.0.0.1:{port}`、ポートは1～65535、既定4455。認証付きobs-websocket v5を使用する。認証なし・非対応版は利用不可として設定手順を案内する。OBSパスワードはAndroidへ渡さない。
- 「OBS連携」「音声によるOBS操作」「AndroidからのOBS操作」は別の設定とし、すべて初期オフで保存する。OBS連携がオフなら両入力を受け付けない。音声操作オフは音声認識本体やAndroid操作を停止しない。
- OBS連携がオンなら起動時に接続する。接続断の再試行は1、2、4、8、16、30秒、以後最大30秒。認証失敗・非対応版では明示的な再試行か設定修正を待つ。配信要求を自動再送しない。
- 設定は版1の専用`obs-control.protected`に保存する。OBSポート・パスワード、操作許可、音声フレーズを保持する。旧Android単独登録は原本を退避してregistration=nullへ置換する。有効経路と端末登録は現行スマホ台帳を正とし、旧経路フラグは独立に編集しない。Electron safeStorageのWindows利用者保護と原子的置換を使い、一般設定JSONへ秘密を追加しない。
- オン・オフは即時保存。音声フレーズはIME確定後の最終入力から500ミリ秒、Android操作許可は変更時に自動保存する。共有待受ポートはスマホ連携仕様に従う。OBSポートとパスワードは一つの入力領域とし、領域外へフォーカスを移した時にまとめて検証・保存する。「この設定を適用」は置かない。
- 共通ナビゲーションのページ移動・戻る操作では接続情報の保存を開始せず、入力を保持する。初回設定の戻る・後で設定する・中断・機能ナビゲーション・詳細設定への移動も同じ扱いとする。接続情報の入力領域から離れた時、または利用者が「OBSの接続設定」を閉じた時に接続情報をまとめて保存する。展開だけでは保存しない。
- 「OBS接続を再試行」は、編集中の接続情報を検証し、その保存成功を待ってから実行する。保存失敗・不正入力・IME変換中・待機中の入力変更で保存できなければ、古い保存値への再試行や成功通知を行わず、入力と理由を保持する。同じボタンから再試行できる。接続・再試行・明示保存・接続設定の折りたたみへフォーカスが移った時は、領域離脱の保存を重ねず、その操作が一度だけ保存する。接続停止と確認取消のために編集中の接続情報を保存しない。
- OBSパスワードは省略時に保持し、明示的な空文字は拒否する。初期準備中はOBS連携オフ・パスワード未設定のまま他の有効な設定を保存できる。OBS連携オンにはパスワードが必要。応答には設定済みかを示す真偽値だけを返す。既存の版1OBS設定は保持し、旧単独登録は退避後に除去する。連携オンなのにパスワードが空の保存は拒否する。
- 初期設定でパスワード入力より先にOBS連携をオンへ操作した場合は、未保存のオン希望を画面に保持する。その後、有効な接続情報を入力して入力領域から離れると、接続情報と未保存の連携設定を一緒に保存し、オン希望ならOBS接続を開始する。オン・オフの再操作を求めない。保存失敗時は入力と希望を保持し、途中でオフへ変更した場合は最新の希望に従う。
- 保存は専用保存ファイル単位で直列化する。旧単独登録の除去とOBS設定の更新を競合させず、保存失敗時は保存済みOBS設定と原本を維持する。現行端末資格の生成・更新・失効はスマホ台帳で管理する。画面には未保存の入力と日本語の理由を残し、同期受信・保存完了で編集中の新しい入力を上書きしない。同値保存は接続や確認待ちに影響しない。
- 操作要求の通信失敗は次の設定保存成功で解消し、接続が接続済みへ復旧した場合も古い操作エラーを残さない。現在の保存エラー・接続エラー・公開警告はそれぞれの実状態に従って表示する。
- OBS接続を切り直すのは連携オン・オフ、OBSポート、パスワードを変更した場合だけ。フレーズ・音声許可・Android許可・公開設定の変更ではOBS接続と配信状態を維持し、Android操作許可の変更は共有接続のOBS購読に反映する。実際の設定変更では既存仕様どおり確認待ちを取り消す。保存のために配信開始・終了要求を送らない。
- 旧版に保存ファイルがなければ全機能オフ。復元不能なら機能を利用不可として再設定を案内し、壊れたファイルを自動上書きしない。
- Androidの機能別資格情報は区別し、[Androidクライアント仕様の登録保存](./android-mobile-client.md#登録の保存形式)で一括保存する。確認待ちと操作結果は永続化しない。

## 共通の状態と操作

- `GetStreamStatus` で初期状態・再接続後の状態を取得し、`StreamStateChanged` で更新する。接続状態は `disabled / connecting / connected / unavailable`、配信状態は `unknown / stopped / starting / streaming / reconnecting / stopping`。OBS出力の再接続を停止と混同しない。
- `StartStream` と `StopStream` を使用し、状態反転要求は使用しない。開始はstopped、終了はstreamingまたはreconnectingで受け付ける。既に目標状態なら `alreadySatisfied` とし要求を送らない。unknown・starting・stoppingでは操作不可。
- 音声とAndroidを通じ、確認待ちまたは実行は同時に1件だけ。他の要求をBUSYで拒否し、キューへ積まない。
- 確認後、要求送信前にOBS状態を再取得する。確認開始時から状態が変わっていれば取り消す。OBS本体での操作との完全な排他は保証できず、OBSの拒否応答も処理する。
- 問い合わせと認証の応答期限は5秒。開始・終了は送信から30秒以内にOBSの目標状態を確認して成功とする。受付応答だけでは成功としない。明示的拒否は失敗、送信後の切断・期限超過は結果不明。送信前の接続失敗では実行しない。
- 結果不明になった要求を再送せず、再接続後に現在のOBS状態を確認する。現在状態から過去の操作成功を断定しない。新しい操作は改めて確認する。配信サイトでの公開成功や映像の表示成功は保証しない。
- 無効化・アプリ終了で未送信の確認を取り消し、該当接続・待受を閉じる。送信済み操作は取り消せず、逆の操作で戻さない。アプリ終了・通信断でOBS配信を自動終了しない。
- OBS操作の障害や停止でコメント、読み上げ、音声認識、映像送信を停止しない。

## 音声操作

- [配信者音声認識仕様](./streamer-speech-recognition.md) の「配信に使う」、OBS連携、音声によるOBS操作がすべてオンの場合だけ新しい確定結果を判定する。プレビュー単独では実行しない。「配信に使う」がオンでプレビューと共有中も、音声操作の対象として扱う。
- 開始指示、終了指示、開始確認、終了確認を各1つ設定する。既定は「きゃすメイト、配信開始」「きゃすメイト、配信終了」「開始を実行」「終了を実行」。
- 設定は各1～100 Unicodeコードポイント。設定値と認識結果へNFKC正規化を行い、Unicodeの空白と句読点（Punctuationカテゴリ）を除去して完全一致で判定する。正規化後空の設定、4項目間の重複を拒否する。読み替え、部分一致、AI推定を行わない。
- 指示受付時に対象操作、確認フレーズ、残り秒数、取消ボタンをPC画面へ表示する。受付から単調時計で10秒未満に、同じ音声認識セッションの別結果ID・後続連番で対応する確認を受けた場合だけ実行する。1発話で指示と確認を兼ねない。
- 無関係な発話、逆の確認、指示の繰り返しは実行も期限延長もしない。10秒到達、取消、設定変更、無効化、音声認識停止・再起動・音声待ち・利用不可、OBS切断、配信状態変更で音声確認を破棄する。音声認識の状態変化だけではAndroid操作の確認を取り消さない。
- 結果ID・セッション内連番で重複と逆順を除外する。過去履歴や、無効化後・停止後の遅延結果を処理しない。有効化以前に取得された発話も対象外とし、認識側との境界に発話取得開始時点の有効期間識別を追加して判定する。
- 受付・確認・取消・結果はPC画面だけに表示し、読み上げを追加しない。既存の認識結果表示を操作判定のために抑止・変更しない。

## Android操作と認証

- 登録先PCは1台、操作端末はAndroid 10以降で固定台数上限を設けない。開始・終了とも前面の確認画面で対象PC・操作・OBS状態を示してから実行する。画面離脱・背景移行・取消で確認を破棄し、再生成や通知から実行しない。
- Android確認の期限はPC側で10秒。OBS切断・配信状態変更・設定変更・登録失効でも無効にする。映像送信の開始・停止とは連動せず、映像送信停止中でも操作できる。
- 端末ごとにOBS操作専用の登録ID、リビジョン、256ビット乱数トークンを生成する。映像用秘密とは分離し、スマホ連携の現行登録応答へ含める。対象端末の削除・再発行はその端末の確認を取り消し、他端末へ影響しない。再発行ではIDを保持し秘密とリビジョンを更新する。単なるオフでは登録を保持する。
- 接続は[認証付き制御プロトコル](./smartphone-transport.md#認証付き制御プロトコル版2)を使う。専用HTTP待受を廃止し、登録と共有するポートをスマホ連携で設定する。
- LANは信頼できるネットワークを前提とし、Bearer認証は暗号化ではないことを設定時に説明する。外部利用はTailscaleまたは[直接接続のPC鍵確認付きWSS](./smartphone-transport.md#direct-secure-transport)を使う。LAN／Tailscaleでは公開ポート転送を要求せず、直接接続の開放・Windows許可はその所有仕様に従う。OBS本体のWebSocketやパスワードを外部へ公開しない。
- 用途別のOBS資格情報で認証する。読取専用面や映像だけの権限からOBS操作を許可しない。境界・失効検証は通信仕様に従う。
- AndroidはQR登録済みのLAN／Tailscale／直接接続を明示選択する。経路間の自動切替・探索・リダイレクト追従を行わない。直接接続内の候補再接続は通信仕様に従う。前面で状態を購読し、変化を即時反映する。接続断で直ちに不明・操作不可とし、背景ではOBS購読と確認を解除する。復帰後は最新状態まで操作できない。再接続で確認・操作を自動再送しない。

## 管理画面

2026-10-26、通常画面は音声・AndroidからOBS配信を操作するための設定であることを明記する。接続情報は領域から離れると保存、発話設定は入力後の自動保存という既存の区別を維持し、説明を各操作付近へ集約する。

Androidの経路と端末別登録は[スマホ連携仕様](./smartphone-integration.md)へ統合する。本画面はOBS接続と各操作許可を所有する。

- 共通見出し・説明枠は[設定編集画面の共通レイアウト](./management-screen.md#設定編集画面の共通レイアウト)を使用し、説明枠は「音声・Androidから、確認付きでOBS配信を操作します。」の1文とする。個別の有効化・接続と確認手順は各操作領域で案内する。
- 2026-10-20、比較見本の1案「ステータス中心」を採用する。従来の3タブを廃止し、上部の状態、操作許可、詳細設定の順に配置する。OBS連携スイッチと実際のOBS接続・配信状態を一つの領域にまとめ、接続と配信の状態を大きく並べる。設定上のオン／オフと実際の状態は区別し、共通スリムスイッチとキーボード操作を使用する。
- 上部の固定領域に確認待ち・残り秒数・確認方法・直近操作・処理中・エラーを表示する。通常は「確認を取り消す」を置き、OBS接続が利用不可で確認待ちがない場合は同じ操作枠を「OBS接続を再試行」にする。実行できない操作はフォーカスを維持して禁止を示す。接続エラーや結果不明は正常な停止状態に置き換えず、結果不明を自動再送しない。
- 状態領域の下に保存状態、その下に「どこから操作する？」と音声・Androidのカードを横並びで置く。狭い幅では音声、Androidの順に縦に並べる。両方の操作許可を常に表示し、OBS連携の保存済み設定がオフなら許可スイッチを操作不可にする。
- 音声カードには10秒以内の別発話による確認と、配信者音声認識の「配信に使う」も必要でプレビューだけでは操作しないことを示す。「フレーズを編集」は初期状態で閉じ、開くと開始・終了別に指示と確認を組にして表示する。開閉しても入力・IME・保存待ち・エラーを破棄せず、開閉そのものではフレーズを保存しない。
- Androidカードは操作許可、実際のAndroid待受状態、映像送信と独立した確認付き操作を表示する。「スマホ連携を開く」から経路選択・端末別登録へ案内し、LANの認証は暗号化ではないことと外部利用の経路を補足する。独立した公開スイッチやQR発行・登録失効操作を置かない。移動だけで有効化や登録は行わない。
- 最下部の「OBSの接続設定」は初期状態で閉じ、閉じた時も保存済みポートとパスワード設定済み／未設定を要約する。開くとポート・パスワード、入力説明と「OBS側の準備方法」を表示する。エラー発生で自動展開しない。上部にも理由を表示し、閉じていても保存失敗を見落とさないようにする。ページ往復で開閉状態と入力を保持する。
- 初回設定のOBS接続段階では操作許可カードを表示せず、接続設定を開いて入力と既存の「接続情報を保存」を表示する。初回設定の移動・進行保存の契約は[初回設定仕様](./initial-setup.md)を維持する。
- 自動保存は固定の小さな状態領域で「保存中…／保存済み／未保存／保存できません」を示し、保存ごとのトーストは出さない。入力エラーは高さを確保した各領域と「要確認」に表示する。処理開始・完了・通知で本文、操作位置、スクロール、フォーカスを動かさない。明示操作の成功は[共通トースト](./management-screen.md#共通トースト)を使用する。
- 2026-10-18、画面末尾の障害分離についての補足案内と、案内削除後に残った空の状態領域を削除する。操作の処理中とエラーは上部の既存の操作状態欄へ表示し、確認待ち・直近操作と併せて確認できるようにする。状態欄の高さは維持し、長文は内部で読めるようにする。

## インターフェース

### PC管理と状態

- `POST /api/obs-control/configure` は設定の部分更新、`POST /api/obs-control/retry` は接続再試行、`POST /api/obs-control/cancel` は確認取消を行う。既存のループバックHost・Origin・操作トークン保護を適用する。端末登録・QR発行経路はスマホ連携仕様が所有する。旧revoke/regenerate APIは移行後には利用不可とする。
- 管理用 `AppSnapshot.obsControl` と `obsControl.stateChanged` は接続・配信状態、秘密を除く設定、パスワード設定済みの真偽値、Android待受準備済みの真偽値、確認待ち、直近操作結果、日本語エラーを持つ。既存のAppStateリビジョンを使用する。コメント公開面・OBSビュー・音声プレイヤーへ公開しない。
- 認識文字列をOBSやAndroidへ送らず、操作要求だけに変換する。OBSパスワード、トークン、QR、コメント、発話を不要な外部送信先・診断ログ・クラッシュレポートへ含めない。

### Android専用通信

通信とフレーミングは[通信仕様](./smartphone-transport.md#認証付き制御プロトコル版2)を参照する。状態・prepare/confirm/cancelのpayloadは旧JSON版1を維持し、IDはUUID、revisionは非負の安全な整数。

- epochはバックエンド起動ごとのUUID。revisionは操作可否に影響する接続・配信状態・設定・占有状態の変化で増加する。古いepoch・準備時revisionは拒否する。確認IDは認証した端末主体・登録・操作・OBS状態・期限へ結び付け、一度だけ消費する。別端末からの確認と取消を拒否する。要求IDの重複記録も端末主体ごとに分ける。
- lastOperationは直近1件の `operationId, action, status, errorCode`。statusは `executing / succeeded / alreadySatisfied / failed / unknown / cancelled`。認識文字列と確認フレーズは返さない。
- 同じrequestId・同じ本文の再到着は元の結果を返し、違う本文は409。消費済み確認を別requestIdで再実行しない。確認失効後の古い要求は拒否する。重複記録の保持は確認期限と実行完了の両方を過ぎるまでとし、破棄後も確認IDの再利用を許可しない。prepareの再到着だけでOBS要求を送らない。
- Androidは操作を自動再送せず、確認後の通信断では結果不明を表示する。PC再起動で確認をすべて失効させる。状態取得は操作を実行しない。
- 状態取得・準備は200、実行受付202、取消204。不正形式400、認証・公開境界違反403、未定義経路404、競合・古い状態・確認失効409、OBS利用不能503。エラーは安定したcodeと日本語messageとし内部例外を返さない。

## テスト・受け入れ条件

1. 初期オフ、保存復元、音声だけの無効化、OBS連携オフ、秘密復元失敗を確認する。
2. 偽のOBS相手で認証、状態取得・イベント、非対応版、拒否、期限、切断・再接続と操作再送なしを検証する。
3. AppState境界から認識結果を入力し、「配信に使う」とプレビュー、フレーズ検証・正規化・非完全一致、別結果による確認、10秒境界を検証する。
4. 誤確認、延長なし、重複・逆順、無効化・設定変更・停止後の遅延結果、有効化前発話の除外を確認する。
5. Androidの確認・取消・背景移行・再生成・連打・期限、古いepoch・revision、確認再利用、同一要求IDを公開通信契約から検証する。
6. 音声とAndroidの競合、OBS本体の手動操作、既に目標状態、開始・終了中、出力再接続、送信後の結果不明を確認する。
7. 現行共通QRのOBS資格、旧単独登録の退避と解除、不正QRで現行保存を壊さないこと、端末資格の失効・再登録を検証する。OBS接続設定・音声フレーズは保持する。
8. LAN・Tailscale・直接接続、誤認証・Host・Origin・接続元・過大要求・ポート競合と、読取面から操作できないことを検証する。直接接続は公開接続元にprivate範囲制約を流用せず、PC鍵・用途別OBS資格を必要とする。IPv4／IPv6候補切替後も確認所有者と要求IDを保持し、操作を再送しない。
9. QRと秘密の保護、ログ・公開状態への非混入、OBS操作と映像送信・コメント・読み上げの独立性を確認する。
10. OBS実機で音声とAndroidの確認付き開始・終了、音声無効化後のAndroid操作を確認する。
11. ステータス中心の配置、共通見出し、詳細の開閉とキーボード操作、入力とIME、500ms保存、接続情報の領域離脱・明示的な折りたたみ時の保存、連続編集・保存失敗・遅い応答・ページ往復での入力と開閉状態の保持を確認する。閉じた詳細の保存失敗は上部からも確認でき、初回設定では接続欄が開いていることを確認する。設定のみの変更で不要なOBS再接続・配信要求を送らない。
12. スマホ連携への案内と、移動だけで設定が変わらないことを確認する。QRの条件と検証はスマホ連携仕様に従う。320・560・760px幅、長文、通知の前後・消去で位置とフォーカスを確認する。

実装時はWindowsのlint・型チェック・テスト・`pnpm build`を実行し、Android本体・共通通信に影響する変更ではAndroidの単体テスト・lint・デバッグ用コンパイルも実行する。PC画面だけの変更では、配信制御基盤の回帰とElectron・通常ブラウザでの画面確認を行う。配布物は明示依頼がある場合だけ生成する。
