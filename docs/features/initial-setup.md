# PC版の初回設定

2026-10-16採用。PC管理画面に、必要な機能を選んで設定・確認する初回設定を追加する。本書は案内の順序、進行、確認記録を所有する。各機能の設定・操作・公開条件は各所有仕様、共通の配色・入力・通知は[管理画面](./management-screen.md)、設定保存と管理認証は[ローカルアプリケーション](./local-application.md)に従う。

## 入口と進行

- 設定読込でファイルが存在しなかった新規利用時だけ「ようこそ」を自動表示する。既存設定の移行・既定値への退避は新規利用と扱わない。初回設定の記録があればそちらを優先する。
- ようこその表示済み記録を保存し、中断・再起動後は「設定 → アプリ設定」の最下部「はじめての設定」にある「はじめての設定を続ける」から再開する。未開始・終了後は「はじめての設定を開く」とし、設定を消さず再閲覧できる。ホームには専用入口を置かない。新規利用時の自動表示と、ホーム・配信中・設定の3ページを維持する。
- 「中断してホームへ」または通常ナビゲーションで初回設定を離れると、共通トーストで再開場所「設定 → アプリ設定」を案内する。中断ボタンの説明でも再開場所を示す。中断・完了でホームへ戻る際はホーム見出しへフォーカスする。完了時は中断の案内を出さない。
- ようこそ、機能選択、必要な準備・設定、確認結果の順に進む。機能は未選択から選び、何も選ばず終了することもできる。戻る・次へ・後で設定する・中断を提供する。
- 基本順序はコメント取得、読み上げ、スマホ、音声認識、OBS接続、AI、文字演出、キャラクター、OBS表示確認。AIにはコメント取得・音声認識・OBS接続を前提手順として追加する。OBS表示を使う場合は共通OBS接続を一度だけ案内する。手動URL登録も利用できる。
- スマホの用途はコメント、読み上げ、映像・配信マイクから選ぶ。読み上げにはVOICEVOXの準備も追加する。音声認識でスマホ入力を選ぶ場合はスマホの登録を先に行う。段階の構成を変えても保存済み設定は消さない。
- 選択・移動・完了は機能を起動しない。接続・ON・モデル準備・試聴・認識開始・QR・OBS登録とテストは専用の明示操作を使う。AIの実投稿とOBS配信開始は初回設定の操作に置かない。
- 詳細設定は同じ既存編集先を開き、戻ると元の段階・入口・スクロールへ復帰する。通常ナビゲーションへの移動は中断として扱う。
- 2026-10-24、読み上げ・スマホのコメント／読み上げ・文字演出・OBSコメント表示にも、コメント接続を先頭の共通前提手順として一度だけ追加する。機能ナビから往復でき、移動だけで接続・設定変更をしない。音声認識は実際に後続のOBS表示がある場合だけその手順を案内し、AIの前提だけで表示段階がない場合は通常設定から字幕を追加できることを伝える。スマホの見出しは映像だけの用途も含む表現とする。
- 同日の修正では、OBS表示からの詳細先を選択済みの表示に合わせる。複数選択時はコメント・音声認識・文字演出・キャラクターの順とし、無関係なコメント表示設定へ移動しない。進行保存中は戻る・次へ・後回し・終了・再読込のフォーカスを保って操作禁止にし、二重要求を同期的に防ぐ。失敗後は同じ位置から再試行できる。再読込成功で入口が消える場合は、他へフォーカスが移っていないときだけ同じ進行記録の状態欄へ戻す。再読込で段階も変わり元の状態欄が消えた場合は、新しい段階の見出しへ戻す。
- 再確認では、後回しの保存成功で次の段階へ進むときも新しい見出しへフォーカスする。スマホ用途を全て外しても、既にONの接続準備は同じ位置から停止できる。用途の選択は接続準備の開始にだけ必要とする。読み上げの話者一覧取得・声保存・ON/OFF・起動ファイル指定も、処理中の再操作を禁止しつつフォーカスを保持する。一覧取得の案内と読み上げ状態は領域を確保し、更新で後続の操作位置を動かさない。
- 進行保存中は初回設定内から詳細設定へ移動せず、完了後の段階で改めて開く。通常ナビゲーションによる中断は維持する。読み上げOFFでも、取得した話者一覧に保存済みの組が存在しない場合は再選択が必要な状態として進行を禁止する。
- 文字演出の新規ルール保存成功・キャンセルで操作ボタンが消えた場合は、他へフォーカスを移していないときだけ残るルール選択欄へ戻す。別の画面や操作へ移したフォーカスは奪わない。ようこそ・音声認識・文字演出の確認案内は左右の位置に依存しない表現とし、狭幅で確認欄が上に移っても同じ対象を指す。

- 機能選択・スマホ用途・本人確認のチェック枠は、ラベルの先頭行の中央にそろえる。補足文や折り返し、文字サイズの変更でもこの位置関係を維持し、確認用のチェック印は枠の中央に収める。チェック状態・操作禁止・処理中の切替で枠とラベルの位置を動かさない。

- OBS表示確認の追加とテストは、表示対象ごとに一つの「OBSに追加して表示を確認…」から共通ダイアログで操作する。同じダイアログへの別のテスト入口は置かない。既存ソースの利用・手動URL登録・明示テスト・本人確認・閉じた際の入口復帰は維持する。

### 準備済み状態の色（2026-10-24）

- 各設定段階の確認欄は現在の準備状態から成功色を判定する。準備済みの個別項目は既存配色の成功色とチェック印で示し、欄全体の準備が整った場合は枠・背景も成功色にする。明暗8配色で共通の意味とし、色だけに依存せず既存の状態文も維持する。印の領域を常時確保し、状態更新で配置・スクロール・フォーカスを動かさない。
- コメントは選択中のサービスの接続済み・YouTube配信開始待ち、読み上げは保存済みの声を一覧で確認できVOICEVOXが準備完了、OBS接続は現在接続済みの場合を準備済みとする。過去の本人確認だけで未接続の欄を完了色にしない。
- スマホは選択中の経路のPC準備・登録と選択用途に必要な現在の準備を判定し、映像用途ではデータ受信、コメントではコメント接続、読み上げでは声・ON・音声利用可を含める。登録と受信は別々に色を判定する。音声認識はモデル準備と適用済み入力が利用でき、準備中・入力待ち・利用不可でない場合を準備済みとする。配信利用OFFでも試せる契約は維持する。
- AIは保存済みのキー・人格・参加先・必要な投稿認証、文字演出は保存済みルール、キャラクターは警告のない登録済み画像を準備済みとする。個々の保存・登録状態と実際の稼働状態を区別する。未保存・エラーがある間は欄全体を完了色にしない。
- OBS表示確認の成功色は現在のOBS接続と有効な本人確認記録の両方を必要とする。記録は過去の表示確認であり、実映像を自動検出した表示に変えない。色の更新だけで保存・接続・本人確認を変更しない。

## 保存と管理API

- 利用者別アプリデータの `initial-setup.json`（版1）に選択、スマホ用途、現在段階、後回し項目、本人確認のハッシュ、表示済み・終了状態、編集リビジョンを原子的に保存する。一般設定のスキーマは変更しない。
- 管理snapshotの `initialSetup` と `POST /api/management/initial-setup` を使う。要求は期待リビジョンと操作を受け、順番待ちの中で照合する。競合は409で最新状態を返し、古い要求で上書きしない。成功時は保存後に管理WSへsnapshotを通知する。設定・OBS・AI資格・スマホ登録やOBS登録対象の変化で確認識別値が変わった場合は、管理専用の `initialSetup.stateChanged` で別管理画面にも失効を反映する。
- 確認記録の取消は `action: unconfirm` と選択済みの `step`、期待リビジョンを受ける。余分なキーや不正な手順は拒否し、既存の認証・公開除外・原子的な保存契約を適用する。保存形式の版は変更しない。
- 管理APIのHost・Origin・操作トークン検証とno-storeを適用する。公開snapshot・イベント、スマホ向け投影へ進行情報・確認記録を公開しない。
- 記録の読込失敗・未知版・破損では原本を保持し、自動表示を抑止して要確認と再読込操作を提供する。保存失敗では進行を更新せず再試行できる。通常機能・起動を停止しない。進行保存には設定本文、秘密、コメント本文、認識本文を含めない。

## 検証

新規・既存・移行・中断再開・完了再閲覧、全選択と各単独経路、依存手順の共有、選択変更、保存失敗・競合・破損保全、関連設定変更による確認失効、管理認証と公開除外を検証する。明示操作なしの外部副作用がないこと、詳細往復の入力保持、各配色・文字サイズ・最小幅・キーボード、非同期通知による位置・フォーカス保持を実描画で確認する。実サービス・実機の確認は自動検証と区別し、通常の完了検証はbuildまでとする。
