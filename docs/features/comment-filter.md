# コメントフィルター仕様

## 調査入口（仕様ではない）

既定値・入力検証・受信コメント判定は[コメントフィルター](../../src/main/core/comment-filter.ts)、画面の遅延保存とスイッチ操作は[フィルター編集](../../src/renderer/use-comment-filter-editing.ts)、共用の判定規則は[共有判定](../../src/shared/comment-filter.ts)を入口とする。代表的な回帰テストは[設定](../../tests/settings.test.ts)、[AppState](../../tests/app-state.test.ts)、[管理画面](../../tests/dashboard-source-start.test.tsx)。入口は影響範囲の全件一覧ではない。

## 問題

配信者が不適切な語句や大きなアスキーアートを含むコメントを受信すると、コメント一覧、OBSコメントビュー、スマホコメント画面、コメント読み上げへ同じ内容が広がり、個別の画面や音声だけでは一貫して防げない。

## 利用者視点の解決策

配信者は管理画面でNGワードを1行1件登録し、必要な場合だけアスキーアート判定をオンにする。該当コメントは共通コメントとして保存・配信される前に除外され、全ての表示とPC・スマホの読み上げに現れない。

## ユーザーストーリー

1. 配信者として、NGワードを含む投稿者名または本文を全ての表示と読み上げから除外したい。配信中の不適切な内容の露出を一か所の設定で防げるからである。
2. 配信者として、大きな複数行アスキーアートを必要なときだけ除外したい。通常コメントと1行顔文字を維持しながら画面占有を防げるからである。
3. 配信者として、大量のNGワードを管理画面の高さを増やさず編集したい。他の配信設定を確認しやすいからである。
4. 配信者として、編集中の条件でサンプルを試し、実際のコメントを送信せずに除外範囲を確認したい。部分一致による意図しない除外を配信前に見つけられるからである。

## 具体的な挙動

### 判定位置と除外範囲

- 初回履歴と新着コメントの双方を、コメント履歴への保存、`sequence` の割当、リアルタイムイベント、OBS表示、PC読み上げ、スマホ読み上げへ渡す前に判定する。
- 該当コメントはコメント一覧、管理画面内プレビュー、独立コメント一覧ウィンドウ、通常ブラウザ、OBSコメントビュー、スマホコメント画面、PC読み上げ、「スマホでコメントを聞く」へ追加せず、コメント文字演出も発生させない。
- 除外したコメントの外部IDは配信セッション中の重複排除へ登録する。同じコメントを再受信しても、設定解除後を含めて復元または再配信しない。
- 除外コメントには `sequence` を割り当てず、10,000件のコメント履歴上限へ数えない。
- したらば次スレッド作成時のシステム案内など、コメントソースから受信した視聴者コメントではない内部案内は対象外とする。

### NGワード判定

- 投稿者名と本文を対象とする。本文のテキストは表示順に連結し、公式エモートは代替テキストを使用する。
- NGワードと対象文字列をUnicode NFKCで正規化して小文字化し、正規表現ではない部分一致で判定する。
- NGワードの前後空白と空行を除き、正規化後に同じ文字列となる登録は最初の1件だけを保持する。
- NGワードが0件の場合、NGワードによる除外を行わない。

### アスキーアート判定

- 本文だけを対象とし、設定がオンの場合だけ判定する。既定はオフとする。
- CRLFとCRをLFへ正規化し、非空白文字のない行を除いて評価する。
- Unicodeの文字、数字、結合文字以外の非空白文字を記号として数える。
- 次の全条件を満たす本文をアスキーアートとして除外する。
  1. 2行以上で、非空白文字が合計8文字以上ある。
  2. 非空白文字が3文字以上かつ記号率50%以上の行が2行以上ある。
  3. 本文全体の記号率が50%以上である。
- 1行の顔文字は除外しない。

### 管理画面

- 2026-09-16、配信者が選んだA案「編集＋確認」を採用する。共通見出し、設定一覧からの移動・復帰、通知は [管理画面仕様](./management-screen.md) に従う。比較案は [見本の記録](../../prototypes/comment-filter-ui-throwaway/README.md) を参照する。
- 2026-10-20、見本「設定とテストを並べる」を採用する。[設定編集画面の共通レイアウト](./management-screen.md#設定編集画面の共通レイアウト)の説明枠は「不要なコメントを、表示・読み上げ・演出から除外します。」の1文とする。全接続先へ適用する範囲と判定・保存処理は変えず、編集領域内では同じ説明を繰り返さない。
- 十分な幅では左側にNGワード編集とアート除外、右側に判定テストを等幅で並べる。680px以下ではNGワード、アート除外、判定テストの順に縦へ並べる。320px幅、文字拡大、長い入力値でも横にはみ出さない。テストや設定を切り替えるタブは追加しない。
- NGワードには登録件数、「投稿者名・本文のどちらかに含まれると除外します。」、1行に1件の説明と固定高さ6行・内部スクロール・手動サイズ変更なしの入力欄を置く。件数は空行・重複を整理した編集中の値から数え、登録数だけで領域全体の高さを増やさない。「空行・重複は自動で整理します。」と保存失敗の説明には共通の固定領域を使う。自動保存の説明を重ねて表示しない。「一致のルール」で部分一致、全角半角と英字大小文字の扱い、正規表現を使用しないことを確認できる。
- アスキーアート判定は「アスキーアートを除外」と共通スリムスイッチで切り替え、「複数行の記号アートが対象です。」と短く説明する。オン／オフを文字でも示し、複数行アートと対象外の1行顔文字を並べる。スイッチを切り替えても周囲の背景・枠色は変更しない。
- NGワード入力欄とアスキーアート判定トグルの保存時期は、[ローカルアプリケーション仕様](./local-application.md) の入力項目とチェックボックスに対する自動保存規則を使用する。
- 入力途中のNGワードをスイッチ操作だけで先に保存しない。保存待ち・保存失敗・編集中の値は画面移動でも保持する。保存失敗時の理由は予約済み説明領域と共通の「要確認」から確認でき、本文へ通知行を挿入しない。処理中に新しい入力を古い値で上書きしない。
- 2026-10-18、末尾の適用時期・過去コメントの扱いの案内を削除する。試作の架空の「反映済み」表示は持ち込まず、保存専用ボタンは追加しない。

### 判定テスト

2026-10-27、除外しない結果は「表示・読み上げの対象です」と示す。これはフィルターの判定であり、機能の稼働や実際の表示・再生成功を保証しない。「入力中の設定を使用」と投稿・読み上げしない注意は常設し、詳細ではこれらを繰り返さず、送信・保存しないこととエモートの入力方法を説明する。

- 管理画面内で投稿者名とコメント本文を入力し、現在の編集値を使って即時に判定する。保存待ちや保存失敗の値も対象とするため、「入力中の設定」での判定であることを常時明記し、実際に保存済みの条件での結果と混同させない。
- 見出し横に「入力中の設定を使用」を置く。サンプルの補足は「NGワード入りは先頭の語を使います。」、0件では「NGワードを登録するとサンプルを選べます。」とする。未入力時は「コメントを入力してください」「投稿者名だけでも判定できます。」、判定済みは記号と「除外されます」「表示・読み上げの対象です」を示す。一致語と対象は短い文で示すが、判定順序は変更しない。
- 結果の下には「テスト内容は投稿・読み上げされません。」を常設し、送信・保存しないこととエモートの代替テキスト入力は初期状態で閉じた「テストについて」にまとめる。入力と両方の詳細の開閉は画面往復で保持し、自動更新では開閉しない。
- 初期入力は空とする。通常文、NGワード入り、複数行アートのサンプルボタンを置き、選択すると投稿者名と本文を差し替える。NGワード入りサンプルは登録順の先頭の有効な編集値を使い、0件ならボタンを無効にして理由を説明する。サンプル選択によってNGワードや判定スイッチを変更しない。
- どちらの入力も空白だけなら入力を促し、判定済みとして表示しない。それ以外は「除外されます」「表示・読み上げの対象です」を記号・文字とともに常設の結果領域へ表示する。
- NGワード一致を先に示し、登録順の最初の一致語と対象（投稿者名／本文）を表示する。同じ語が両方にある場合は投稿者名を優先する。NGワードに一致せずアスキーアート判定に該当する場合は、その理由を表示する。結果の長文化は結果領域内で折り返し・縦スクロールし、下の操作位置を動かさない。
- 受信コメントとテストは同一の判定関数を使う。テスト本文はプレーンテキストとして扱い、エモートを確認する場合は代替テキストを入力する。
- テストは画面内だけで完結し、入力・結果をAPI、WebSocket、コメントソース、AI、読み上げ、表示先、診断ログへ送信しない。コメント履歴・重複排除・設定ファイル・ブラウザー保存領域にも追加しない。
- テスト入力と「一致のルール」「テストについて」の開閉は管理画面内の移動で保持し、管理画面の再読み込みで破棄する。テスト入力・結果はReactのテキストとして表示し、HTMLとして解釈しない。
- 通知・処理中・結果更新の確認には、[通知で操作位置を動かさない共通ルール](./management-screen.md#通知で操作位置を動かさない共通ルール) と [共通トースト](./management-screen.md#共通トースト) を必ず適用する。判定結果自体は常設結果領域で伝え、成功通知トーストにはしない。

### 設定変更

- 保存後に受信したコメントから新しい設定を適用する。
- 設定変更前に保存、表示、再生、または待機していたコメントは再判定しない。
- 除外済みコメントはNGワード削除またはアスキーアート判定オフの後も復元しない。

## 設定

- `ngWords`: NGワード文字列の配列。既定は空。
- `asciiArtEnabled`: アスキーアート判定の有効状態。既定はオフ。
- コメントフィルター設定をローカルへ永続化する。除外コメントと除外理由は永続化しない。

## エラー処理とプライバシー

- 不正な設定は保存せず、直前の有効設定を維持して管理画面へ日本語で通知する。
- 除外理由、NGワードに一致した箇所、投稿者名、コメント本文を診断ログ、テレメトリー、スマホ向け公開データへ追加しない。
- 判定処理の失敗で他のコメントソースやアプリ全体を停止させない。

## テスト条件

1. 投稿者名、本文、公式エモート代替テキストでNGワードを判定し、大文字小文字と半角全角の差を吸収する。
2. 空行、前後空白、正規化後の重複を整理し、登録していない部分一致は発生しない。
3. 代表的な複数行アスキーアートを除外し、通常の複数行文章、箇条書き、URL、1行顔文字を除外しない。
4. 初回履歴と新着コメントの該当コメントが、履歴、WebSocket、OBS、PC読み上げ、スマホ読み上げへ伝播しない。
5. 設定変更前のコメントを維持し、保存後の受信だけへ適用し、除外済み外部IDを再受信しても復活しない。
6. A案の左右配置と狭幅での縦配置、6行入力、正規化後の登録件数、共通スイッチ、説明の開閉を確認する。画面移動で編集中の値・保存待ち・テスト入力を保持する。
7. 現行のNGワードと判定設定を保持し、旧保存の退避・初期化は[保存と対応版](./local-application.md#compatibility-baseline)に従う。
8. 判定テストの空入力、投稿者名／本文の部分一致、全角半角・大小文字、通常文・顔文字・複数行アート、0件時のサンプル、長い一致語を確認する。テスト操作だけでは保存・API要求・コメント配信を行わない。
9. NGワードの遅延保存とスイッチの即時保存、保存中の追加入力、失敗からの再編集、警告入口からの復帰を確認する。通知・結果変更前後で入力位置・本文高さ・スクロール・フォーカスを維持する。

## 対象外事項

正規表現、コメントソース別設定、判定感度の手動調整、除外件数の統計とログ、除外コメントの復元は対象外である。比較用のB・C案、案切替・状態選択・模擬保存・状態JSONは製品へ含めない。
