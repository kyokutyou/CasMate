# Android外配信仕様

2026-10-13追加採用の手書き合成・静止中の編集版と送信版・復帰時の公開条件は[Android手書き映像合成仕様](./android-handwriting-overlay.md)が所有する。既存カメラ・時刻・弱回線対策と組み合わせる際は同仕様も適用する。

## 認識用のローカル分岐（2026-10-08追加）

選択された端末の受信MPEG-TSをOBSとは別の127.0.0.1 UDPへ非待機で分岐する。認識の接続・停止・入力変更・障害によってSRT受信やOBS転送を再開始しない。受信接続の境界で認識分岐を解除し、即時に新connectionRevisionを通知する。現在世代を確認した認識側の準備要求だけで再開する。任意アドレスへ転送せず、分岐失敗は認識側だけへ通知する。認識と復旧の意味は[配信者音声認識](./streamer-speech-recognition.md#外配信入力とスマホ操作2026-10-08追加採用)を参照する。

## 問題と解決策

配信者はスマホ1台でコメント一覧と読み上げを利用しながら、外のカメラ映像と配信マイクを自宅のOBSへ送りたい。AndroidからLAN、Tailscaleまたは直接接続でPCの端末別ワーカーへSRT送信し、PCはOBSへループバックUDPでMPEG-TSを転送する。送受信刷新の判断は[ADR 0018](../adr/0018-native-srt-and-local-receiver.md)、直接接続追加は[ADR 0020](../adr/0020-adopt-smartphone-direct-connection.md)に従う。2026-10-04の直接接続追加は**実装済み・実機検証未完了**で、既存送受信の検証結果と区別する。

本書が外配信の正式仕様を所有する。現行の通信判断は [ADR 0018](../adr/0018-native-srt-and-local-receiver.md)、既存の表示・読み上げは [Androidクライアント仕様](./android-mobile-client.md) を参照する。

2026-09-30、自動ビットレート制御全体を一から設計し直す方針を採用した（[ADR 0016](../adr/0016-redesign-outdoor-adaptation.md)）。映像の動きと早い動画復帰を優先し、旧「音声優先」を「弱回線対策」へ改める。当時は既存のSRT転送・登録・音声経路を維持した。**2026-09-30時点の再設計版の実装と必須確認を完了**。現行の送受信経路は以下のネイティブ送受信契約で更新する。自動検証・独立レビュー・短い実機確認の結果と確認済み構成・未検証範囲は[実装検証記録](../validation/outdoor-adaptation-implementation-2026-09-30.md)を参照する。制御の所有範囲は[弱回線対策と自動制御](#弱回線対策と自動制御)、録画なしの検証範囲は[再設計版の受け入れ条件](#自動制御の再設計版の受け入れ条件)を参照する。

## ユーザーストーリー

1. 配信者として、PCのQRから外配信設定を登録したい。送信先や秘密情報を手入力せずに済むからである。
2. 配信者として、OBSの受信設定を再利用したい。毎回ソースを作り直さずに済むからである。
3. 配信者として、スマホで明示的に映像送信を開始・停止したい。意図しない撮影を防げるからである。
4. 配信者として、コメント一覧・読み上げと映像送信を同時に使いたい。外配信を1台で行えるからである。
5. 配信者として、前後カメラ、向き、マイクを選びたい。撮影状況に合わせられるからである。
6. 配信者として、画面ロック中も送信し、通知から停止したい。画面点灯を続けずに配信できるからである。
7. 配信者として、通信断から自動復旧してほしい。移動のたびに操作せずに済むからである。
8. 配信者として、PCとスマホで送信状態を確認したい。接続の問題に気づけるからである。
9. 配信者として、マイク切断や権限不足を知りたい。意図しない音声入力や無音を避けられるからである。
10. 配信者として、一つの機能の障害で他の機能を失いたくない。配信を継続できるからである。
11. 配信者として、秘密情報を通常画面やログへ残したくない。送信設定を必要な相手にだけ渡せるからである。
12. 配信者として、映像ビットレートを固定するか回線に合わせて自動調整するか選びたい。画質と継続性の優先を決められるからである。
13. 配信者として、対応端末でH.265を選びたい。画質と通信量を比較して選べるからである。
14. 配信者として、回線が弱いときも低画質の動画で動きを残し、必要な場合だけ現在画像で静止してほしい。外の様子をできるだけ伝え続けたいからである。
15. 配信者として、条件が整ったら低画質の動画を早く試し、安定してから画質を戻してほしい。長い静止と不安定な往復を抑えたいからである。
16. 配信者として、手動で隠した映像を自動で表示しないでほしい。撮影内容の公開を自分で管理したいからである。
17. 配信者として、映像だけの故障でも利用できるマイク音声を継続したい。一部の故障で配信全体を失わずに済むからである。
18. 配信者として、未対応の形式や自動調整を開始前に知りたい。送信中の予期しない形式変更を避けたいからである。
19. 配信者として、判断理由と直近の数値履歴を必要時だけ書き出したい。映像・音声や秘密情報を渡さずに挙動を説明したいからである。
20. 配信者として、普段の端末で短い確認だけを行いたい。OBSとスマホの録画・編集・照合をせずに検証へ協力したいからである。
21. 配信者として、設定要求が受け付けられたことと実際に映像量が変わったことを区別したい。未計測や制御の効果不足を回復と誤解したくないからである。

## 構成と対応範囲

- Windows 11上のOBSときゃすメイトPC、およびAndroid 10以降のAndroidクライアントを対象とする。LANは家庭内LAN、Tailscaleは配信者が管理する同じtailnetへ両端が参加する。直接接続は[公開候補・受信準備](./smartphone-direct-connection.md)を必要とする。
- AndroidはSRT Caller、PCの端末別ワーカーはListenerとし、MPEG-TSの映像と音声を同じAES-256 SRT接続で送る。OBSは固定のループバックUDPメディアソースで受信する。音声の独立した通信経路や帯域保証は追加しない。
- 登録先PCは1台、OBSは同じPCで稼働する。複数スマホから同時送信でき、経路別のSRT登録と端末共通のOBS入力は[スマホ連携仕様](./smartphone-integration.md#device-shared-obs-input)に従う。
- PCアプリは端末別ワーカーで受信し、127.0.0.1へ転送する。映像の保存・再エンコード・シーン変更は行わない。OBS配信の開始・終了は独立した [OBS操作仕様](./obs-control.md) が所有する。
- Tailscaleの導入・契約・接続は [ADR 0009](../adr/0009-use-tailscale-private-network-for-mobile-speech.md) の利用者管理方針に従う。directの確認手順を案内するが、リレー経路を理由に一律拒否しない。

## OBS表示テストとの境界

2026-10-05、利用者の判断でスマホ合成映像テストを採用範囲から除外した。[OBS表示テスト](./obs-source-registration.md#obs表示テスト)はブラウザ表示だけを対象とし、受信ワーカーはテストcapability・テスト制御・合成パケットを扱わない。実SRT映像を通常どおりOBSへ転送し、テストのために保留しない。スマホのカメラ・マイク・送信経路は通常のスマホ送信で確認する。

## ネイティブ送受信契約

2026-10-08、経路別受信管理を端末単位で調停する。保存成功後に旧経路世代を失効し、周期更新・準備・再試行を含む全ワーカー操作の受付、非同期待機後、開始直前に現行設定を照合する。旧ワーカーの実終了確認後だけ共通OBS入力へ新受信を開始する。端末ごとに開始・停止を直列化し、他端末とコメント公開の切替を停止待ちで塞がない。保存キューから直接接続全体の準備・終了完了を待たない。

停止は入力終了による通常終了1.5秒、その後の所有プロセス強制終了と実終了確認1.5秒を上限とする。終了未確認は停止不明の所有記録を保持し、同じ転送先へ新受信を開始しない。遅い実終了確認後は現在世代だけ再試行する。停止開始で認識分岐と旧認識世代を失効し、現行受信の確認後だけ認識を再開する。停止中・停止不明は管理画面の状態に示す。

2026-10-03採用。既存の品質・入力・適応状態・数値履歴の製品挙動を維持し、以下を通信実装の現行契約とする。旧版の観測でACKと呼んだ送達根拠は、現行ではlibsrtの統計とPC実受信による確認へ置き換える。過去の検証記録は新通信経路の検証完了を意味しない。

- libsrt 1.5.7と暗号化ライブラリを両端で静的リンクする。依存ソースの版・SHA-256・ライセンスを管理し、配布時に通信依存を別途導入させない。SRTの再送・暗号化・ペーシング・生存監視を独自実装しない。
- Androidは接続ごとに世代を増加させ、SRT stream IDに外配信セッションUUIDと世代を渡す。資格情報は含めない。接続の期限は1.5秒、無応答監視は1.5秒とし、取消・明示停止を優先する。古い非同期結果で再開しない。
- エンコード済み送信待ちは時刻と総バイト数で上限を持つ。上限は選択SRT遅延以下かつ4MiB以下とし、期限切れを後送しない。映像の抑制は投入前、混雑時の破棄はフレーム単位で行い、音声を優先する。再接続で古い待ちを全破棄し、PSI・codec設定と新しいキーフレームを送る。再接続だけで入力を再準備しない。
- MPEG-TSの同期時計（PCR）は、映像・音声の再生時刻（PTS）と同じ送信時間軸で生成し、端末起動からの経過時間を混在させない。現行のPTSだけを持つPESでは、そのPESの再生時刻を同期時計にも用いる。再接続時もエンコーダーの時間軸を引き継ぎ、33bit時刻の周回をPCRとPTSで揃える。
- PCは端末・選択ネットワークごとに1プロセスを所有する。LAN／Tailscaleは検証済みIPv4と専用UDPポートへbindし、接続元のネットワーク範囲を検証する。直接接続は検証済みローカルIPv4／IPv6と端末専用内部UDPポートへアドレス別にbindし、接続元にprivate範囲制限を流用しない。全経路でAES-256と端末別パスフレーズを必須とし、未暗号化・誤鍵を拒否し、stream IDの形式・世代を検証する。受信したMPEG-TSのみ127.0.0.1の固定UDPポートへ送る。任意の転送先を受け付けない。
- 直接接続の受信ワーカー設定は新しい契約版2とし、選択network、family・ローカルaddress・内部portからなる待受一覧、端末資格・固定localPortを明示する。既存LAN／Tailscaleの契約版1を維持し、新版を旧版として解釈しない。ワーカーは各アドレスを検証し、一候補のbind失敗で他候補の正常な待受・同じ端末の接続を閉じない。候補がすべて失われれば端末受信エラーとする。
- AndroidのSRT callerは登録応答版14のoutdoor.endpointsと端末別outdoorPortを使い、トップレベルのTCP候補、PC内部ポートやOBS入力をSRT送信先に使わない。IPv4／IPv6の選択・再接続・鍵の失効は直接接続仕様と通信仕様に従う。同じ端末の同じ送信世代を候補別に重複送信しない。
- ワーカーへの秘密は標準入力で渡し、コマンド行・ログ・管理snapshotへ出さない。標準出力は版付きの最小状態と数値だけにする。入力終了で終了し、PCは停止期限後に自分が起動したワーカーだけを終了する。異常終了・bind失敗は端末別に表示して有界間隔で再試行し、他端末・コメント・OBS操作を止めない。
- 直接接続ワーカーのローカル状態には、実際に準備した`listeners`、接続中の`activeListener`、有効なSRT接続受付ごとに増える`connectionRevision`を含める。PCはワーカー起動IDと組み合わせて受信の接続世代を識別する。この情報をAndroid向け版1の受信確認へ追加せず、公開候補別の到達判定だけに使う。
- 受信確認は[認証付き制御プロトコル](./smartphone-transport.md#認証付き制御プロトコル版2)で購読する。版1のpayloadは同じsessionId/generationの受信バイト、損失・破棄、完全な映像/音声PES進行と最終PTSを返す。不一致・未受信は未取得。媒体内容・秘密・他端末の状態は返さない。
- Androidは最大4回/秒、映像送信から独立してフィードバックを取得する。接続世代・ローカル受信時刻・累計後退を検証し、1秒を超えた結果は欠測とする。映像PTSと送信フレームの対応を有界に保持し、同じ復帰試行世代の新しいライブ映像の実受信を確認する。静止フレームや過去接続・重複応答で復帰させない。フィードバック障害だけで正常なSRTを閉じない。
- PCの受信進行とOBSでの復号・表示は区別する。管理画面は「受信待ち／受信中／再接続待ち／受信エラー」を端末別に示す。診断のLAN／Tailscale／直接接続は選択経路であり、Tailscale direct/relayとアプリの直接接続を混同しない。Tailscale direct/relayは計測できない場合「未確認」とする。
- 現行libsrt統計の送信量は映像・音声・再送とIPv4/UDP/SRTヘッダーを含み、制御パケットを含まない。NAKは受信した制御パケット件数であり、要求されたDATAパケット数ではない。期限切れ判定は送信側と受信側の検出件数を合算し、同じDATAの重複検出を含むと説明する。期限切れバイト量は送信側だけと明記する。
- 直接接続のIPv6でも統計の定義と品質設定を維持し、IPv4ヘッダーを基準とする現行値をIPv6回線の実通信量と断定しない。選択familyと計測値の定義・未計測範囲を区別する。
- OBS入力は `udp://127.0.0.1:PORT?localaddr=127.0.0.1&fifo_size=1024&overrun_nonfatal=1` とする。入力形式はmpegts、ローカルファイルOFF、ネットワークバッファを小さくして確認する。コピー内容に秘密を含めない。OBSを閉じてもPC受信は継続できる。
- 720p30・SRT 400ms・良好な直接接続で撮影からOBS表示1秒未満、回線復帰後5秒以内の映像・音声復帰を目標とする。SRT設定値を総遅延としない。弱回線は音声欠落・停止時間・復旧を優先する。旧版と同条件で比較し、未測定を達成としない。
- ネイティブ実接続で暗号化・不正鍵・未暗号化拒否、接続期限・停止競合、帯域制限・損失・遅延・断復帰を確認する。偽の時系列では世代・欠測・復帰条件を確認する。Windows/Android両ビルド、複数端末・ワーカー故障・更新移行を検証し、実機不足やOBS目視・聴取の未実施は明記する。

## PCの準備と設定

PCの準備と登録情報の自動更新は、2026-10-04採用の[接続準備の一本化](./smartphone-integration.md#simplified-preparation)に従う。

ネットワークの選択、端末別ポート・資格情報・準備状態、OFFと削除の意味、旧設定移行は[スマホ連携仕様](./smartphone-integration.md)が所有する。映像の状態受付TCPポートは既定3001、1024〜65535とし、既存HTTPポートとの競合を拒否する。秘密は既存のWindows・Androidの保護領域に保存する。最新の保存情報と送信中の情報を分け、更新だけで正常なSRT・撮影・エンコーダーを再起動しない。切断後の再接続または次回の明示開始で最新の準備済み情報を使う。失効した資格では再接続せず、手動停止後に再開しない。固定のローカルOBS入力は維持する。直接接続のUDP開放はネットワークONで維持し、送信停止・OBS終了とは連動しない。

## 送信品質とエンコード設定

本節以降の送信開始・停止はAndroidからOBSへの映像送信を指し、OBS配信の開始・終了とは独立する。

品質設定はAndroidが所有する。映像形式はH.264／H.265（HEVC）から選択する。AAC-LC、48kHz・モノラル、ハードウェア映像エンコード、AES-256と登録済みパスフレーズを維持する。対応上限は1080p・60fpsとし、実際に選択できる組み合わせは端末の対応範囲に限る。

| 項目 | 選択範囲 | 初期値 |
| --- | --- | --- |
| 映像形式 | H.264・H.265（HEVC） | H.264 |
| ビットレート制御 | 固定・自動 | 固定 |
| 弱回線対策 | オフ・オン（自動モードのみ） | オフ |
| 映像ビットレート | 0.5～12Mbps、0.1Mbps刻み | 2.5Mbps |
| 解像度 | 640×360、854×480、1280×720、1920×1080 | 1280×720 |
| フレームレート | 15・24・30・60fps | 30fps |
| SRT遅延バッファ | 200～3,000ms、100ms刻み | 400ms（保存済み値は維持） |
| 音声ビットレート | 32・64・96・128・192kbps | 64kbps |
| キーフレーム間隔 | 1・2・4秒 | 2秒 |

- 縦向きでは解像度の縦横を入れ替える。映像ビットレートはエンコーダーの目標値とし、実送信ビットレートや通信量の上限保証とは区別する。CBR/VBRやプロファイルの手動選択は追加しない。
- カメラと、選択形式を実際に処理するハードウェアエンコーダーの対応を検証する。H.264の対応でH.265も対応とみなさない。自動モードでは動的ビットレート変更の実効性と選択範囲も検証対象とする。未対応時は理由を表示し、黙って別形式・ソフトウェアエンコード・固定モードへ切り替えない。OBSでの映像・音声受信は実機確認対象とする。
- 利用者による品質設定の編集は停止中だけ可能とする。選んだ形式・解像度・fps・音声品質・SRT遅延・制御方針は送信中と再接続中に維持する。自動モードの実行中映像目標値と入力画像の適応は[弱回線対策と自動制御](#弱回線対策と自動制御)に従う。設定欄では「設定を変更するには映像送信を停止してください」と案内する。
- 品質設定は端末内に保存し、アプリ再起動後も復元する。QR再登録では上書きしない。操作配置は [Androidクライアント仕様](./android-mobile-client.md#android画面) に従う。

### 映像の向きと描画

- 2026-10-07の修正採用により、横向き／縦向きは送信映像の縦横比・解像度だけを選ぶ。カメラ画像を正立させる回転角は独立し、端末の実際の向きに追従する。画面の自動回転が無効でも実向きを用い、向きを取得できない間は最後の角度を維持する。開始時は表示の回転を初期値にし、角度の境界付近で細かく往復しない。
- カメラのSurfaceTextureが持つセンサーの回転・クロップ・反転を維持し、その変換と取得解像度から画像の縦横比を求める。プレビューと送信で同じ正立画像を使い、選択した出力に全体が収まるよう中央配置する。異なる縦横比では余白を許し、引き伸ばしや追加の切り取りを行わない。プレビュー外側の余白と映像内部の余白ではタップによるピント合わせを行わず、画像内の座標は同じ描画変換の逆変換で求める。
- 端末の回転・Activity再生成・タブ移動だけでエンコーダー、マイク、SRTを再開始せず、出力解像度・fpsと音声の設定を維持する。前後カメラの切替とカメラ復帰でも補正を再適用する。手動非表示の黒／固定画像にはカメラ補正を適用しない。緊急静止の保持画像は端末回転でも保持し、動画復帰時に現在の向きを反映する。診断時刻は正立画像への描画後に重ね、プレビュー・送信で従来の一致を維持する。
- プレビューの描画面の作成・差替え・解放は送信用の描画と同じスレッドで直列化する。共有するEGL環境は所有元の終了時だけ解放し、プレビューの破棄で送信側を終了しない。旧画面の遅い破棄通知は新しいプレビューへ作用させず、停止した描画世代の保留操作を次の送信へ持ち越さない。
- 縦横出力と4方向、前後カメラのセンサー変換、縦横比・余白・ピント座標、向き不明・境界付近、保持・非表示・復帰を自動検証する。短い実機確認では横向き出力のプレビューと実送信映像、前後カメラとタブ復帰を確認し、実物の端末回転など未確認の範囲は区別して報告する。

### 固定と自動の設定・保存

- 固定では選択した目標ビットレートを維持し、混雑による自動低下・緊急静止を行わない。「固定」はCBR指定や回線送信量の一定化を意味しない。
- 自動では通常動画の下限と上限を指定する。選択範囲と刻みは映像ビットレートの表に従い、下限は上限以下とする。初期下限は0.5Mbps、初期上限は2.5Mbps。固定値と自動の範囲は別々に保存する。
- 「弱回線対策」は自動調整とは独立して選択する。自動＋オフは通常下限までの調整に限り、意図的な静止を行わない。自動＋オンは通常下限より低い動画と、必要時の現在画像静止を許可する。固定では無効表示し「自動モードで利用できます」と案内する。固定へ切り替えるとオフにし、自動へ戻しても勝手にオンにしない。
- 品質保存は版1と全品質項目を持つ。現在の完全な版なし保存だけを同値で版1へ取り込む導入入口を設ける。既知の旧項目形状は元JSONをnoBackupFilesDirへ退避後、品質だけ初期化し、volumeと登録は保持する。audioFirstは現行キーとして維持する。
- 保存する選択値と実行中の目標値・適応状態を分離する。自動制御のたびに保存値を書き換えない。自動の新規送信は通常下限から始め、再接続では現在の低下・静止状態を維持する。停止後の新しい送信へ保持画像や緊急状態を引き継がない。
- 品質と版は同じquality JSONキーへcommitする。全インスタンス共通のロックで直列化し、退避・保存確認が成功するまで利用側へ反映しない。未知・不正・破損は自動初期化しない。保存・復元失敗は外配信の設定エラーとし、原本退避と失敗記録を保持する。

## 診断用の映像時刻表示

- 送信停止中に「診断用時刻を映像に表示」を選べる。初期値はオフとし、選択は外配信セッションだけに適用する。送信を終了するとオフへ戻し、次の送信やアプリ再起動へ引き継がない。送信中は切り替えず、画面再生成後もそのセッションで実際に適用中の値を表示する。
- オンのときは端末の現地時刻を `HH:mm:ss`（24時間表記、秒まで）でカメラ映像に描き、同じ時刻表示をAndroidのカメラプレビューとSRT映像の両方へ載せる。時刻は映像へ焼き込まれ、OBS録画・配信にも残ることを設定画面で案内する。時刻表示はカメラ撮影時刻やOBS表示時刻、OBSでの受信成功を証明しない。端末時計の変更は次の更新から反映する。
- 時刻の更新は最大1秒に1回とし、同じ映像フレームを描くプレビューとSRTで同じ表示値を使う。画面ロック、他アプリ表示、プレビューを閉じた状態でもSRT側の表示を続ける。時刻表示の故障で音声送信を止めない。
- 緊急静止では、保持画像に焼き込まれた時刻も静止させる。音声と映像フレームの表示時刻は従来どおり進める。手動で「映像を隠す」を選んだときは、黒／固定画像とAndroidの代替プレビューのどちらにも診断用時刻を表示しない。
- 時刻の更新・一致、向き・プレビュー、保持／解除、手動非表示と描画再準備は時計・描画経路の自動テストで検証する。実機で必要な目視確認は[短い実機確認](#録画なしの短い実機確認)へ含められる。OBSとスマホの録画・照合や、時刻表示による音声欠落の精密測定を今回の完了条件にしない。実生成量・キーフレームピーク等への未測定の影響を、影響なしとは扱わない。

## 弱回線対策と自動制御

2026-09-30採用。目的は、低画質でも映像の動きを残し、必要時だけ現在画像で静止し、条件が整ったら早く動画を試すことである。判断理由は[ADR 0016](../adr/0016-redesign-outdoor-adaptation.md)を参照する。本節が制御・観測・適用の契約を所有し、画面配置はAndroid仕様、診断の内容は[通信状態の詳細](#通信状態の詳細)が所有する。

### 制御の責務と優先順位

- 自動制御が変更できるのは映像の実行中目標ビットレートと送信する入力画像だけとする。映像形式・解像度・fps・SRT遅延・音声品質は送信中に自動変更しない。
- 動画の継続・早い復帰を優先しつつ、音声の待ち・破棄を緊急制御の材料にする。同一SRT接続を維持し、完全断や音声分にも足りない帯域での継続を保証しない。OBSの表示・音声受信成功は送信側から断定しない。
- 利用者の公開希望（カメラ／手動非表示）、通信適応、適用待ち、自動変更の停止理由、映像故障、SRT接続状態を分離する。停止・手動非表示・権限失効を最優先し、古い画像保持・保持解除・映像復旧の完了を反映しない。
- マイクの入力機器、AAC設定、音量、手動ミュート、入力喪失時の無音を変更しない。正常な音声・SRTを映像適応だけの失敗で停止・再開始せず、コメント読み上げにも波及させない。
- 固定モードは観測と診断だけを行い、映像目標・入力画像へ緊急介入しない。自動＋弱回線対策オフは通常下限までの調整に限り、緊急動画・自動静止を行わない。

### 観測と混雑・安定の判定

- 同じ接続世代・単調増加時計で得た、読み取り専用の一貫したスナップショットを使用する。接続世代、取得時刻、ACKの進行と最終進行時刻、確認済み量、未確認量と最古経過時間、送信前と処理中の待ち、音声の最古待ち、再送、送信前破棄、期限切れ破棄、実映像生成量とキーフレーム量、映像・音声の生成／ローカル送出の進行を区別する。
- ACKは実際に新たな送信データを確認したときだけ進行と数える。重複・逆順のACKや期限切れによる削除を確認済み量へ加算しない。連番周回を扱い、試行開始後の動画データまでACKが進んだかを、接続世代と動画フレーム・送信パケットの対応から判別できるようにする。圧縮済み映像を診断履歴へ保存しない。
- 音声の送信前破棄と、SRT送信後の期限切れ破棄を混同しない。初期実装では音声／映像別の期限切れ内訳を必須にせず、いずれかの期限切れ破棄が発生した窓を混雑・回復不可として扱う。取得できない内訳を0と表示しない。
- 周期は250ms。取得時刻が未来・1秒以上古い・前回からの間隔が1秒を超える、必須値が欠ける、接続世代が違う、累計値が後退する観測は比較不能とする。新しい比較基準から再開し、混雑・安定の継続時間をリセットする。1秒間に新たなACK進行または必要な映像・音声生成がない場合も、復帰・増加の根拠にしない。欠測を0や良好へ変換しない。
- 警戒時間を `W = min(250, max(50, latencyMs / 4))` msとする。送信前・処理中の最古待ちをQ、未確認データの最古経過時間をU、基準RTTをRとし、滞留指標は `max(Q, max(0, U - R))` とする。空の待ちは0、有効な基準RTTがない間の補正値は未計測とする。
- 基準RTTは接続世代内の新しい有効なRTT観測の最小値を保持する。時間窓から低い値が消えたことや、混雑・静止・試行中の高いRTTで引き上げない。再接続で取り直す。基準RTTの補正とは独立に、音声の待ち、未確認データが設定SRT遅延に達していること、期限切れ破棄を監視する。
- 滞留指標がW以上、音声の最古待ちがW以上、未確認データの最古経過時間が設定SRT遅延以上、送信前の音声／映像破棄、期限切れ破棄のいずれかを混雑とする。RTTだけ、NAKだけ、主キュー件数だけでは混雑を確定しない。再送とNAKは診断に残し、回線の固有損失率へ換算しない。
- 安定候補は、比較可能な新しい観測で滞留指標と音声待ちがW/2未満、送達期限超過と各破棄がなく、新しいACK・音声・現在選択した映像入力の生成／送出が進んでいることとする。映像処理停止を回線の回復としない。
- 静止中の安定候補は「低い負荷で試行できる健全性」であって、動画帯域の回復確認ではない。画質増加・動画復帰成功には下記の動画側の条件も必要とする。

### 状態と遷移

| 通信適応状態 | 挙動と次の状態 |
| --- | --- |
| 通常動画 | 通常下限から開始し、通常範囲内で調整する。下限でも混雑が続き弱回線対策オンなら緊急動画へ進む |
| 緊急低ビットレート動画 | 通常下限より低い目標で動く映像を継続する。持続悪化で静止へ、動画の安定で段階的に目標を戻す |
| 静止 | 現在画像を保持して新しい時刻で再エンコードする。新しい安定候補と必要な再試行待ちがそろえば動画復帰試行へ進む |
| 動画復帰試行 | 保持を解除して低い目標で動画を試す。新しい動画の証拠を確認して成功、悪化・期限切れ・証拠不足で静止へ戻る |

- 目標変更、画像保持、保持解除は要求と完了を分け、適用待ちとして管理する。要求しただけで状態の適用成功や実出力量の低下を表示しない。並行する映像操作は世代番号で無効化・直列化する。
- 混雑が500ms継続したら映像目標を30%下げる。低下要求の間隔は最短500msとし、通常動画では通常下限に制限する。下限へ到達した後も混雑が500ms続けば、弱回線対策オンに限り緊急動画へ進む。単発の音声破棄は持続確認を待たず通常下限へ下げ、既に下限なら緊急動画へ進む。この場合も変更要求の500ms間隔は維持し、未処理の破棄イベントを保持して次の変更可能時刻に処理する。
- 緊急動画は250,000bps、静止は150,000bpsを基準とし、実際に選択するハードウェアエンコーダーの対応下限以上に補正する。通常の上下限自体が未対応なら開始を拒否するが、150,000bpsをそのまま使えないことだけでは開始を拒否しない。補正後の緊急動画目標が通常下限以上なら緊急動画段階を省き、通常下限での持続悪化から静止へ進む。
- 緊急動画の目標がAPIに受け付けられた後も混雑が1秒続く、またはその変更後に新しい音声破棄が発生したら静止を要求する。緊急動画を省く構成では通常下限での1秒の持続悪化を使用する。
- 静止では送信映像と同じ向き・構図の最新有効画像をメモリ内で保持する。別の待機画像への自動切替、圧縮済みフレームの単純再送、UIのスクリーンショットは使用しない。カメラ・映像エンコーダーは継続し、映像PTSと音声の時間軸を進める。プレビューを閉じた状態や画面ロック中も動作させる。
- 保持確認の期限は要求から2秒。失敗時は低い目標で現在の動画を継続し、理由を表示する。同じ保持操作の取得失敗に対する再試行は初回を含め最大2回、再要求は失敗から5秒以上あける。保持成功でその取得失敗予算を終了し、動画試行が失敗した後の新しい再保持は別の保持操作として扱う。取得が2回とも失敗した場合は、動画で2秒安定するか明示的に映像を復旧するまで同じ悪化に対する取得を繰り返さない。保持成功だけでは通信の再試行待ち段階をリセットしない。別画像を勝手に送らず、実故障は[映像故障の分離](#映像故障の分離)で扱う。
- 静止後の初回試行には静止後に取得した安定候補の1秒継続を必要とする。試行失敗後は、その失敗後の安定候補1秒と、失敗時刻からの2、4、以後8秒の待ち満了を必要とする。両方が成立した後は最大2秒以内に試行を開始する。成立から開始までに条件を失えば開始しない。
- 待ちの段階をリセットするのは動画復帰試行が成功したとき、または明示停止後の新しい外配信セッションだけとする。静止による滞留解消、新しいACK、時間経過、手動表示切替、再接続だけで短縮・リセットしない。再接続では過去の安定観測を破棄し、待ちの段階を維持する。新しい健全観測が続けば有限の待ち後に再試行でき、同一接続で滞留が最初から0でも永久静止にしない。
- 試行開始は低い動画目標がAPIに受け付けられ、保持解除を要求する時点とし、試行世代・時刻を記録する。目標は補正後の緊急動画値、緊急動画を省く構成では通常下限とする。開始時点から最大5秒で終了させ、保持解除待ちも含める。[混雑判定](#観測と混雑安定の判定)のいずれかが成立した場合は500msの持続を待たず次の観測で中止する。動画生成／送出が1秒進まない場合、欠測・切断も中止し、静止へ戻して失敗を数える。W/2未満の小さな待ちの変動だけでは失敗にしない。再保持失敗時は上記の保持失敗へ従う。
- 成功には、保持解除の適用、新しいカメラフレームの生成と送出、同じ試行世代の動画データまでのACK進行、および安定候補のすべてを必要とする。条件がそろった区間が2秒連続したときだけ成功とする。W/2以上W未満など、安定候補でなく混雑でもない場合は成功の継続時間だけをリセットし、5秒の試行期限は延長しない。静止中に生成したフレームや試行前データへのACK、単なる5秒経過では成功にしない。成功後は現在の低い目標を維持して動画へ戻る。
- 動く映像で安定候補が2秒継続するごとに、現在目標の20%と100,000bpsの小さい方まで増加する。整数bpsへ切り下げ、保存入力の0.1Mbps刻みは実行値に強制しない。通常下限未満では緊急動画として段階的に戻し、通常下限以上になったら通常動画へ移る。上限を超えず、悪化時は増加間隔を待たず直前の安定した目標以下へ戻す。
- 手動非表示では黒／選択済み固定画像を維持し、同じビットレート低下を許すがカメラの保持・復帰試行はしない。低い目標からの増加には当該入力での安定確認を使用し、公開希望を変更しない。明示的にカメラへ戻した場合も現在の低い目標から新しい動画観測を始める。
- 保持画像は動画復帰完了、手動非表示、停止、セッション終了で破棄する。試行のライブ描画が保持テクスチャを上書きする場合は、再悪化時の最新有効画像を保持し直す。カメラ切替・調整は保持適用待ち・静止・復帰試行中は無効とし、同一カメラの調整値は維持する。

### 観測・判断・適用の実装境界

- 観測層は実測事実と有効性、制御層は状態・要求する目標と理由、適用層はエンコーダー／GL操作と結果を所有する。UI・設定保存・ファイル書き出しを制御判断へ混ぜない。外部のQR・状態報告・REST契約は変更しない。
- RootEncoder 2.8.1の撮影・エンコード・MPEG-TS多重化と既存APIの互換を保持し、版・変更表示・ライセンスを記録する。通信には[ネイティブ送受信契約](#ネイティブ送受信契約)のlibsrtを使用し、従来のKotlin SRT通信エンジンを外配信の実行経路で使用しない。
- ビットレート変更に「未稼働／API受付／APIエラー」を返す最小APIを追加する。既存の戻り値なしAPIの正常復帰を受付成功とみなさず、エンコーダー内部の例外・無操作を結果へ反映する。要求目標、最後にAPIが受け付けた目標、実生成量は独立した値として保持する。
- APIエラー・未稼働では自動変更を停止し、最後に受け付けた目標と現在の入力表示を維持して理由を表示する。正常なマイク・AAC・SRTは維持し、映像自体の故障は既存の局所復旧へ渡す。停止解除は利用者の明示再試行または新しい送信開始に限り、単なる回線回復で解除しない。映像が稼働中の明示再試行は最後の受付目標（まだなければ開始目標）のAPI適用をやり直し、受付成功時だけ観測基準を取り直して制御を再開する。未稼働なら局所映像復旧を行い、復旧と目標受付の両方を必要とする。失敗時は停止理由を残し、再試行だけで公開希望・通信の待ち段階をリセットしない。
- API受付は実出力の追従保証ではない。単発のキーフレームピークを変更失敗と断定せず、生成量とピークを別に記録する。生成ビットレートを `映像生成bytesの差分 × 8 × 1000 / 観測窓ms` で求め、受付目標と同じbpsで比較する。補足の初期判定値として、同一受付目標で2秒の追従猶予後、直近2秒窓の生成ビットレートが目標の2倍を超える状態が2秒継続したら「映像量の低下が不十分」と表示し、画質増加を止める。この判定に欠測期間を加えず、同じ換算で目標の2倍以下の新しい窓が2秒継続したら増加抑止を解除する。固定モードは表示だけとする。効果不足だけで復帰試行を永久に禁止せず、静止・有限な復帰試行は各条件に従う。
- 統計は送信・ACK・破棄の更新箇所で集計する。UIスレッドでキュー全体を走査せず、一貫した不変スナップショットを取得する。取得失敗や診断処理の例外は欠測として扱い、送信スレッド・音声・GLを待たせない。

### キーフレームと送信待ち

- 保持画像はスマホの取得画像であり、OBSの最後の受信・表示画像と同一ではない。OBSが復号に必要なデータを欠く場合もある。
- 静止・復帰だけを理由にエンコーダー・音声・SRTを再開始せず、不要なキーフレーム要求を追加しない。再接続・映像codec再準備後には、キーフレームと形式別パラメーター、MPEG-TS情報の生成・送出を検証する。
- 再接続成功時の既存キャッシュ破棄とキーフレーム要求は維持する。要求は500ms内の重複をまとめる。通常の混雑・静止切替に音声を含む全キャッシュ消去を流用せず、映像量をキュー投入前に抑える。
- 静止や150,000bpsの指定だけで実送信量が必ず減るとは保証しない。キーフレーム・再送の瞬間量も観測し、対応範囲の宣言と実際の効果を分ける。

### 映像故障の分離

- カメラ・画像保持・描画・映像エンコーダーの故障を区別する。固定／自動・弱回線対策の選択によらず、映像だけの故障で正常な配信マイク・AAC・SRTを一括解放しない。
- 実カメラ故障では有効な保持画像と正常な映像処理があれば継続し、画像がなければ黒表示を選ぶ。通常の保持失敗とは区別し、カメラ再開は明示操作に限る。
- 映像codecは同時1件・セッション内自動1回まで、映像だけの再準備と5秒以内の新規キーフレーム生成確認を試す。失敗時は音声を維持して明示再試行を案内する。受付や要求発行だけでは復旧成功としない。
- 描画経路の故障も局所表示する。明示再試行では壊れたGL資源と保持画像を再生成し、手動非表示を維持する。カメラ公開を選んでいる場合は現在の低い目標で動画から再評価する。
- 共通送信器・プロセス・OS・権限の異常、明示停止まで継続保証を広げない。許可されないリソースを解放し、サービスや端末の再起動後に自動撮影を開始しない。

## Android操作

- 前面画面の「映像送信開始」で開始する。コメント読み上げの開始停止とは別操作にする。「映像送信停止」は取得・エンコード・送信・再試行を終了する。
- カメラとマイクの権限、通知、選択した品質に対応するカメラ・ハードウェア映像エンコーダー、選択した入力機器を開始前に検証する。未対応時は理由を表示し、ソフトウェア映像エンコードや別品質へ黙って切り替えない。
- 送信操作とカメラプレビューは外配信タブへ配置する。タブと共通状態表示の配置は [Androidクライアント仕様](./android-mobile-client.md#android画面) に従う。プレビューの非表示だけでは送信を停止しない。
- 開始前に縦横とマイクを選択する。利用可能な内蔵・USB・Bluetooth入力だけを列挙し、実際の入力経路を確認する。機器ごとの対応を保証せず、利用不可を明示する。
- 送信音声の時刻は映像・エンコーダーと同じ、端末のスリープ時間を含む単調増加時計を使う。送信中のマイク再選択でも時刻の基準を維持し、切替に要した時間を反映して再開する。切替中の短い音声中断を、その後も残る映像・音声の同期ずれにしない。
- 映像の向きは横向き・縦向きから明示選択する。端末画面の向きにかかわらず、選択した出力の縦横比と回転を一致させ、プレビューと送信映像を縦横に押し潰さない。送信開始後は選択した向きを固定する。
- Bluetooth入力ではAndroidの音声経路を有効化し、接続完了を待ってから入力を検証する。接続確認中を表示し、30秒以内に経路を確立できない場合は利用不可とする。別機器への自動切替はしない。経路はSRT再接続や開始前検証から本録音への移行で解除せず、送信終了または入力変更時に解放する。音声経路制御のため通常権限 `MODIFY_AUDIO_SETTINGS` を宣言する。
- 出力の向きと保存した品質設定は送信中に固定する。自動制御による実行値の変更は[弱回線対策と自動制御](#弱回線対策と自動制御)に従う。前後カメラ切替前に選択形式・設定範囲の対応を確認し、非対応なら切替を拒否して現在の送信を継続する。対応する前後カメラは保持適用待ち・緊急静止・復帰試行中を除き送信中も切替可能とし、短時間の映像中断を許容する。切替失敗時は元のカメラへ復帰を試み、復帰も失敗なら[映像故障の分離](#映像故障の分離)に従う。
- Androidのカメラ・マイク用前面サービスが取得と送信を所有する。前面で開始した後は画面ロック、他アプリ表示、履歴画面からの除去でも継続し、常駐通知に外配信状態と停止操作を表示する。
- サービス終了・プロセス終了・再起動・強制停止後は自動でカメラやマイクを再開しない。画面からの再開始を必要とする。OSによる強制停止後も含む無条件の継続は保証しない。
- Bluetooth等の選択入力が失われた場合は送信音声をミュートし、別マイクへ切り替えない。映像を継続し、配信者が前面画面で入力を再選択・再開するまで無音を維持する。着信等で入力を失った場合も同様に案内する。
- 読み上げ再生をマイク音声へソフトウェアで混合しない。スピーカーからの物理的回り込みを避けるイヤホン利用を案内する。読み上げの音声フォーカス規則は既存仕様を参照する。

## 映像の非表示

- 配信中の「映像を隠す」でカメラ取得を停止し、黒画面または事前に選択した固定画像を同じ形式・解像度・fps・向きで送る。映像の実行中目標値は選択した固定／自動の方針に従う。配信マイク、音量、手動ミュート、SRT接続、再試行、コメント・読み上げを継続する。既に送信済みの映像は受信バッファ分だけ表示が残り得る。
- 設定の「映像を隠したときの表示」で黒画面／固定画像を選ぶ。初期値は黒画面。固定画像はAndroidの選択画面から選び、端末内へ取り込んで見本を表示する。画像の縦横比を保ち、余白は黒、切り抜きはしない。表示方法と取り込んだ画像を端末に保存し、変更は配信停止中に限る。読込・保存失敗は案内し、映像を隠す際に画像を利用できなければ黒画面を維持する。
- 「カメラに戻す」で選択中カメラを再開する。復帰失敗時は映像非表示を維持し、マイクを継続して再操作を案内する。非表示中・切替中はカメラ切替と調整を無効化する。カメラ復帰時の調整値は初期化する。
- 映像非表示はタブ切替・画面再生成・SRT再接続で維持する。非表示状態自体は端末保存せず、新しい外配信はカメラから開始する。配信停止・OS終了後の自動再開は行わない。
- 手動非表示と現在画像による緊急静止は別状態とする。手動非表示は[自動制御の優先順位](#制御の責務と優先順位)に従い、回線回復でカメラへ自動復帰しない。静止移行や復帰試行の処理中も「映像を隠す」と明示停止を受け付け、古い非同期処理を無効にする。
- 端末のプレビューを閉じる操作とは独立する。配置・終了確認は [Android画面](./android-mobile-client.md#android画面) が所有する。PC状態報告とQRの形式は変更しない。

## 配信マイクの音量と手動ミュート

- 音量は0～200%、1%刻み、初期値100%とする。取得したPCMへソフトウェアゲインを適用し、AACエンコード前に反映する。読み上げ音量と端末音量は変更しない。
- 送信音量メーターは調整後のピーク音量を約100ms間隔で表示する。上限を超えるサンプルは飽和処理し、音割れ警告を約1秒保持する。入力段階で既に飽和した音も警告対象とする。
- 手動ミュートでは取得と入力経路の監視を続け、送信音声だけを無音にする。メーターはゼロ、表示は「ミュート中」とする。音量0%は手動ミュートと区別する。
- 入力喪失による無音と手動ミュートを別状態で管理する。手動ミュート解除だけでは入力喪失を解除せず、従来の入力再選択を必要とする。
- 音量だけを端末に保存する。新しい外配信セッションは手動ミュート解除で開始する。同一セッション中のタブ切替、画面再生成、再接続、マイク再選択では音量と手動ミュートを維持する。
- 操作の配置は [Androidクライアント仕様](./android-mobile-client.md#android画面) に従う。

## 通信状態の詳細

通常表示は送信状態・適応状態と短い理由、実送信ビットレートに絞り、詳細は明示操作で開く診断パネルへまとめる。実送信ビットレートは既存のSRT送信器の計測値をMbpsで小数点以下2桁まで表示し、欠測を0で置き換えない。停止中は現在の送信値として表示しない。診断は送信側の観測であり、OBSの受信・表示成功や原因を自動断定しない。画面配置は[Android画面](./android-mobile-client.md#android画面)が所有する。

| 項目 | 計測と表示 |
| --- | --- |
| 実送信ビットレート | SRT送信器の送信バイト差分から算出する。映像生成量、目標値、ACK済み量、回線全体の通信量と区別し、再送を含むかなど集計範囲を明記する |
| SRT往復時間（RTT） | 有効な値をmsで表示する。撮影からOBS表示までの遅延や設定SRT遅延と区別する |
| 再接続試行回数 | 同一外配信セッション内の累計を表示する |
| NAK通知件数 | libsrtが受信したNAK制御パケット数。接続世代内の値とし、要求対象DATA数・固有損失数・損失率と表示しない |
| 制御の現在値 | 固定／自動、弱回線対策、公開希望、通信適応状態、適用待ち、要求目標、API受付結果と最後の受付目標、実映像生成量、停止・抑止理由を分ける |
| 判定に使った観測 | 接続世代、観測窓と有効性、ACKの進行・経過時間、確認済み量、未確認量・最古経過時間、基準RTT、送信前・処理中と音声の待ち、生成／送出量、破棄・再送・キーフレーム量を区別する |
| 復帰試行 | 安定確認、再試行の待ち、試行世代、開始・期限、成功条件の充足状況を表示する。次に試せる時刻とOBSで動く時刻を混同しない |

- UI要約・詳細・制御・診断履歴は同じ観測スナップショットと判断結果を使う。最新の有効値に欠測値を混ぜず、未計測・比較基準待ち・取得失敗・世代変更・停止を区別する。無効な差分を0と表示しない。
- ビットレートはbps、量はbytes、待ち・観測時刻はmsを内部単位とする。画面のkbps・Mbps等への変換は表示だけで行う。累計値には接続世代またはセッションの集計範囲を付ける。
- 計測と履歴を有効にしてもSRT映像へ診断値を描かず、PC状態報告・QR・RESTへ追加しない。任意の映像時刻表示は[別設定](#診断用の映像時刻表示)とする。診断表示の開閉で計測や制御を開始・停止しない。

### 数値履歴と明示的な書き出し

- 送信中は最新5分までの数値・状態履歴を端末メモリに保持する。観測は250msごと最大1,200件、状態・適用結果のイベントは最大1,200件とし、時間または件数の上限を超えた古いものから破棄する。上限による欠落は件数で示す。映像・音声・保持画像は履歴に含めない。
- 停止時はそのセッションの履歴を残し、次の送信開始またはアプリ終了で破棄する。送信中も停止後も利用者が「数値診断を書き出す」を操作した場合だけ、操作時点の不変コピーをJSONとして保存する。常時のディスク記録、自動送信、自動共有は行わない。
- 書き出しはAndroidの保存先選択を使用し、ネイティブ側で行う。WebViewへファイル権限を渡さない。キャンセルや保存失敗で元の履歴を消さず、再試行を許す。書き出し中の計測・送信を待たせず、重複保存操作は無効にして処理中を示す。アプリ終了をまたぐ履歴保持は保証しない。
- JSONは形式版 `schemaVersion`、アプリ版、制御方式の版、実観測／試験入力の別、送信品質の条件、観測列、状態・適用イベント列を持つ。時刻はセッション開始からの単調増加時間とし、端末の壁時計に依存しない。接続世代、観測有効性と欠測理由、判定理由、要求とAPI結果を復元できるようにする。
- 品質条件は選択映像形式・実エンコーダーのコンポーネント名、縦横・解像度・fps、固定／自動・弱回線対策、固定値・通常上下限・補正後の緊急目標、音声ビットレート・キーフレーム間隔・SRT遅延・時刻表示の有無に限定する。動的制御の受付と実効性の分析に必要な範囲だけを記録する。
- 許可した固定フィールドだけを組み立てて保存する。接続先IP・URL・ポート・ホスト名、登録ID・トークン・パスフレーズ、コメント本文、利用者が付けた機器名、端末識別子、画像・音声、任意の例外文字列・スタックトレースを含めない。理由は固定の列挙コードとし、秘密が混入し得る設定・例外オブジェクトを丸ごと直列化しない。
- 新版を読めない解析側は形式非対応を示し、欠測・未知の理由を成功に変換しない。履歴がない場合は書き出しを無効にして理由を示す。履歴の取得・書き出し失敗だけで映像・音声・コメント機能を停止しない。

## カメラの調整

- ズーム、タップによるピント合わせ、露出補正、ライトは送信開始後に操作可能とし、通常動画の再接続中も利用できる。手動非表示、保持適用待ち・緊急静止・復帰試行、映像故障中の制限はそれぞれの節に従う。送信前のカメラプレビュー開始操作は追加しない。
- ズームと露出補正は端末の対応範囲を取得し、範囲内で操作する。露出は自動露出に対する補正とし、シャッター速度・ISOの手動設定は含めない。
- プレビューの映像部分をタップすると、その位置へピントを合わせる。余白のタップは無視し、向き、前後カメラ、表示拡縮を考慮する。対応端末では約3秒後に連続オートフォーカスへ戻す。
- ライトは連続点灯として扱う。非対応操作は理由付きで無効表示し、ライト非搭載の前面カメラでは画面照明などで代替しない。
- 新規配信と前後カメラ切替では、ズームを端末の標準値、露出補正を0、ピントを標準動作、ライトを消灯へ戻す。調整値は永続化しない。
- 同一カメラのタブ切替、画面再生成、通信再接続では調整を維持する。送信停止時にライトも消灯する。
- 調整操作の失敗だけでは送信を停止せず、失敗を表示する。カメラ自体が継続不能な場合は[映像故障の分離](#映像故障の分離)に従う。緊急静止・復帰試行中の調整操作制限は[自動制御](#状態と遷移)に従う。
- 操作の配置は [Androidクライアント仕様](./android-mobile-client.md#android画面) に従う。

## 状態報告と公開境界

- 状態は `stopped`（停止）、`preparing`（準備中）、`connecting`（接続中）、`sending`（送信中）、`reconnecting`（再接続中）、`actionRequired`（操作が必要）とする。
- `sending` はSRT接続が成立して現在のデータを送信できていることを表す。OBSのデコード、表示、配信サイトでの公開成功を意味しない。OBS表示状態は「未確認」と明示する。
- 通信適応と映像だけの故障詳細はAndroid内に表示し、状態報告形式版1へ新フィールド・新エラーコードを追加しない。静止または映像局所故障中でも音声等のデータを送信できていれば送信状態と局所故障を別に扱い、局所故障だけを理由に全体を停止・`actionRequired`にしない。
- 外配信状態と受信進行は[認証付き制御プロトコル](./smartphone-transport.md#認証付き制御プロトコル版2)で送受信する。用途別認証、公開境界、送信間隔、切断時の扱いは同仕様に従う。
- 報告の形式版は `1`。登録ID、設定リビジョン、外配信セッションID、連番、状態、マイクの有効・ミュート状態、安定したエラーコードを含める。映像・音声・コメント・秘密情報・任意のエラー本文は含めない。
- 報告するマイク状態は実効的な有効／無音状態とする。手動ミュート、音量0%、入力喪失では `muted` を報告する。正常な入力で音量が0%より大きく、手動ミュートが解除されている場合は `enabled` とする。Android内の手動ミュート理由や詳細数値を新しい通信フィールドとして追加しない。
- 正常報告は状態変化時と再接続時、最大4KB。PCは登録と版を検証し、同じセッションの古い連番を無視する。新しいセッションを採用した後は古いセッションへ戻さない。対象端末・対象ネットワークの現行以外の登録は拒否する。端末ごとにセッション・連番・鮮度を独立管理する。
- PCは報告と共有接続の健全性で鮮度を判断する。該当端末の状態購読が失われたら「状態不明」とし、最後の状態と確認時刻を添える。停止を推測しない。再接続時は過去イベントではなく現在状態だけを報告する。
- Androidは状態報告の成否を映像状態と別に表示する。PCへ報告できなくても、保存済み設定によるOBSへの送信・再接続・停止を利用できる。
- PCの管理用スナップショットに秘密情報を除いた外配信状態を追加し、状態変更を管理画面へ通知する。コメント・OBS向けスナップショットには追加しない。
- 外配信topicは状態報告と受信進行の確認に限定する。同じ待受ポートの認証付き自動登録は[スマホ連携仕様](./smartphone-integration.md)が所有する。遠隔設定変更、映像開始停止命令、一般管理API、ファイル取得は提供しない。設定管理とQR発行は既存のループバック操作トークン・Origin・Host保護下で行う。

## 再接続とエラー

- 開始前からPC受信へ接続できない場合は接続中、接続成立後の断では再接続中とする。再試行は0.5、1、2秒へ増加し、最大2秒を維持する。ネットワーク変更検出時は早期に再試行できる。
- 通信断とSRT再試行だけではカメラ・配信マイク・エンコーダーを終了または再準備せず、現在の映像表示を維持する。手動非表示はカメラ停止を維持し、自動の低下・静止は[自動制御](#弱回線対策と自動制御)に従う。配信マイク状態は実際の入力経路・入力喪失に基づき、通信断だけで入力未確認・無音へ切り替えない。明示停止とOS・入力機器に起因するエラーの扱いは従来どおりとする。
- SRT再接続時は古いアプリ内送信待ちを破棄し、現在選択中の入力から新しい時刻の映像・音声を生成して送る。緊急静止中は保持画像、手動非表示中はその黒／固定画像を維持し、回復判定前に動画へ戻さない。既存の接続成功時キーフレーム要求は[キーフレームと送信待ち](#キーフレームと送信待ち)に従う。SRT自身の遅延バッファは使用するが、切断中の録画・後送はしない。
- 権限拒否、選択品質未対応、カメラ開始失敗、前面サービス開始拒否は操作が必要として開始を完了しない。OSが入力継続を認めない場合はリソースを解放する。
- 接続タイムアウトからPC未起動、ファイアウォール、ポート違いを断定しない。PCの受信設定、選択経路の接続・受信許可を確認する。直接接続では[原因分類と復旧限界](./smartphone-direct-connection.md#direct-recovery)を適用する。PC受信後のOBS未表示はOBS入力を確認する。認証失敗等は取得できる場合だけ個別表示する。
- 発熱・低電池は取得可能なOS状態に基づき案内する。通信への自動適応とは分離し、発熱だけを理由に独自の品質変更はしない。OSが継続を拒否した場合は対象リソースを解放し、継続できない機能に操作が必要と表示する。サービス全体を継続できない場合は停止する。
- PC状態受付、映像送信、コメント取得、読み上げ、WebViewを独立して失敗させる。状態報告再試行で映像送信スレッドを待たせない。

## OBS設定案内

- 現行の入力形式・URLは[ネイティブ送受信契約](#ネイティブ送受信契約)に従う。既存利用者にはSRT ListenerからローカルUDPへの入力変更を一度だけ案内し、OBSを自動変更しない。
- AndroidのSRT遅延バッファは要求値であり、撮影からOBS表示までの総遅延ではない。PCワーカーでSRTを受信した後にも、OBSのネットワークバッファ・復号・表示の遅延が加わることを説明する。
- 解像度・fps変更後は、配信者がOBSで受信と画面内の配置を確認する。

- 配信者がOBSでメディアソースを一度作成し、ローカルファイルをオフ、入力形式を `mpegts` にする。端末別のループバックUDP入力をPC画面からコピーできる。SRTのパスフレーズと暗号鍵長はAndroid・PCワーカーが管理する。
- OBS入力のコピーには秘密を含めない。SRTのパスフレーズ不一致・未暗号化送信の拒否を受け入れ試験で確認する。
- OBSの非表示時にソースを閉じる設定を無効にする手順と、Windowsファイアウォールで対象スマホからのSRT受信を許可する手順を案内する。LAN／Tailscaleではルーターの公開ポート転送を要求しない。直接接続の開放・Windows規則は[直接接続仕様](./smartphone-direct-connection.md#自動開放と手動設定)に従い、OBS入力を公開しない。
- OBS入力の登録設定の読戻し確認は[OBSソース登録](./obs-source-registration.md)の明示操作に限って行う。映像表示をアプリから自動確認しない。PCの実受信やOBS操作による接続・配信状態の確認は映像表示成功を意味しない。実際の映像と音声メーターを配信者が確認する。

## テスト・受け入れ条件

以下は既存機能も含む回帰確認の観点である。今回の自動制御再設計の必須実機範囲と完了判定は[再設計版の受け入れ条件](#自動制御の再設計版の受け入れ条件)に一本化する。一般項目にある各品質・各経路の確認を、今回の複数機種・全構成の実機試験要求として重ねない。実機未確認の構成は未確認として残す。

1. QRの登録・再登録・版不一致・欠落・不正IP・不正ポートを検証し、拒否で既存登録を壊さない。コメントQRは従来どおり動作する。
2. 初期無効、保存と再起動、秘密情報の保護・復元失敗、設定変更後のOBS更新・再登録案内を確認する。
3. 認証なし・誤認証・別端末の登録・別Host・非選択経路・過大要求を拒否し、管理APIや秘密情報を外部へ公開しない。
4. 連番逆転、旧セッション、PC再起動、報告途絶と復帰で、送信中を誤って維持せず状態不明を表示する。
5. 偽のSRT相手と偽のPCを用い、開始停止、切断再接続、停止後の再試行抑止、報告失敗でも映像が継続することを確認する。
6. OBS実機で固定メディアソース、縦横、映像・AAC音声、暗号化、不正パスフレーズ・未暗号化の拒否、再接続を検証する。
7. ロック、他アプリ、履歴除去、Wi-Fi／携帯回線切替、Tailscale断復帰、direct／リレーについてサービス・接続の回帰を検証する。複数機種・長時間の実機確認は追加検証として実施構成を記録し、今回の再設計の必須条件にはしない。
8. 権限拒否、通知拒否、エンコーダー未対応、カメラ切替失敗、着信、Bluetooth切断、マイク再選択、発熱・低電池を検証する。
9. 同時のコメント一覧・読み上げを確認し、一方の停止・障害が他方を停止させない。プロセス終了・端末再起動後に撮影を自動開始しない。
10. QRや資格情報、コメント、映像・音声がログ、状態イベント、クラッシュレポートへ流出しないことを確認する。
11. 音量0・100・200%、飽和処理、入力段階の飽和検知、メーター更新、警告保持、手動ミュートと入力喪失の組み合わせを検証する。手動ミュート解除で入力喪失を解除しない。
12. 音量の保存、新規配信時の手動ミュート初期化、タブ切替・画面再生成・再接続・マイク再選択での設定維持と、PCへの実効的なマイク状態報告を確認する。
13. 偽の計測値で通信数値の単位・差分計算・未取得表示・再接続時の更新を検証する。RTTをOBS表示遅延、NAKの再送要求パケット数を損失率として扱わず、PCの通信契約も変更しない。
14. カメラ操作の対応／非対応、操作範囲、プレビューのタップ座標・余白、連続オートフォーカスへの復帰、前後切替時の初期化、通信再接続中の維持、停止時のライト消灯を検証する。調整失敗だけで送信を止めない。
15. 実機でOBS音声への音量・ミュートの反映、読み上げとの独立性、Tailscale断復帰中の取得継続、屋外の明暗・撮影距離に応じたカメラ操作を確認する。
16. 品質設定の各境界値、プリセット、個別調整後のカスタム表示、保存・復元、QR再登録時の品質保持を検証する。
17. 現行共通招待・登録応答だけを受理し、旧QR・旧登録は拒否または退避して未登録にする。非対応版の更新案内、不正QR拒否、現行IDと品質の保持、状態報告形式版1の維持を確認する。
18. 非対応の解像度・fps・ビットレートと組み合わせを拒否し、非対応カメラへの切替を拒否して現在の送信を継続することを検証する。
19. 送信中・再接続中の利用者による品質設定編集の禁止、保存値の維持、許可した自動制御だけの実行値変更、再接続時の低下・静止・手動非表示の維持、古い送信待ちの破棄を検証する。
20. OBS実機で縦横・各品質の映像とAAC音声、AndroidとOBSの遅延設定の組み合わせ、対応端末での1080p・60fpsの継続動作を確認する。既存OBS入力設定の更新案内と、解像度・fps変更後の配置確認も検証する。

自動テストは公開通信契約と配信者の操作から確認する。実装時はWindowsのlint・型チェック・テスト・`pnpm build`、Androidの単体テスト・lint・デバッグ用コンパイルを実行する。配布物は明示的な依頼がある場合だけ生成する。

直接接続の追加では[直接接続の受け入れ条件](./smartphone-direct-connection.md#受け入れ条件と実装段階の検証)も必須。IPv4／IPv6の実SRT暗号化・未暗号化拒否、公開／内部UDPポート相違、アドレス別受信失敗、TCP断だけで正常SRTが止まらないこと、複数端末と固定OBS入力の保持を検証する。既存の品質・自動制御・時計・音声の契約と検証結果は維持する。

### 自動制御の再設計版の受け入れ条件

今回の再設計は、自動テストと普段使うAndroid端末1台・映像形式1つ・品質構成1つでの短い実機確認を完了条件とする。利用者によるOBS／スマホの録画、録画編集・照合・提出、複数機種の長時間試験、音声欠落・遅延の精密測定を必須にしない。録画を依頼しないことは、未検証の性能を保証することではない。

#### 自動テスト

| 対象 | 必須の確認 |
| --- | --- |
| 設定と互換性 | H.264／HEVCの個別対応、固定／自動、弱回線対策オフ、`audioFirst`の保持、品質保存版1、完全な未版付き品質の同値取込、既知の不完全旧品質の退避・初期化、未知版・破損・保存失敗の保全。音量と登録を保持し、制御値を保存へ書き戻さない |
| 観測 | 接続世代・取得時刻・欠測・遅延・累計後退・連番周回、重複／逆順／期限切れによる削除と真のACK進行の区別、送信前／処理中／未確認の滞留。主キューが0でも未ACKが積み上がるケース |
| 混雑と回復 | 各閾値の直前・一致・直後、単発と持続、ACK停止、RTT単独高値、長時間混雑でも基準RTTが引き上がらないこと、再接続で新しい観測を取り直すこと |
| 状態遷移 | 通常低下→緊急動画→静止→試行→動画→段階増加。補正された緊急値と段階省略、固定では無介入、自動＋オフでは通常範囲外へ進まないこと |
| 試行の寿命 | 静止後／失敗後の新しい観測、条件成立から開始までの上限、試行全体の期限、W以上の待ち・各破棄・欠測・切断による中止。W/2未満の揺らぎでは失敗せず、W/2以上W未満では成功時間だけをリセットする。保持解除待ちも期限に含める |
| 試行の成功 | 新規ライブフレームの生成・送出とそのデータへのACKが必要。古い静止フレームのACKや時間経過だけでは成功せず、全条件が連続して成立すること |
| 再試行 | 失敗を繰り返した後の待ち段階と上限、静止による滞留解消・ACK・手動表示切替・再接続ではリセットされないこと。保持成功と動画試行失敗を3回以上繰り返しても毎回静止へ退避できること。静止負荷なら健全なまま回線容量だけが改善した場合も有限の待ちで試行できること |
| エンコーダー | 未稼働・API例外・受付成功だが実出力不変、遅れた追従、実量の超過、キーフレーム集中。要求・受付・実量の区別、窓のbytesからbpsへの換算と増加抑止／解除の境界、明示再試行の成功／失敗、対応範囲だけで実効性を合格にしないこと |
| 適用と故障 | GL保持／解除の遅延・失敗と回数上限、向き・鏡像・クロップ・PTS、カメラ／描画／codec故障を分離。古いコールバックで停止・手動非表示・権限失効を覆さず、正常なマイク・AAC・SRTを一括再開始しない |
| 送信と診断 | 再接続時だけの既存キャッシュ破棄、キーフレーム要求の重複抑制、UIと同じ観測、リング上限・停止後保持・次回開始時破棄、JSON版と単位、保存失敗／キャンセル／書き出し中の送信、許可フィールド外や秘密情報の非混入 |
| 画面と回帰 | 手動非表示・ミュート・マイク喪失・コメント読み上げの独立性、状態・欠測・エラーの識別、通知と結果による位置・スクロール・フォーカスの維持、文字拡大、プレビュー・画面再生成 |

- 制御器だけに成功する観測を与える試験に加え、送信量と混雑が制御へ返る閉ループ試験を作る。仮想時計、回線モデル、独立したエンコーダーモデルを使い、帯域急落・回復・揺らぎ・完全断・長時間の低帯域を再現する。
- エンコーダーモデルは要求目標をそのまま実生成量とせず、反応遅延・変更無視・オーバーシュート・キーフレーム集中を独立に与える。主キュー、処理中、未ACK、期限切れ、音声待ちを動かし、制御対象からの反作用を検証する。期待値を実装内部の状態名だけに合わせず、映像操作・送信・音声保護・有限な待ちという外部挙動で確認する。
- Androidの単体テスト・lint・デバッグ用コンパイルに加え、ローカル化した各RootEncoderモジュールのビルド・既存API互換・依存重複クラスを確認する。Windows側も運用手順に従い `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build` を実行し、全体テストとビルドを同時に走らせない。配布物生成は別の明示依頼時だけとする。

#### 録画なしの短い実機確認

1. 開発側が普段の端末・OBS・選択映像形式と品質1構成を記録し、数分で実行できる検証用の観測入力シナリオを準備する。試験入力の入口は開発用ビルドに限定し、製品の通常制御へ混入させない。記録する数値にも試験入力を明示する。
2. 実際のカメラ・映像エンコーダー・GL・配信マイク・SRT・OBSを使用し、制御への観測入力を通じて「低下→静止→動画復帰」を一度実行する。状態を直接書き換えて成功にしない。端末の状態表示とOBSの静止・動き、音声継続をその場で目視・聴取する。マイクメーターだけで音声確認を代替しない。
3. 同じ短い確認内で手動非表示・ミュート・停止が優先されることを確認し、任意の数値JSONを書き出せることを確認する。記録は実施構成・結果・未確認点の短いメモでよく、利用者へ録画作業を求めない。
4. 実観測を併記した数値履歴で要求とAPI受付、映像生成、保持／解除の結果を確認する。試験入力を使った遷移確認は、実回線の混雑判定・回復性能の実証とは区別する。実回線での追加確認ができた場合だけ、その条件と観測結果を別に記録する。

#### 完了の区別

- **仕様完了**: 本書と関連文書が整合し、独立レビューの重大な指摘を解消した状態。製品機能の完成ではない。
- **実装・必須確認完了**: 再設計版の実装、自動テスト、全体検証、上記の短い実機確認を満たした状態。実機確認ができなければ、その項目は未完了と明記する。
- 他端末・他形式・全品質の組み合わせ、長時間運用、厳密な音声欠落／遅延量、OBSでの復帰秒数は確認した範囲だけを記録する。1台での成功を全端末・全回線の性能保証へ広げない。静止からの試行開始目標は送信側の条件成立を起点とし、物理的な回線回復やOBS表示の回復時間を合格条件へすり替えない。

## 他機能と対象外

### 実装上の通信フィールドと保存

版2 QRのフィールド名は `type`、`version`、`registrationId`、`revision`、`address`、`obsPort`、`statusPort`、`passphrase`、`token` とする。登録IDは英数字・ハイフンの1～64文字、リビジョンは正の安全な整数、トークンは256ビットの乱数を64文字の小文字16進数で表現する。


状態報告は `version`、`registrationId`、`revision`、`sessionId`、`sequence`、`status`、`microphone`、`errorCode` だけを受理する。セッションIDは英数字・ハイフンの1～64文字、連番は非負の安全な整数。マイク値は `enabled` / `muted`。エラーコードは `NONE`、`PERMISSION_REQUIRED`、`QUALITY_UNSUPPORTED`、`CAMERA_FAILED`、`SERVICE_FAILED`、`INPUT_LOST`、`CONNECTION_FAILED`、`AUTH_FAILED`、`OS_STOPPED` とする。正常受付と無視した旧報告は204、不正な内容は400、境界・認証違反は403、他の経路は404で返す。

現行のPC管理操作・状態は[スマホ連携仕様](./smartphone-integration.md#管理apiと状態)が所有する。旧外配信の管理APIから独立した公開やQR発行はできない。

旧Windows保存のoutdoor.protectedは退避対象とし、資格を引き継がない。現行PCの保護台帳はスマホ連携仕様、AndroidのKeystore・noBackup・AtomicFile保存と復元失敗時の保持はAndroidクライアント仕様に従う。
