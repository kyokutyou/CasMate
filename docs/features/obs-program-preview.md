# スマホからのOBS映像確認

2026-10-14採用。OBSの本番シーンをAndroidから静止画で確認する機能の画面・撮影・寿命を所有する。OBS接続・Android操作許可は[OBS操作](./obs-control.md)、登録は[スマホ連携](./smartphone-integration.md)、認証付き制御接続は[通信仕様](./smartphone-transport.md)を共用する。AIリスナーの指定ソース撮影とは独立する。

## 画面と操作

- Androidの「送信・配信」から「OBS映像を確認」を開く。開く操作で未送信のOBS操作確認を取り消し、画像を1枚取得する。以後は「更新」を押したときだけ撮影する。画面の再生成、再接続、復帰で自動撮影しない。
- 確認画面には画像、シーン名、PC側の取得時刻、「更新」「閉じる」を表示する。縦横比を維持して画像全体を表示し、画像領域と状態領域の寸法を結果の有無で変更しない。状態・長文は確保した領域の内部でスクロールできる。ライト／ダーク、小画面、文字2倍でも両操作を利用できる。成功トーストを追加しない。
- OBS連携、AndroidからのOBS操作の許可、選択経路の登録資格が必要。スマホ送信・OBS配信の開始は条件にしない。無効な操作は理由を表示する。対応機能を通知しない旧PCでは「PC版を更新してください」と案内し、既存機能を維持する。
- 取得中は「更新」を無効にし、前の画像を消す。失敗時に前の成功画像を最新として表示しない。更新で撮影時刻を捏造しない。
- 閉じる、背景移行、接続／購読世代・接続先変更、登録失効、OBS切断、利用許可OFFで撮影と受信を取り消し、画像を破棄する。復帰後の取得は明示的な更新だけとする。映像送信・読み上げ・OBS配信を停止しない。

## 撮影と寿命

- PCだけが既存の認証付きループバックOBS接続を使う。`GetCurrentProgramScene`で取得したシーン全体を`GetSourceScreenshot`で撮影する。スタジオモードの編集中プレビュー、スマホ送信側プレビュー、AIの指定ソースに置き換えない。シーン名・UUIDはPCが解決し、Androidから任意ソースを指定させない。
- JPEG、縦横比維持、長辺最大1280px、圧縮品質75、画像本体最大2MiB、小画像の拡大なし。OBSの基本キャンバス寸法に基づいて縮小し、形式・寸法・容量を検証する。撮影前後のシーン・コレクションと接続・映像世代が一致しなければ破棄する。黒映像も正常な画像として表示する。
- PCの撮影全体を最大5秒、Androidの要求から受信・画像検証までを最大10秒で打ち切る。PC全体で同時撮影1件、制御接続ごとに画像転送1件とし、競合は待ち行列へ入れず再操作を案内する。失敗・取消を自動再取得しない。
- 画像は撮影・転送・表示に必要な間だけメモリーで保持する。ディスク、通常ログ、画像履歴、共有記憶、AIサービスへ保存／送信しない。OBS配信開始・終了、シーン変更、録画を要求しない。
- 確認対象はOBS本番シーンの取得時点の静止画。切替エフェクト途中、エンコード後の画質、配信サイト到達、動画の動きや停止、音声品質の判定は保証しない。

## 追加通信契約

- 制御版3の`control.hello.payload.capabilities`へ任意の文字列配列を追加し、対応PCは`obs.captureProgram`を含める。版2へは追加しない。旧Androidは任意項目を無視でき、新Androidは欠落時に撮影要求を送らない。登録・招待・保存の版と資格を変更しない。
- `obs.captureProgram`は既存の要求IDと購読generation、空オブジェクトのpayloadを持つ。版3、OBS購読、同じ端末・経路の更新／OBS資格、現在のOBS連携・Android操作許可を要求受付から転送完了まで検証する。
- 成功の`control.result.payload.payload`は`imageId, sceneName, capturedAt, width, height, byteLength, mimeType`。imageIdは18バイト乱数の24文字base64url、capturedAtはPC撮影時のISO日時、mimeTypeは`image/jpeg`。画像本体をJSONへ含めず、既存の32KiB JSON上限と8KiB受信要求上限を維持する。
- バイナリは36バイトのヘッダーと最大16KiBのJPEG断片。ヘッダーは先頭32ビットbig endian `0x434d4931`、32ビット購読generation、32ビットoffset、24バイトASCII imageId。同じ接続の成功メタデータが届いた画像だけを順番に組み立てる。未知ID、旧世代、重複・欠落offset、過大サイズ、画像検証失敗を破棄する。
- `obs.cancelCapture`は同じ購読generationとpayload `{requestId}`を持つ取消通知。自分の制御接続の一致する撮影／転送だけを取り消す。応答を待たず、再撮影しない。
- Androidは受理した断片の末尾offsetを`obs.imageAck`のpayload `{imageId, offset}`で返す。PCは一致する確認を待って次の断片を送り、最初1KiB・以後256バイト〜4KiBで実測の到着確認時間から約250ms以内の送出量に調整する。任意の最大16KiBより小さい断片を使用できる。誤ID・offset・世代の確認で先へ進めない。Androidは画像専用の256KiB／16件の受信予算を使い、超過は画像要求だけを失敗させ、制御JSONの受信予算を消費しない。
- PCは断片ごとに送信完了を待ちイベントループへ戻す。転送で無制限の送信キューを作らず、バックプレッシャー中も制御応答・ハートビートを維持する。要求全体10秒で画像転送を取り消す。画像の失敗だけで健全な制御接続・SRT・コメント・読み上げを停止しない。

## 検証・受け入れ条件

- 本番／プレビューの区別、シーン全体の合成、横／縦キャンバス、小画像、黒映像、配信前の取得、画像不正・過大、シーン／コレクション／接続変更、撮影期限、同時要求を検証する。
- 全経路の用途別認証とOBS操作許可、旧PC／Android互換、資格失効、取消、購読変更、欠落・重複・旧世代・過大断片、転送期限、遅い回線での制御応答を検証する。
- Androidの画面開閉、更新、背景／復帰、再生成、接続先変更、旧画像の破棄と手動再取得、両配色・小画面・文字2倍で操作位置保持を確認する。
- Windowsのlint・型チェック・全体テスト・`pnpm build`、Androidの単体テスト・lint・デバッグ用コンパイルを実行する。仕様との一致と故障時の影響を別々にレビューする。
- 実OBSとAndroidでLAN・Tailscale・直接接続、スタジオモード、コメント・手書き・非表示映像の合成、送信・読み上げとの同時利用を確認する。未確認経路・条件は明示し、過去の検証を今回の完了根拠にしない。配布物は明示依頼がある場合だけ生成する。
