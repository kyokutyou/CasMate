# コメントフィルター UI・UX 比較見本

2026-09-16。コメントフィルターの設定を、情報の順序と編集操作から再構成した3案。同日、配信者がA案「編集＋確認」を採用した。正式仕様は [コメントフィルター仕様](../../docs/features/comment-filter.md)、本体への反映は [実装・検証記録](../../docs/validation/comment-filter-ui-2026-09-16.md) を参照する。このディレクトリ自体は比較資料であり、すべてメモリ内の模擬操作で、更新すると初期状態に戻る。

## 起動

```powershell
node node_modules/vite/bin/vite.js --config prototypes/comment-filter-ui-throwaway/vite.config.mts
```

[プレビュー](http://127.0.0.1:5195/?variant=A)。画面下部のA・B・Cで切り替える。左右の矢印ボタン・キーでも循環し、選択をURLへ反映する。入力欄・選択欄・警告モーダルの操作中は矢印キーによる案切替を行わない。入力・未反映値・サンプルは案切替やホーム／設定一覧との往復で保持する。

## 比較する問い

「まとめて調整してすぐ確認」「登録済みを一件ずつ管理」「初回に順を追って設定」のどの流れが使いやすいか。

| 案 | 主な構成 | 利点 | トレードオフ |
| --- | --- | --- | --- |
| [A：編集＋確認](http://127.0.0.1:5195/?variant=A)（推奨） | NGワード・アスキーアート判定を左、判定テストを右に配置 | 条件を変えながらその場で確認できる | 狭い画面では縦に並ぶためスクロールが増える |
| [B：ワード管理](http://127.0.0.1:5195/?variant=B) | NGワード一覧を中心に、検索・追加・削除・まとめて編集。アスキーアート判定とテストは切替 | 多数の登録を一件ずつ見直しやすい | 設定全体を見渡すには切替が必要 |
| [C：順番に設定](http://127.0.0.1:5195/?variant=C) | NGワード、アスキーアート判定、確認の3手順 | 初回の判断順序が分かりやすい | 日常の微調整には操作数が増える |

## 見本の範囲

- 既存のホーム／設定の枠組み、スリムスイッチ、ヘッダー内トーストを使用する。
- 投稿者名・本文、部分一致、全角半角、アスキーアートの意味を判断できる説明とサンプルを置く。
- 判定テストは本体の純粋関数 `blocksComment` / `isAsciiArt` を使用する。外部接続・実設定保存・コメントの受信や投稿・読み上げ・診断ログへの送信は行わない。
- 状態選択で設定済み、未登録、60件登録、次の編集時の保存失敗を再現する。失敗時は編集値と直前の適用値を保持し、「要確認」から模擬復旧できる。
- 入力500ms後・スイッチ即時の模擬反映。本文の条件付き通知挿入を避け、成功通知はヘッダー内で4秒表示する。失敗は要確認へ集約し、自動消去しない。
- Bの一件追加・検索・削除、全案の判定テストはUI提案であり、正式採用された追加機能ではない。保存の実装も比較用で、本体へコピーしない。
- 状態JSONと比較操作は検証専用。比較バーは開発モードでのみ表示する。

## 正式仕様との関係

機能契約は [コメントフィルター仕様](../../docs/features/comment-filter.md)、共通レイアウト・通知は [管理画面仕様](../../docs/features/management-screen.md)、保存は [ローカルアプリケーション仕様](../../docs/features/local-application.md#設定保存)、用語は [CONTEXT.md](../../CONTEXT.md) を参照する。

A案の採用内容と判定テストの契約はコメントフィルター仕様で定義してから本体へ反映した。本体の表示・取得・除外契約は変更していない。正式仕様を複数文書へ重複記載しない。

既存の作業中の変更を保護するため、独立したthrowawayディレクトリに置き、ブランチ切替・コミット・既存ファイルの変更はしていない。本体のエントリーポイントからは参照されない。
