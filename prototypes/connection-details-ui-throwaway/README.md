# 接続の詳細設定 · 4案の比較見本

2026-10-08。採用案を選ぶために作成した比較見本。同日、3案「接続経路図」を採用し、[正式仕様](../../docs/features/smartphone-integration.md#接続の詳細設定)に従って製品側の保存・状態へ接続して実装した。このディレクトリは4案の比較時の資料として保持する。SVGアイコンと実受信先の表示は製品側で仕上げており、比較見本の模擬状態は製品の実状態を示さない。

| 案 | 構成 | 向く操作 | トレードオフ |
| --- | --- | --- | --- |
| 目的別タブ（推奨） | 接続設定／準備状況／保守 | 日常の設定変更と問題確認 | 設定値と状態の同時比較には切替が必要 |
| 手順ガイド | PC／ルーター／受信確認／保守 | 初回の直接接続準備 | 慣れた利用者には移動が増える |
| 接続経路図 | スマホ→ルーター→PCを選んで編集 | 公開側と内部側の対応の理解 | 複数端末の詳細は下の状態一覧で見る |
| 設定一覧 | 左に設定、右に通信ごとの状態 | 値を見ながら診断 | 狭い幅では状態が下へ回る |

主な変更は、公開IPと公開ポートを別々の欄へ分離し、TCP共通入口と端末別UDP、公開側と内部側、PC待受・Windows許可・開放・実接続を区別すること。保守操作は通常の設定から分ける。LAN／Tailscaleには必要なTCP設定だけを表示する。

入力、方式、表示経路、候補追加、手動設定確認、受信再試行、残存確認、鍵再生成の確認画面を操作できる。表示経路の切替だけでは接続ON／OFFを変更しない。入力を500ms後に模擬保存し、失敗でも下書きと直前の保存値を保持する。保存完了では本文を再生成せず、ヘッダー内の通知だけを更新する。状態選択で受信・部分失敗・自動化未対応・保存失敗・残存・未登録を再現する。

アドレスはRFC 5737／RFC 3849の架空例で、実接続には使えない。見本の入力検証は形式確認だけであり、製品の公開アドレス・候補重複・選択インターフェース照合の検証を代替しない。再試行は処理終了を再現し、設定成功・到達成功への強制置換をしない。外部接続・API呼出し・実保存・OS権限要求・ルーター操作・OBS操作・テレメトリーはない。内部状態は比較・検証用で製品へ含めない。

正式契約は [スマホ連携](../../docs/features/smartphone-integration.md#pc管理画面)、[直接接続](../../docs/features/smartphone-direct-connection.md)、[共通レイアウトと通知](../../docs/features/management-screen.md)、[自動保存](../../docs/features/local-application.md#設定保存)を参照する。比較の採用は通信仕様の変更を意味しない。
