# Androidきゃすメイト UI・UX 4案の比較見本

2026-10-07作成。現在のAndroid画面をゼロから見直すための独立したthrowaway試作。4案はいずれも未採用で、正式仕様や製品実装の置き換えではない。採用案を決めた後、[Androidクライアント仕様](../../docs/features/android-mobile-client.md)を更新して製品へ反映する。

```powershell
node node_modules/vite/bin/vite.js --config prototypes/android-ui-throwaway/vite.config.mts
```

[比較見本](http://127.0.0.1:5208/)を開く。下部の案名・左右ボタンで切り替えられる。各案へ直接移動するURLは `?variant=A`、`?variant=B`、`?variant=C`、`?variant=D`。操作した各案の状態は切り替えても保持される。ローカルのvisualize同梱カルーセルを利用し、未導入環境ではブラウザー比較用の簡単な切替操作へフォールバックする。

| 案 | 狙い | 構成 | 比較する点 |
| --- | --- | --- | --- |
| A 同時に見る | 配信の状態とコメントを一画面で確認する | カメラ、状態、コメントを同時表示 | 一画面の情報量と操作の見つけやすさ |
| B カメラに集中 | 撮影と配信マイクの操作を中心にする | 大きなプレビューと撮影操作 | コメントを確認する際の切り替え |
| C コメントに集中 | コメントを読み、読み上げを聞く | コメント中心の本文とコンパクトな送信操作 | 撮影状態の確認のしやすさ |
| D 準備から進める | 登録・接続・開始を順に理解する | 準備の手順と開始後の操作画面 | 初回の分かりやすさと日常操作の速さ |

## 試せる操作

映像・マイクの送信、読み上げ、マイクミュート、映像を隠す、プレビューを閉じる、確認付きのOBS配信開始・終了、スマホ連携、設定・診断の開閉を模擬する。「配信中」「開始前」「通信断」「初回起動」の表示例で比較できる。映像・マイクの送信、OBSの本番配信、読み上げの3つは独立した状態として扱う。

送信停止は確認後だけ模擬状態を変更し、コメント・読み上げとOBS本番配信を終了しない。OBS操作も確認後だけ変更し、確認待ちは10秒で失効する。登録や画面の移動だけでは送信・本番配信・読み上げを開始しない。送信中の経路変更・QR登録は無効にする。QRは読み取れるコードではなく、架空の登録手順を示すプレースホルダー。

## 見本の境界

実際のPC・OBS・カメラ・マイク・読み上げ・Androidサービスへ接続しない。製品の登録、秘密、コメント、設定を読み出し・保存せず、外部ネットワークへの通信、配信操作、公開待受を行わない。表示内容と数値は架空の例。チャット内では見本の操作状態だけを復元する場合がある。プレビュー用ページには外部通信を許可しないCSPを適用し、CDNやアイコンパッケージを追加しない。

正式なネイティブ／WebView分離、ネイティブ音声サービス、通信・認証・資格の保護、SRT送受信の制約は維持する。[Android画面](../../docs/features/android-mobile-client.md#android画面)、[通信仕様](../../docs/features/smartphone-transport.md)、[外配信仕様](../../docs/features/outdoor-streaming.md)、[OBS操作仕様](../../docs/features/obs-control.md)、[直接接続仕様](../../docs/features/smartphone-direct-connection.md)が製品の動作を所有する。静的な比較見本はAndroidのネイティブ画面、WebView、カメラやサービスの再実装ではない。

見本の確認をAndroid実機・OBS・実回線の確認成功として扱わない。既存の作業ツリーの変更を維持し、ブランチ切り替え・コミットを行わない。配布物を生成しない。

## 検証

```powershell
node prototypes/android-ui-throwaway/verify.mjs
pnpm lint:prototypes
pnpm test:prototypes
node node_modules/vite/bin/vite.js build --config prototypes/android-ui-throwaway/vite.config.mts
```

`verify.mjs`はローカルのJSDOMで4案の操作を検証する。状態の独立、確認付き停止、OBS確認期限と案を離れた際の取消、登録時の自動開始禁止、未登録・切断・送信中の保護、QR更新でのOBS・経路保持、音量0%・カメラ停止と復帰・再送信時の表示、ダイアログのフォーカス・背景操作防止・閉じる操作、未登録ヘッダーと通信断時の案内、ネットワークAPIの呼び出しがないこと、DOM ID重複がないことを確認する。画面サイズ・文字拡大・Android実機の検証はこのスクリプトの対象外。

JSDOMの71項目、`pnpm lint:prototypes`（50ソース）、`pnpm test:prototypes`（既存の見本専用テスト7ファイル・69件）、見本のViteビルドを確認済み。JSDOMの検証と既存テストは別の実行で、製品全体の検証結果とも区別する。

Windowsサンドボックス内のElectron描画は初回に`ERR_FAILED`・GPU初期化失敗で実行できず、通常のWindows権限での再確認では描画に成功した。Android実機・OBS実接続・実回線は未確認。

`verify-layout.mjs`では4案を幅320・398・736px指定で描画し、実測幅320・400・736pxで横はみ出しなし、表示中の操作が48px以上、接続・設定・診断シートの横はみ出しなし、レンダラーエラーなしを確認した。ライト表示の全4案とダーク表示のA案を画像でも確認した。実測幅400pxはWindowsの寸法丸めによる。文字拡大とAndroidの実機描画は未確認。

製品の`pnpm lint`（295ソース）・`pnpm typecheck`・`pnpm build`は成功。初回`pnpm test`は113ファイル中7ファイル・1007件中13件が描画起動失敗または時間切れで失敗した。通常のWindows権限で`pnpm test --maxWorkers=2`を再実行し、113ファイル・1007件が成功した。権限と並列数の両方を変更しているため、初回失敗の原因を一つに確定した結果とは扱わない。製品ソースは今回変更していない。
