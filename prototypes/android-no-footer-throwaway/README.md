# Android フッターなしの比較見本（throwaway）

フッターをなくすと、カメラ・コメントの表示領域と操作の探しやすさはどう変わるかを比較する。

- A「操作を上部に集約」：上部の機能別操作メニューから送信・OBS・読み上げ・設定へ進む。本文に操作を重ねない。
- B「操作をサイドに配置」：機能別の操作アイコンを右側に常設する。コメントは操作列の分だけ幅を確保する。
- C「必要時だけ操作を表示」：本文上の小さな「操作」ボタンから一時的な操作パネルを開く。

2026-10-07、A（1案）「操作を上部に集約」を採用。B・Cは未採用の比較資料。現行の正式仕様は[Androidクライアント仕様](../../docs/features/android-mobile-client.md#android画面)、現行配置の採用判断は[ADR 0024](../../docs/adr/0024-adopt-android-camera-comments-ui.md)が所有する。
全状態は架空のローカル状態で、接続・QR・カメラ・OBS・読み上げを実行しない。OSのナビゲーション領域は残し、アプリのフッターだけを削除する。
カメラとコメントの分離、左右フリック、ライト／ダーク、通信断でも位置を動かさない表示、確認付きの送信停止とOBS操作を維持する。

起動（リポジトリルート）：

```powershell
node node_modules/vite/bin/vite.js --config prototypes/android-no-footer-throwaway/vite.config.mts
```

http://127.0.0.1:5211/ 。`?variant=A`、`?variant=B`、`?variant=C`で各案を開ける。
`build`を`vite.js`の直後に追加すると、`tmp/android-no-footer-prototype-build/`へ単独ビルドする。
先行する上部切替の比較資料は5210に保持する。

`verify-layout.mjs`は隔離したElectronで、320／400／736px、両画面、両配色、通常／2倍文字の72条件を描画確認する。フッターの不在、48px以上の操作対象、通信断・読み上げ状態の変更で本文を動かさない表示、メニュー・設定・QR入口、停止・OBSの確認、フリックを対象とする。図は架空の縦向きプレビューを想定した比較用のもの。
仕様との一致と影響範囲は自己レビューで確認した。実サービス・実カメラ・Android本体の実行確認を示す見本ではない。
