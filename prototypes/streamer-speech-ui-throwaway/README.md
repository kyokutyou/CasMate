# 配信者音声認識 UI 比較見本

2026-09-16。破棄可能なUI検討用コード。本体の実装・正式仕様ではない。
問い：マイクの準備、認識の調整、プレビュー、本番利用を、どの配置で最も理解しやすく扱えるか。
既存のホーム／設定の枠を維持し、編集領域を3通りで再構築した。

```powershell
node node_modules/vite/bin/vite.js --config prototypes/streamer-speech-ui-throwaway/vite.config.mts
```

http://127.0.0.1:5198/ を開く。`?variant=A`、`?variant=B`、`?variant=C` で直接指定できる。
ソースの `fragment.html` は会話内とローカルプレビューで共用する。

| 案 | 設計 | 向いている使い方 | トレードオフ |
| --- | --- | --- | --- |
| A | 一画面のマイク準備＋プレビュー。認識の調整は必要時に展開 | 日常の設定確認。推奨案 | 全数値の比較には展開が必要 |
| B | マイクを準備→話して確認→本番で使う、の3手順 | 初めての準備 | 複数箇所の往復が増える |
| C | 左に全調整値、右にプレビュー。狭い幅では縦配置 | 発話の区切りや語頭・語尾を調整 | 情報量が多く、小窓では縦に長い |

6項目の数値設定には目的を表すラベルと正式な項目名を併記。編集中と適用済みを分離し、案や画面を切り替えても入力を保持する。WAV保存と履歴、モデル準備、要確認、ヘッダー通知も比較できる。最初は認識・本番利用ともに停止し、プレビュー開始後に見本上部の「発話を再現」で架空の確定結果を追加する。

音声の取得、モデル取得、OBS操作、WAV保存、設定の永続化、外部通信は行わない。処理時間・マイク・URLは架空データ。モデル準備・適用・再試行は模擬操作。状態JSONと比較操作は製品外の検討用UI。
