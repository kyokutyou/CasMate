# スマホでコメントを聞く：設定UIの比較見本

2026-09-17。情報構造と操作の流れを3通りで比較し、利用者の指定によりC案を採用した。本体の機能名は「スマホでコメントを聞く」へ変更。見本には比較時点の旧名称を残している。

## 起動

プロジェクトルートから、インストール済みViteで起動する。

```powershell
node node_modules/vite/bin/vite.js --config prototypes/mobile-speech-ui-throwaway/vite.config.mts
```

下部のA/B/Cボタン、前後ボタン、入力中以外の左右キーで切り替える。開発用スイッチャーは本番ビルドには表示しない。

| 案 | 情報構造 | 適した使い方 | トレードオフ |
| --- | --- | --- | --- |
| A 接続方法を並べる | LAN・Tailscaleのカードを並べ、共通の音質・端末状態を下へ配置 | 両経路を見渡し、日常の切替と確認を素早く行う | QRを開くと縦に長くなる |
| B 目的に集中する | 公開設定・スマホ接続・音質と状態をタブへ分割 | 小さい画面で一つの目的に集中する | 全体の確認にはタブ移動が必要 |
| C 手順に沿って進める | 公開する・スマホで開く・音声を聞くの3段階を開閉 | 初めて使うときに順序を理解する | 日常の音質変更や状態確認に展開操作が必要 |

## 比較できる操作

LAN・Tailscaleの独立切替、接続案内とQRの明示展開、複数LAN URL、音質入力、ページ・タブ・案をまたぐ入力保持、警告ダイアログと通知を比較できる。C案では手順移動後に移動先の見出しへフォーカスする。

比較用の状態選択でLANのIPv4なし、Tailscale未導入・サービス停止・ログイン待ち・IPv4取得失敗・待受失敗、音声変換エラー、音声再生中を確認できる。「見本の内部状態」で現在のメモリ上の設定と表示状態を確認する。

## 見本の境界

本体と同じ管理画面の枠を使い、既存の試作と同じ独立ディレクトリへ隔離した。本体の入口・API・ネットワーク公開・設定ファイルへ接続しない。既存の未コミット作業があるため、ブランチ切替とコミットは行っていない。

公開設定は両方オフから開始し、設定・状態はメモリだけに保持する。リロードで初期化する。公開・コピー・保存は模擬であり、実際の音声再生や接続確認をしない。QRは表示した架空URLと一致する検討用データで、実際のPCの接続先ではない。公式案内リンクだけは実際の外部ページへ遷移する。

正式な保存・非同期処理・復旧の実装へそのまま昇格させるコードではない。採用後の本体は、既存の実データ・自動保存へ接続する独立したMobileSpeechPanelとして実装した。
