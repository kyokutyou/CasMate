# OBS用URL：2案のUI比較見本

2026-09-18、利用者がA案「一覧からコピー」を採用した。同時に管理画面仕様のヘッダー高さを45pxへ修正した。本ディレクトリは比較時の見本を保持する。A案は本体へ反映済み。正式仕様は[OBS用URLの管理画面](../../docs/features/local-application.md#obs用urlの管理画面)、実装検証は[検証記録](../../docs/validation/obs-urls-ui-2026-09-18.md)を参照する。以下の72pxの記述・検証結果は採用前の見本に関する記録である。


- [B：選んで追加](http://127.0.0.1:5205/?variant=B)

下部のA/Bボタンで比較。入力欄・ボタン等の操作中を除き、左右キーでも切り替えられる。

## 比較する判断

| 案 | 構成 | 向いている使い方 | トレードオフ |
| --- | --- | --- | --- |
| A 一覧からコピー | 4種類の用途・URL・コピーを一列の一覧に集約。追加手順は任意に展開 | 欲しいURLをすぐ見つける、複数の表示を連続で登録する | 全URLが見えるため情報量が多い |
| B 選んで追加 | 表示を選び、そのURLと「コピー→OBSに貼り付け」を一つの領域で案内 | 初めてOBSへ追加する、一つずつ用途を確認する | 別のURLを確認するには選択の切替が必要 |

## 両案の共通点

- [共通レイアウト](../../docs/features/management-screen.md#設定編集画面の共通レイアウト)を読み、実際の `ManagementEditorHeading` を再利用。枠付きの矢印、画面名、菱形付きの緑の説明枠を配置する。見出し下に副題や現在値の要約を重複させない。
- 製品の管理画面CSSを共有し、ヘッダーは共通トーストの仕様に合わせ72pxとする。通知はヘッダー内の重ね表示、4秒で消え、同じ通知の再実行でも寿命を更新する。
- OBS向け4種類を先頭に配置し、ブラウザ向けの管理画面・コメント一覧、ポート・バージョン・更新手順は下部の開閉領域にまとめる。
- URLのパス、ポート範囲、再起動後の反映は[ローカルアプリケーション仕様](../../docs/features/local-application.md#web画面の正式url)を参照する。保存したポートと起動中のポートを分け、再起動するまでコピー対象のURLを変えない。
- 表示例は明示操作でだけ開く、架空内容の静止見本という提案。採用時に仕様を確定する。実OBSの見た目、キャラクター素材、配信中のコメントは取得しない。
- コピー失敗・保存失敗は既存の `ManagementWarnings` に集約。ポートの条件説明と再保存の領域は高さを確保する。

## 操作と制約

URLのコピーはクリップボードAPIを呼ぶ。設定はメモリ内だけで、再読み込みで初期化する。既存の管理画面を開く操作は行き先を説明するモーダルで代替する。OBSへの接続・追加・配信操作、設定API、外部通信、保存ファイルへの書込みは行わない。

「検証」から幅、失敗、長い通知、再起動後を試せる。「操作状態」は見本専用の状態JSONで、製品画面への提案ではない。入力値は案・ページをまたいで保持する。

既存の未コミット変更を保護するため、今回の見本は独立ディレクトリに置き、ブランチ切替・コミットを行っていない。製品のエントリーポイントからは参照しない。
