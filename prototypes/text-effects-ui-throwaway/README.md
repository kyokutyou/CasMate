## 比較する問い

「ルールを見渡しながら手早く調整」「対象を選んで集中して編集」「入力順に案内されながら作成」のどの構成が使いやすいか。

| 案 | 情報と操作の構成 | 向いている使い方 | トレードオフ |
| --- | --- | --- | --- |
| [A：一覧で調整](http://127.0.0.1:5198/?variant=A)（推奨） | 一致条件と表示結果を一行に集約。一覧内で一件だけ編集を展開。共通設定は下部の開閉領域 | 少数〜中程度のルールを見渡して調整・テスト | 編集を開くと一覧が縦に長くなる |
| [B：選んで編集](http://127.0.0.1:5198/?variant=B) | 左のルール一覧と右の編集欄を分離。共通設定は別タブ | 多数のルールを一件ずつ整える | 狭い画面では上下配置となり、一覧と編集欄の移動が増える |
| [C：順番に作成](http://127.0.0.1:5198/?variant=C) | 反応ワード→表示文字と色→個数の3手順。既存ルールは選択欄で切替 | 初回設定・新規ルールの作成 | 日常の微調整では手順間の移動が必要 |

色や装飾だけを変えず、情報の優先順位・編集位置・移動手順を変えている。推奨は設計上の判断であり、利用者評価で優位性を検証した結果ではない。

## 共通レイアウトとの対応

[管理画面仕様の「設定編集画面の共通レイアウト」](../../docs/features/management-screen.md#設定編集画面の共通レイアウト)を確認し、本体の `ManagementEditorHeading` と既存CSSを直接使用する。枠付き戻る矢印、画面名、菱形付き緑の説明枠、共通余白を3案で揃える。

スイッチと警告一覧も本体の `SlimSwitch` / `ManagementWarnings` を使用。成功は既存の共通ヘッダートーストのスタイル・配置で4秒表示し、本文へ挿入しない。入力エラーの説明領域と保存状態欄は事前に高さを確保する。常設のアニメーションプレビューは置かず、明示的な「テスト再生」で見本内のダイアログを開く。

## 試せること

- 全体・個別のオン／オフ、ルール追加、編集、上下の並び替え、確認付き削除。
- 固定個数と連動型、文字と絵文字、色の入力、不正値を保持する入力エラー。
- 共通の文字サイズ・落下時間・同時表示上限。
- 入力500ms後、選択・スイッチ操作時のメモリ内への模擬保存。新規は「追加」で反映。
- 保存済みの値によるテスト再生。全体やルールがオフでも操作可能。
- 案切替・ホーム／設定との往復で、編集値と追加途中の値を保持。
- 下部「比較用の操作」で3件・未登録・50件・保存失敗を再現。状態プリセットの選択は見本データを初期化する。「保存失敗を再現」チェックだけの解除は編集値を維持する。
- 状態JSONで入力値・模擬保存値・選択・エラーを確認。比較バーと検証操作は開発時だけ表示。

## 正式仕様との関係・制約

正式な機能契約は [コメント文字演出仕様](../../docs/features/text-effects.md)、共通保存契約は [ローカルアプリケーション仕様](../../docs/features/local-application.md#設定保存)、用語は [CONTEXT.md](../../CONTEXT.md)、管理画面の方針は [ADR 0014](../../docs/adr/0014-adopt-home-and-settings-management-ui.md) が所有する。

Aの一覧中心の構成と共通設定の開閉を採用。正式な挙動は所有する機能仕様に記載し、このREADMEでは上書きしない。B・Cと見本内の再生ダイアログは未採用。

実設定・API・OBS・コメント取得とは接続しない。サンプル3件のうち拍手と祝いは比較用データ。再生は縮小した領域の簡略アニメーションで、実際のOBS描画品質・位置・乱数・通信を検証するものではない。色付き絵文字の色は利用フォントに依存する。

保存処理は比較専用で、複数画面同期や非同期競合、設定移行を実装していない。既存ルール全体を一つの入力ドラフトとして模擬反映するため、本体の保存処理へ流用しない。

見本は独立したthrowawayディレクトリに置き、本体のエントリーポイントから参照しない。本体への反映は別途、正式仕様と製品コードに実施した。
